# runtime — рантайм визуальной новеллы «Криминальная Россия»

Собственный TypeScript-рантайм по ADR-001 (`docs/architecture/06-engine-and-pipeline.md`): исполняет эпизод
из `episodes/**.json` напрямую (сценарий — данные, `schemas/episode.schema.json`), сцена рисуется PixiJS,
текст и интерфейс — DOM/CSS, платформа — Playgama Bridge или обычный браузер. Это **играбельная версия для
телефона**: весь эпизод 1 проходится от меню до концовок; картинки и звук берутся из `../assets` (нет файла —
плейсхолдер и одно предупреждение в консоли), поверх чистой картинки рантайм даёт «камкордер» — дрожание ручной
камеры, редкие слабые помехи, зерно и HUD записи (стиль домашней видеокамеры 1995–2000, решение владельца);
интерфейс — документальный, mobile-first. Настоящих картинок и звука в репозитории пока нет — см. «Не сделано».

Всё в этой папке; за её пределами рантайм только **читает**: `../episodes`, `../locales`, `../assets`,
`../tools/vnexpr_test.py` (сверка грамматики условий) и `../docs`.

## Быстрый старт

Нужны Node.js ≥ 22.12 и доступ к npm registry (больше никуда рантайм в сеть не ходит).

```bash
cd runtime
npm install

npm run dev            # http://localhost:5173 — dev-сервер; эпизод и локали берутся прямо из ../episodes и ../locales,
                       #   при правке JSON страница перезагружается. В dev включена отладочная панель.
npm run typecheck      # tsc --noEmit, strict
npm test               # vitest (node + jsdom)
npm run build          # dist/ — готовый архив для обычного хостинга (+ ../assets → dist/assets); в конце проверка scripts/check_dist.mjs
npm run preview        # http://localhost:4173 — раздать dist/
VN_ASSETS_DIR=/путь/к/assets npm run build   # собрать с другим каталогом картинок и звука (проверка «с файлами»)

npm run build:playgama # dist-playgama/ — то же + локальная копия Bridge SDK и playgama-bridge-config.json
npm run preview:playgama   # http://localhost:4174

npm run smoke          # Playwright-смоук собранной игры в настоящем Chromium: игра, камкордер и ассеты, Bridge (см. ниже)
npm run smoke:matrix   # + раскладка 5 размеров × языки, скриншоты в e2e/out/
```

Проверка «с нуля», как в CI: `npm install && npm run typecheck && npm test && npm run build`.

### Параметры адреса (для разработки и QA)

| Параметр | Что делает |
|---|---|
| `?lang=ru\|en\|es\|pt` | язык интерфейса (иначе: выбор игрока → язык платформы → `en`) |
| `?debug=1` | отладочная панель (сцена, шаг, переменные, ожидание) и подробный лог Bridge SDK |
| `?autostart=1` | сразу новая партия новеллы, без меню и контент-предупреждения |
| `?vn=1` | вместе с `?episode=ep01_murylev`: прежняя новелла вместо режима дела — клик по эпизоду в меню открывает партию, а не папку дела (`docs/architecture/09-case-mode.md`) |
| `?scene=s15_q&vars=found_photo:true,nerves:3&items=arc_keys` | проверка геймплея: новая партия минуя меню, переменные как в эффектах сценария (true/false, целое, строка), `items` — материалы архива в партию (улики дедуктивных развилок, без тоста; то же — `__vn.unlock(item)`), переход сразу к сцене. Дедуктивные развилки эпизода 1: `s15_q` (Галина), `s16b_q` (Ковригин, `found_photo:true` для скрытой опции), `s20b_q` (Лапин), `s29b_q` (Ковригин с папкой: `vars=found_chain:true,docs_flaw:true&items=arc_bti,arc_power_of_attorney,arc_registration`), `s41b_q` (очная ставка: `vars=keys_found:true,docs_flaw:true&items=arc_keys,arc_power_of_attorney,arc_registration`) |
| `?renderer=dom\|pixi` | принудительно DOM-рендерер или PixiJS (по умолчанию PixiJS, при отказе WebGL — DOM) |
| `?pseudo=1` | псевдолокализация: +35 % длины, диакритика (проверка вёрстки), см. `src/core/pseudo.ts` |
| `?episode=<id>` | эпизод из манифеста (по умолчанию первый — проба «Хода следствия» `ep01_hod`; прежний эпизод 1 — `ep01_murylev`) |

### Управление

| Действие | Мышь / тач | Клавиатура |
|---|---|---|
| Дальше (первое нажатие допечатывает текст) | клик / тап по сцене или тексту | Space, Enter, →, PageDown |
| Откат на реплику назад (до 30) | колесо вверх | ←, PageUp; кнопка ↶ в журнале откатывает на любую из последних 30 |
| Вариант выбора | клик / тап | 1…9 |
| Auto / Skip прочитанного / Log / Hide UI | кнопки быстрого меню | A / S / L / H |
| Save / Load / Mute | панель быстрых кнопок на экране настроек | M (Mute) |
| Временный Skip | — | удерживать Ctrl |
| Закрыть экран / открыть настройки | — | Esc |

Быстрое меню — иконки (подпись остаётся скрытым текстом и подсказкой `title`, так кнопку читает скринридер):
Auto, Skip прочитанного, Log (папка), Settings, Hide UI; кнопки ≥ 48 px. Сохранить / Загрузить / Звук — панель быстрых
кнопок вверху экрана настроек (сохранение и загрузка — только в игре). «Пропуск» на непрочитанной реплике не включается
и объясняет подсказкой; в настройках — переключатель «Пропускать непрочитанное». В авто-режиме показана красная полоса
времени до перехода (портрет — под картинкой, ландшафт — над окном текста): пауза = «пауза авто-режима» + 20 мс × символы
реплики, с озвучкой — до конца клипа + 300 мс. Настройки: язык, **эффекты камеры**
(«Выкл» / «Слабо» — по умолчанию / «Сильно»; при включённом в системе `prefers-reduced-motion` эффекты выключены
принудительно, переключатель недоступен), размер шрифта, скорость текста, пауза авто-режима, громкости, **озвучка**
(переключатель и громкость), таймеры выборов вкл/выкл, режим «только история», режим показа насилия (`full` / `schematic`; выбирается и на экране
контент-предупреждения).

### Отладочный API `window.__vn`

Установлен и в продакшен-сборке (смоук гоняет именно её):

```js
__vn.goto('s35')                 // перейти к сцене (без рекламы и проверки условий блока)
__vn.set('trust_oper', 2)        // записать переменную (тип и границы — как у эффектов сценария)
__vn.state()                     // копия { episode_id, scene_id, step_index, vars, globals, archive, journal }
__vn.autoplay('default')         // пройти эпизод автоматически → { ending, scenes, choices, … }
__vn.autoplay({ choice: 'last', minigame: 'fail' })   // политики: first | last | random | default, явные choices/minigames, seed
// помощники: start() · pending() · view() · lang('es') · skip(true) · settings({ timers: false }) · renderer()

__vn.settings({ cameraFx: 'off' })      // 'off' | 'low' | 'high' — эффекты камеры на лету
__vn.camera()                    // { setting, effective, reducedMotion, degraded, running, rec, transform, bursts }
__vn.camera('burst')             // вызвать сейчас: 'burst' (помеха) | 'glitch' (разрыв кадра) | 'reframe' | 'angle' («неожиданный ракурс»)
__vn.assets()                    // { loaded, missing, pending, inflight } — что загружено, чего нет, что в очереди
await __vn.assets(true)          // + { verify: { present, missing } } — HEAD-проверка всех файлов из episode.assets (QA)
__vn.audio()                     // { music, ambient, audible, log, voice } — что играет и последние события звука;
                                 //   voice: { enabled, volume, playing, clips } — озвучка реплик (раздел «Озвучка»)
__vn.slots()                     // { bg, cg, sprites: { <who>: … } } — что нарисовано: image | placeholder | solid | loading | none
```

## Как это устроено

- **Интерпретатор — pull и детерминированный.** `pump()` исполняет шаги до первого ожидания игрока и возвращает
  `{ events, pending }`: события (`scene`, `caption`, `show`, `bg`, `cg`, `audio`, `archive`, `checkpoint` …) и одно
  ожидание (`line`, `hold`, `document`, `choice`, `minigame`, `ad_break`, `end`). Ответ — `continue()`,
  `choose(id)` или `finishMinigame(result)`. Состояние — `{ episode_id, scene_id, step_index, vars, globals, archive[], journal[] }`;
  кадр сцены (`ViewState`: фон, фильтр, спрайты, CG, музыка) хранится рядом, поэтому загрузка и откат
  восстанавливают картинку без повторного проигрывания сцены.
- **`when` — на любом шаге** (ложное условие пропускает шаг целиком); `offscreen_left/right` в `say.position` —
  голос за кадром: имя и реплика показываются, спрайт не рисуется ни одним рендерером.
- **Реклама.** Interstitial запрашивает только интерпретатор — при входе в блок с `ad_break_allowed`. Сцена в этот момент
  уходит в чёрное и **держит чёрный кадр** до `continue()` после рекламы; новая сцена проявляется только после неё
  и после загрузки картинок блока (они грузятся, пока экран гаснет и идёт ролик)
  (правило — в комментарии `src/stage/director.ts`, тесты — `tests/director.test.ts`, `tests/director_loader.test.ts`, `tests/session.test.ts`).
- **Сейвы.** Файл сейва = состояние + кадр + `schema_version` + `content_version` (`id@хеш` JSON эпизода) + состояние
  мини-игры. На Playgama — один вызов `bridge.storage.set(['profile','progress','settings','archive'], …)`; нумерованные
  слоты (`slot_N`) — только в web-plain, на Playgama «ручной» слот один (`progress.quick`). Автосейв: вход в блок,
  после выбора, после мини-игры, при уходе со страницы. При загрузке сейв приводится к текущему описанию эпизода
  (новые переменные, исчезнувшие сцены).
- **Мини-игры** подключаются через реестр (`registerMinigame(type, factory)`); тип без реализации получает grey-box.
  Результат → `outcomes` → `goto` + эффекты + `archive_unlock`; `skipped` → `skip.skip_counts_as`.
- **Раскладка (mobile-first).** Портрет — картинка сверху, текст и варианты выбора под ней, HUD записи внутри картинки; ландшафт —
  окно текста поверх картинки, быстрое меню — иконки в углу. Окно реплики — по макету в Figma (2026-10-13): над подложкой
  `rgb(0 0 0 / 0.24)` круглый портрет (`cast.portrait`, `AssetCatalog.portraitUrl`, грузится с блоком), полное имя и подпись
  (`cast.title_key`), в конце текста — красный «>»; размеры макета (кегль 15 px) пересчитаны в em. Шрифт — Tinos; моноширинные
  DM Mono и JetBrains Mono (по `html[lang]`) — только у индикации камеры и отладочного HUD (`--font-osd`); на тач-устройствах
  (`pointer: coarse`) у интерфейса нет обводок и теней — текст и кнопки на подложке 8 % белого; варианты выбора и кнопки ≥ 48 px; безопасные поля `env(safe-area-inset-*)`; страница не скроллится, контекстное меню по
  долгому тапу отключено. Главное меню — кинескоп телевизора (CSS, без картинки фона): в шапке логотип передачи
  `assets/common/ui/logo_kr.webp` и сезон, ниже полка эпизодов по `episodes/s<N>/season.json` (`loadSeason`; нет файла — только
  текущий эпизод); язык, архив и настройки — иконками в правом верхнем углу. Игра открывается сразу меню; при его показе стартует главная
  тема `m_theme_main` (луп, оригинальная запись темы передачи), она гаснет при старте партии. Если браузер запрещает автозапуск звука
  без жеста, бэкенд помечает трек заблокированным и включает его при первом касании, клике или клавише на странице.
- **Платформа** выбирается по наличию `window.bridge`; поверх одной абстракции — язык, сейвы, реклама, пауза/звук, телеметрия
  (`level_started/completed`, `minigame_*`, `ending_reached`, … через `sendMessage` / `analytics.send`).

## Ассеты: графика и звук

Картинки и звук лежат в `../assets/` (эпизод 1 — 78 файлов, 17,5 МБ: их скачивает по `assets/<ep>/manifest.json`
workflow `fetch-assets` на раннере GitHub и коммитит в ветку; без файлов игра идёт на плейсхолдерах). Пути берёт
`episode.assets.*[].path` (`assets/ep01/bg/yard_summer.webp`), перекодирования рантайм не делает: в dev и в сборке файл
отдаётся как есть.

| Что | Откуда | Формат |
|---|---|---|
| фоны, CG, бланки документов | `assets.backgrounds`, `cg`, `documents` | webp (допустимы png, jpg) |
| спрайты | `assets.sprites[].base` — базовый кадр набора (в ep01 — `…/neutral.webp`); рядом `<выражение>.webp`, `silhouette.webp` | webp (png допустим) |
| музыка | `assets.music` | m4a (AAC) |
| эмбиент, эффекты | `assets.ambient`, `assets.sfx` | mp3 |
| озвучка реплик | `assets/<ep>/voice/<lang>/<ключ реплики>.mp3` — вне `episode.assets`, находится по индексу `voice-index.json` (раздел «Озвучка») | mp3 (допустимы m4a, ogg) |
| главное меню и заставка | `assets/common/ui/logo_kr.webp` — логотип передачи без фона (заставка и шапка меню); `assets/common/ui/menu_video_salon.webp`, `assets/common/ui/title_plate.webp` — красная полоса по центру кадра (66 % × 44 % картинки), название эпизода и титры глав ложатся в неё (вне `episode.assets`) | webp |

- **Плагин сборки** `scripts/assets_plugin.mjs`: dev-сервер отдаёт `/assets/**` из `../assets` (HTTP Range и HEAD — Safari
  не играет аудио без Range; нет файла → настоящий 404, а не index.html), `npm run build` копирует файлы в `dist/assets/**`.
  Берутся `.webp .png .jpg .jpeg .mp3 .m4a .ogg`; файлы и папки на `_` и `.`, `manifest.json` и `*.md` в сборку не попадают.
  Другой каталог: `VN_ASSETS_DIR=/путь/к/assets npm run build` (проверка «с файлами» без правки репозитория).
- **Цепочка спрайта** — рендерер берёт первый существующий файл: `silhouette.webp` (если спрайт — силуэт) → `<выражение>.webp` →
  `neutral.webp` → `base`. Нет силуэта — рендерер делает его из найденного кадра (`brightness(0)`, непрозрачность 85 %);
  собеседники вне речи затемняются тинтом. Нет ни одного файла — плейсхолдер и **одно** предупреждение на цепочку:
  `[assets] нет файла спрайта (… → …): плейсхолдер`. Так же — для фона, CG и бланка: один `console.warn` на файл.
- **Чёрный кадр**: `bg_black` (`assets/common/bg/black.png`) — сплошной цвет; файла нет и быть не должно, его не запрашивают,
  не проверяют и не предупреждают.
- **Предзагрузка по блокам** (`stage/preload.ts`): при входе в блок грузятся все картинки его сцен (до 4 одновременно), сцена не
  показывается, пока они не готовы (вход в блок ждёт не дольше 15 с; кадр сцены, фона, CG и спрайтов — не дольше 6 с);
  пока ждём — чёрный кадр, а не вспышка плейсхолдера. Звук блока прогревается в
  фоне, следующие блоки подтягиваются с низким приоритетом. Через 300 мс ожидания включается индикатор загрузки (три точки), а
  платформе уходят `in_game_loading_started` и `in_game_loading_stopped` — только если загрузка действительно блокировала показ.
  На границе блока с рекламой картинки грузятся, пока экран гаснет и идёт ролик.
- **Память**: хранилище держит картинки текущего блока, следующего и закреплённые (меню, заставка); Pixi-текстуры — кэш с
  бюджетом 120 МБ и mipmaps; отрисовка Pixi — по требованию (в покое 0 вызовов отрисовки, постоянная — только в мини-играх).
- **Размер сборки**: `scripts/check_dist.mjs` считает игровые ассеты (`assets/<папка>/…`) отдельной строкой; больше 40 МБ —
  предупреждение (на мобильном долго грузить), общий лимит архива 300 МБ — ошибка. Бандл Vite (`assets/index-*.js`) — ядро.
- **QA**: `__vn.assets()` — что загружено, чего нет, что в очереди; `await __vn.assets(true)` — ещё и HEAD-проверка всех
  файлов из `episode.assets` (`{ present, missing }`; ответ-HTML SPA-фолбэка считается «файла нет»).

## Кадры покрытия (монтажёр)

Сцена с `coverage: "<set>"` показывается не фоном со спрайтами, а готовыми кадрами сета из `assets.shots`
(`docs/architecture/08-shot-grammar.md`): общий план при входе, `ots`/`medium` в спокойном разговоре, крупный план
на напряжённой реплике, реакция слушающего на длинной реплике, редкая перебивка `angle` в кульминации, `wide`/`insert`
под рассказчика. Выбор делает `src/core/editor.ts` — чистые детерминированные функции (жребий перебивки — хеш
`scene_id:step_index`), память сцены лежит в `ViewState.shot_ctx`, поэтому загрузка сейва и откат показывают тот
же кадр. Сценарист может задать `beat` (`calm`/`tense`/`climax`) и явный `shot` у `say`/`narrate`/`show`.

- Переход `dissolve` между сценами на PixiJS — растворение: снимок прошлого кадра без фильтров камеры (`generateTexture`)
  кладётся поверх нового и гаснет за `DISSOLVE_MS` (750 мс, smoothstep). DOM-рендерер — прежний провал в чёрное.
- Событие `shot` идёт перед `speaker`; внутри сета склейка `cut`, кадр ждём не дольше `SHOT_WAIT_MS` (2 с), дальше
  рендерер подменит его, когда загрузится (до этого виден прежний кадр).
- Слой кадра лежит между спрайтами и CG: Pixi выключает слой спрайтов, пока кадр показан; DOM прячет
  `.ph-sprites` классом `has-shot`. Файла нет → плейсхолдер не рисуется, остаются спрайты (`__vn.slots().shot ===
  'placeholder'`). Спрайты продолжают обновляться по `show`/`hide` — для отката и запасного варианта.
- Нет подходящего кадра (в сете нет людей, которые стоят на сцене; говорящий не на сцене) → `shot: null`, сцена
  идёт спрайтами. `hide` того, кто в кадре, → общий план оставшихся; `bg` на другую локацию снимает покрытие.
- Предзагрузка: общие планы сетов блока — вместе с фоном (блокирующе), остальные кадры — в фоне до картинок
  следующего блока (`BlockAssets.idle`).
- Длину реплики для правила реакции даёт `Session` (`t(key).length`), поэтому на другом языке монтаж может чуть
  отличаться — это ожидаемо.

## Камкордер

Решение владельца (2026-10-10): картинки в игре чистые и фотореалистичные, ощущение документальной съёмки домашней
видеокамерой 1995–2000 создаёт **рантайм**. Текст и интерфейс эффектов не получают: всё происходит внутри слоя кадра.
Код — `src/stage/camcorder.ts` (чистое ядро без DOM: ГСЧ и время приходят аргументами, поведение детерминировано и
проверяется тестами), `src/stage/camcorder_layer.ts` (DOM-часть) и `src/stage/vhs_filter.ts` (шейдер записи).

**Два пути (2026-10-13).** Основной — видеокарта: рендерер PixiJS принимает кадр камкордера (`camera()`), и один проход
шейдера по всему кадру делает и движение камеры (обратное преобразование при выборке), и искажения аналоговой записи по
мотивам [ntsc-rs](https://ntsc.rs) — прямо на картинке, поверх уже сдвинутого кадра, как у настоящей камеры. CSS-трансформации и
холста помех на этом пути нет (на сцене класс `cam-gpu`): растянутый холст 256 px мылил шум в «размазанные пиксели», а
CSS-пересчёт холста давал муар. Запасной путь — DOM-рендерер или шейдер не собрался на устройстве (проверка компиляцией в
том же GL-контексте до включения): прежние CSS-трансформация `hand` и холст помех.

Слои кадра изнутри наружу: `host` (canvas Pixi или DOM) → `cam` (Ken Burns, моторный зум) → `grade` (цветокоррекция
`stage.filter`, неподвижный слой) → `hand` (дрожание: единственный элемент с `transform`) → `scene`; поверх — виньетка,
интерлейс, холст помех, HUD, титры, текст и интерфейс.

| Эффект | Как работает | Числа (уровень «Слабо») |
|---|---|---|
| Ручная камера | сумма синусов с весами ~ 1/f × огибающая «беспокойства»: в покое остаётся 15 % амплитуды, эпизоды полной амплитуды приходят раз в 14–32 с и длятся 1,2–2,6 с с плавным входом и выходом по 1,2 с; «кроп стабилизатора» — масштаб ровно такой, чтобы края картинки не показывались | сдвиг ≤ 1,2 %, поворот ≤ 0,5°, масштаб 1,00–1,03; на «Сильно» покой 35 %, эпизоды раз в 6–14 с по 2–4 с |
| Сила по режиму показа | `presets.ts` (`handheld`) | reconstruction 1, procedural и montage 0,5, talking_head 0,25, остальные — штатив (0) |
| «Оператор поправил кадр» | при входе в сцену (не при загрузке, откате и Skip); режимы с `reframe` | сдвиг/наклон 2–4 % за 300–500 мс; в ~25 % случаев «неожиданный ракурс» ≤ 2°, оседает 2–3 с |
| Помехи | всплеск: полоса трекинга, мерцание яркости, хроматический сдвиг | раз в 20–45 с, 150–500 мс; в `vhs_heavy` — раз в 6–12 с, чуть сильнее, слабый интерлейс |
| Запись (шейдер, `SignalProfile`) | кадр делится на виртуальные строки (480, но не тоньше 2 пикселей — на телефоне меньше): у строки свои сдвиг, шум и фаза цвета, а картинка читается с полным вертикальным разрешением (без ступенек на диагоналях); сдвиги строки: дрожание развёртки (чётные и нечётные врозь — зубцы на вертикалях), волна строк, полоса переключения головок внизу кадра, полоса трекинга при всплеске; яркость — лёгкое размытие вдоль строки и «звон» у резких границ; цвет (I/Q) — шире, с задержкой вправо, пополам с соседней строкой, шум фазы по строкам, потеря насыщенности; лента — шум яркости полосками, шум цвета, «снег» (белые штрихи с хвостом, гуще у нижнего края), редкие длинные выпадения; разрыв кадра `vhs_glitch` — шов и шум на открывшемся крае | «Слабо»: размытие яркости 0,6 вирт. пикс., звон 0,35, растекание цвета 2,5, задержка 1,2, шум яркости 0,03, снег 0,0015, выпадения 0,0015, зубцы 0,35, головки 2 % ширины, насыщенность 0,92, строк чересстрочности нет. «Сильно» — вдвое и больше по всем искажениям, рябь цвета в яркости, строки чересстрочности. `vhs_heavy`: шум, снег, выпадения, зубцы × 1,3 |
| Зерно (запасной путь) | один canvas ≈ 256 × 144, растянут на кадр, из 6 заготовленных кадров | 12–15 к/с (на 30 Гц обновления кадра — 15), непрозрачность ≤ 5 % (4,5 %) |
| Виньетка | мягкая, под титрами | 0,28 |
| Моторный зум (`fx zoom_in`) | с перелётом, «поиск фокуса» | 1,00 → 1,12, размытие 0 → 1 px → 0 |
| `freeze_frame` | движение и помехи замирают, кадр слегка темнеет | |
| `vhs_glitch` | разрыв кадра: рывки и шумовая полоса на холсте (при выключенных эффектах — прежний CSS-вариант) | |
| Остальные фильтры | только сдержанная цветокоррекция на неподвижном слое `grade` | десатурация ≤ 35 % (`tests/css_contract.test.ts`) |
| HUD записи | красная точка и `REC`, мигание 1 Гц, PT Mono, внутри картинки (под вырезом, не ближе 3,2 % к краю), скрывается вместе с интерфейсом | только reconstruction |
| `date_stamp` | мелкий PT Mono в правом верхнем углу картинки | |

- **Уровни**: «Выкл», «Слабо» (по умолчанию), «Сильно» (амплитуда ×1,6, масштаб ≤ 1,05, помехи вдвое чаще и сильнее —
  числа владельца относятся к «Слабо»). `prefers-reduced-motion` выключает эффекты принудительно (даже при «Сильно»; выбор
  игрока сохраняется и вернётся, когда настройку ОС снимут). При «Выкл» цикл не запускается вовсе.
- **Цикл**: `requestAnimationFrame`; стоит при скрытой вкладке, паузе платформы, открытой мини-игре и уровне «Выкл». Кадр
  дрожания обновляется не чаще 30 раз в секунду (камкордер снимает 25–30 к/с; вдвое реже — вдвое меньше композитинга на слабых
  телефонах), внутренние часы планировщика не бегут быстрее 100 мс за кадр — после паузы движение продолжается плавно.
- **Самозащита от слабого устройства**: если браузер стабильно не успевает ≈ 20 к/с (средний интервал между кадрами > 50 мс на
  окне 4 с после 2,5 с прогрева; разовые подвисания не считаются), эффекты выключаются до конца сессии. В консоли одна строка
  `[camcorder] N к/с: эффекты камеры выключены до конца сессии`, в настройках отмечено «Выкл», `__vn.camera().degraded === true`;
  выбор игрока в сейве не меняется, а явное нажатие на уровень в настройках возвращает эффекты. Под автоматизацией
  (`navigator.webdriver`: Playwright, Selenium) защита отключена — смоук видит эффекты.
- **Включить и выключить**: настройки → «Эффекты камеры»; из консоли `__vn.settings({ cameraFx: 'off' | 'low' | 'high' })`;
  QA: `__vn.camera('burst')`, `__vn.camera('reframe')` и т. д. вызывают эффект сейчас.

## Звук

`src/stage/audio_html.ts` — настоящий бэкенд на `HTMLAudioElement` (надёжно играет в iOS Safari); `src/stage/audio.ts` — состояние
менеджера (что играет, mute игрока, запрет платформы, громкости, журнал для отладки).

- **Музыка**: один трек, луп; смена трека — кроссфейд длительностью `fade_ms` шага (старый гаснет, новый нарастает на втором
  элементе); тот же трек повторно не запускается (откат и загрузка вызывают `sync` много раз). Эмбиент — отдельный канал с теми же
  правилами. Эффекты — пул из 6 элементов, самый старый заменяется, если все заняты.
- **Громкости**: «Музыка», «Звуки», «Озвучка» (переключатель и громкость, см. раздел ниже); эмбиент идёт на громкости музыки. Mute (кнопка, клавиша M) и запрет звука платформой
  (Playgama `AUDIO_STATE_CHANGED`) — нулевая громкость: музыка продолжает идти беззвучно и при включении не «перематывается».
  Пауза платформы и скрытая вкладка: всё играющее встаёт и продолжается с того же места.
- **iOS Safari**: автозапуск звука разрешён только внутри жеста, поэтому фиксированный набор элементов (по два на музыку и эмбиент
  и пул эффектов) «разблокируется» первым касанием, кликом или клавишей — каждому проигрывается беззвучный WAV из data-URI; трек,
  который не удалось запустить до жеста, стартует при разблокировке. На iPhone громкость `HTMLAudioElement` программно не меняется
  (`volume` всегда 1): бэкенд определяет это сам, громкость каналов превращается в «вкл/выкл» через `muted`, а кроссфейд — в склейку.
- **Нет файла**: звук пропускается, одно предупреждение на файл (`[audio] нет файла …: звук пропущен`), игра не падает.
- QA: `__vn.audio()` → `{ music, ambient, audible, log, voice }`.

## Озвучка

Реплики `say` / `narrate` озвучиваются готовыми клипами. Настоящих клипов в репозитории пока нет (их сгенерируют позже): без них
озвучка молчит — ни запросов за файлами, ни предупреждений, ни задержек, игра идёт как раньше. Код: `src/core/voice.ts`
(соглашение о файлах и индекс, ядро без DOM), `src/stage/voice.ts` (`LineVoice`: клип по реплике), канал звука в `audio.ts` /
`audio_html.ts`, запуск и остановка по ходу партии — `DomUI.showLine`.

**Куда класть клипы**

```
assets/<папка эпизода>/voice/<язык>/<id клипа>.<ext>        assets/ep01/voice/ru/ep01.s12.l003.mp3
```

- `<папка эпизода>` — первый сегмент id эпизода: `ep01_murylev` → `ep01` (как у остальных ассетов, `assets/ep01/bg/…`).
  Папка с полным id (`assets/ep01_murylev/voice/…`) тоже принимается; короткая просматривается первой.
- `<язык>` — `ru`, `en`, `es`, `pt`. Клип играет только на своём языке: на языке без клипа реплика немая (русский голос под
  английский текст не подставляется). Озвучка только на русском — это клипы только в `voice/ru/`.
- `<id клипа>` — ключ локализации реплики (`ep01.s12.l003`). **Явное поле `voice` шага** `say` / `narrate` имеет приоритет: это id
  клипа в той же папке (`voice: take_two` → `…/voice/ru/take_two.mp3`); такого клипа нет в индексе — берётся клип по ключу. Один
  ключ — один клип, сколько бы шагов на него ни ссылалось (в ep01 12 ключей стоят в ветвях `when` дважды, сцена s42); чтобы такие шаги
  звучали по-разному, задайте им `voice`. Список `episode.assets.voice` для воспроизведения не используется.
- `<ext>` — `mp3` (канон: тот же формат, что у эмбиента и эффектов, в него приводит аудио `tools/fetch_assets.py`); допустимы `m4a`
  и `ogg`. Если клип лежит в нескольких форматах, берётся первый из `mp3 > m4a > ogg`. Имена — только `[a-z0-9_.]` в нижнем
  регистре, иначе файл в индекс не попадёт, а сборка предупредит.
- Вес: речь ≈ 14 знаков в секунду, моно 32–48 кбит/с — 0,23–0,35 МБ на минуту. Весь ep01 (≈ 58 тыс. знаков по
  `tools/export_voice_lines.py`, число растёт вместе с эпизодом) — около 70 минут, то есть ≈ 16–25 МБ на язык. Бюджет эпизода
  `assets.budget_mb` — 30 МБ, `check_dist` предупреждает с 40 МБ игровых ассетов (картинки сейчас 17,5 МБ).

**Индекс клипов.** `voice-index.json` в корне сборки (рядом с `episodes/index.json`) строит плагин ассетов по содержимому
`../assets` (или `$VN_ASSETS_DIR`). В `vite build` это файл в архиве (создаётся и пустым — на старте нет 404); в dev он отдаётся на
лету, поэтому положенный клип виден после перезагрузки страницы. Формат — папка эпизода → язык → имена файлов:

```json
{ "version": 1, "episodes": { "ep01": { "ru": ["ep01.s01.l001.mp3", "ep01.s01.l002.mp3", "take_two.m4a"], "en": ["ep01.s01.l001.mp3"] } } }
```

Рантайм читает его на старте параллельно эпизоду (не ждёт дольше 2,5 с; ошибка, не-JSON и таймаут дают пустой индекс) и
обращается к клипу **только если он есть в индексе**. Сборка пишет в лог `[vn-assets] озвучка: N клипов (ru …, en …)`.

**Воспроизведение**

- Клип стартует вместе с показом реплики на текущем языке; одновременно звучит один клип.
- Клип обрывают: листание, отмена партии (откат, загрузка сейва, выход в меню: `Session.cancel` → `DomUI.reset`), смена языка,
  выключение озвучки. Откат показывает прежнюю реплику заново — её клип играет с начала. При Skip прочитанного клипы не
  запускаются; Skip дошёл до непрочитанной реплики — он выключается, и она звучит. Пауза платформы (реклама, вкладка в фоне)
  ставит клип на паузу, после неё он продолжается с того же места.
- **Авто-режим**: пока реплика озвучена, ждёт конец клипа и ещё 300 мс (`AUTO_VOICE_TAIL_MS`), но не раньше, чем допечатан текст;
  пауза по длине текста при этом не используется. Нет клипа или он сорвался (файл не читается, автозапуск запрещён, озвучку
  выключили посреди реплики) — прежняя пауза по тексту. Зависший клип (оборвалась сеть) авто-режим держит не дольше 120 с.
- `cast[].voice`: `none` — персонаж не озвучивается, `ru_only` — только на русском, `all` и не задано — на всех языках, где есть клипы.
- Не слышно — не запускаем: озвучка выключена, Mute игрока (M), запрет звука платформой или громкость озвучки 0 — клип не
  стартует, реплика немая, авто-режим считает по тексту.
- Файл есть в индексе, но не читается: один `console.warn` на файл (`[audio] нет файла …: озвучка пропущена`), дальше клип
  молча пропускается. Запрет автозапуска (iOS до первого касания) предупреждения не пишет.

**Предзагрузка по блокам.** План блока (`collectBlockAssets`) хранит его реплики. Когда картинки блока загружены, `BlockPreloader`
просит `LineVoice` прогреть клипы блока (приоритет `now`), а у следующих блоков — первые 6 реплик (`idle`). Греются они очередью
по два (`VOICE_WARM_CONCURRENCY`), поэтому картинкам не мешают и вход в блок не задерживают. Где браузер не предзагружает аудио
сам (iOS до первого жеста), клип грузится при показе реплики и отменяется, если реплику сменили. Нет клипов — нет и прогрева.

**Настройки.** Пункт «Озвучка» в настройках: переключатель `voiceEnabled` (по умолчанию включена) и ползунок `voice` (громкость
0–1, по умолчанию 0,9). Хранятся в том же ключе `settings` (web-plain: `localStorage` `krimrussia:settings`, Playgama:
`bridge.storage`), старые сейвы настроек читаются. Пока озвучка выключена, ползунок недоступен; выключение посреди реплики сразу
обрывает клип. Итоговая громкость = `voice` × «общий мастер» (Mute игрока и запрет звука платформой, `AudioManager.audible`):
отдельной мастер-громкости в настройках нет. На iPhone громкость элемента программно не меняется — громкость озвучки там работает как
«вкл/выкл» (см. «Звук»).

**QA и инструменты.** `__vn.audio().voice` → `{ enabled, volume, playing, clips }`: включена ли озвучка, громкость, адрес играющего
клипа, сколько клипов эпизода на текущем языке есть в индексе (0 — озвучка молчит). Список реплик для озвучки и статистика по
персонажам: `python3 tools/export_voice_lines.py episodes/s1/ep01_murylev.json --out …` (см. `docs/season1/ep01-voices.md`).

**Смоук в браузере** (`e2e/smoke.mjs`, Playwright; доки: `06 §8`, чеклист Playgama п. 36), три сценария:
1. *Игра*: загрузка → контент-предупреждение → Skip до первого выбора → выбор → сейв → перезагрузка → «Продолжить» → загрузка слота →
   смена языка на лету (ru/en/es/pt без `[ключей]`) → автопилот до концовки → отсутствие ошибок и внешних запросов.
2. *Камкордер и графика*: «Слабо» по умолчанию, трансформ кадра дышит и остаётся малым, HUD записи только в реконструкции, на PixiJS
   камкордер рисует шейдер (холст помех скрыт, обёртку кадра CSS не трясёт; на DOM-рендерере — маленький холст помех), всплеск включается и сам заканчивается, «Выкл»/«Сильно» применяются на лету и выбираются в настройках,

   на месте). В обоих режимах сверяется `__vn.slots()` с тем, что должно получиться по наличию файлов (путь фона, цепочка спрайта):
   так Pixi-рендерер проверяется в настоящем браузере.
3. *Bridge SDK* (только сборка с `window.bridge`): `game_ready` один раз, пакетное хранилище, `level_started`, пауза.

   проверка, что ожидания в сценариях привязаны к состоянию игры (камера включается после показа первого кадра), а не к паузам.

экран, обрезанного текста и прокрутки страницы). `--only play,camera,bridge,matrix` запускает часть сценариев.

## Допущения

Решения, принятые там, где схема и документы молчат:

- Нет исхода `partial` — работает `fail`. `skipped` засчитывается как `skip.skip_counts_as` (по умолчанию `partial`);
  при `skip.allowed=false` кнопки пропуска нет, а программный `skipped` — ошибка.
- CG переживает смену сцены внутри блока; `cg.hide_after` (по умолчанию `true`) прячет её после ближайшей реплики;
  шаг `bg` и смена блока убирают CG. Вход в сцену убирает спрайты; музыка и эмбиент продолжаются, пока сцена или блок не задали другие.
- `block.when` проверяется только при входе в `entry_scene` из другого блока (ложное — берётся следующий включённый блок).
- Interstitial — только при входе в блок с `ad_break_allowed` (не первый блок, не при отладочном переходе и не при загрузке).
  Сейв во время `ad_break` уже указывает на новую сцену (поэтому интерпретатор не менялся, а чёрный кадр держит сцена).
- Титры `date_stamp` / `location` / `lower_third` не блокируют сюжет; `chapter` / `fact` и любые `fx` держат паузу `hold_ms`
  (Space, клик и Skip завершают её досрочно).
- «Только история» = таймеры выборов выключены + пропуск мини-игры доступен сразу. Настройка «Skip и непрочитанного» скрыта (по умолчанию выключена).
- Прочитанное запоминается по ключу локализации реплики; глобальные переменные сезона переносятся только в эпизоды с `order > 1`.
- Отличия от `tools/vnexpr.py` (сознательные): `==` / `!=` между строкой и числом не бросают исключение; упорядоченное сравнение
  разнотипных значений — `ExprError`; `bool` в сравнениях ведёт себя как число.
- Кнопка Mute отражает выбор игрока; запрет звука платформой действует отдельно (при возврате настройка игрока не теряется).
- Озвучка: клип только на языке реплики (без подстановки русского под en / es / pt); `voice` шага — id клипа в папке языка, нет его в
  индексе — клип по ключу; один ключ — один клип. Авто-режим с озвучкой: реплика длится до конца клипа + 300 мс, но не короче
  вывода текста; нет клипа — пауза по тексту. Выключенная озвучка, Mute, запрет платформы и громкость 0 клипы не запускают.
- «Голос» в настройках (`voice`) раньше был громкостью без воспроизведения; теперь это громкость озвучки реплик с умолчанием 0,9
  (было 1), рядом флажок `voiceEnabled`. Уже сохранённая громкость остаётся как была. Пункт показан и тогда, когда клипов нет вовсе.
- Эффекты камеры по умолчанию — «Слабо»; `prefers-reduced-motion` выключает их принудительно (выбор игрока при этом не стирается).
  «Сильно» заметнее чисел владельца — они относятся к «Слабо».
- Картинки меню и заставки эпизода (и логотип `logo_kr.webp`) грузятся до первого показа меню, но не дольше 2 с; нет файла — прежний тёмный фон и обычный заголовок.
  Название эпизода на плашке заставки — текст из локали поверх `title_plate.webp` (в картинке текста нет).
- Поворот к собеседнику: у набора спрайтов есть `facing` (куда персонаж повёрнут на кадрах); при двух и более персонажах
  на сцене стоящий слева зеркалится лицом вправо, стоящий справа — влево (`wantFlip` в `stage/renderer.ts`, оба рендерера);
  один персонаж остаётся как нарисован, `front` не зеркалится.
- Силуэт без `silhouette.webp` рантайм делает сам из найденного кадра спрайта; чёрный кадр `bg_black` — сплошной цвет без файла.
- Цветокоррекция фильтров (`vhs`, `archive_photo`, `night`, …) — CSS-фильтр на неподвижном слое кадра, а не часть дрожания:
  фильтр не пересчитывается на каждом кадре трансформации (при нехватке производительности можно перенести в Pixi, см. «Не сделано»).
- Десктопное ограничение 2:1 применяется только к устройствам с мышью (`hover: hover`); на тач-устройствах поле занимает весь экран.

2. **Звук на устройствах** (`03 §звук`): разблокировка первым касанием и режим «громкость как вкл/выкл» на iPhone написаны по
   спецификации и проверены на поддельных элементах и в Chromium; на настоящем iPhone / Safari не проверялись. Плавная громкость и
   кроссфейд на iPhone (WebAudio `GainNode`) не реализованы: там музыка склеивается без плавного перехода. Озвучка реплик
   реализована (раздел «Озвучка»), но настоящих клипов нет: проверена на сгенерированных тональных mp3 в Chromium и на
   поддельных элементах, на iPhone / Safari не проверялась. Chromium из Playwright собран без AAC и `.m4a` не
   декодирует — музыку в браузере проверяли mp3-данными в файлах `.m4a`; Chrome, Safari, Firefox и Edge с кодеками AAC играют.
3. **Мини-игры** (`04`): пять типов — настоящие реализации (`src/minigames`, ведут авторы мини-игр); остальные одиннадцать типов
   (`deduction_fill`, `identikit`, `custom` …) получают grey-box. Подробности и остаток работ — в `docs/architecture/04-minigames.md`.
4. **Интерфейс дела** (`06 §7`): панель дела для `procedural` (в пресете есть только флаг `casePanel`); структурированный бэклог
   (реплики свидетелей в «протокол»); экран «ранее в деле» при входе в главу; карта блоков и `title_key` блоков; галерея CG (v1.1);
   озвучка интерфейса (v1.1).
5. **Desktop** (`06 §3`): адаптер Tauri/Electron + steamworks.js; в `IPlatform` реализованы только `web-plain` и `playgama`.
6. **CI** (`06 §8`): смоук готов как скрипт, но в `.github/workflows/validate.yml` не подключён (файл вне `runtime/`).
   Нужна задача: job `runtime` — `npm ci`, `typecheck`, `test`, `build`, `npx playwright-core install --with-deps chromium`, `smoke`, загрузка `dist-playgama` артефактом.
7. **Playgama** (`playgama-constraints.md`): реклама проверена только на поддельном Bridge — нужна проверка в песочнице Playgama
   (`smoke --url`, п. 36 чеклиста); `playgama-bridge-config.json` минимальный; rewarded-подсказки включены только в grey-box
   `document_check` и `crime_scene_search`; платежи, лидерборды, достижения, кросс-промо не подключены.
8. **Контент и локали**: en заполнен ~8 % строк ep01 (остальное показывается русским через фолбэк), es / pt — скелеты;
   запас +35 % проверен только псевдолокализацией, шрифты — на псевдотексте; эпизодов, кроме ep01, нет (перенос `globals` между эпизодами проверен синтетически).
9. **Сейвы**: цепочка миграций готова, но версия формата одна (миграций пока нет); нет облачной синхронизации сверх возможностей Bridge.
10. **Доступность**: DOM-текст читается скринридером (реплика целиком в `aria-live`), но полный аудит (фокус-навигация по сцене,
    контраст, масштаб ≥ 200 %) не проводился.
11. **Производительность камкордера на телефонах**: шейдер записи (≈ 12 выборок на пиксель) измерен на Apple M4 Max (ANGLE Metal):
    ≈ 70 к/с rAF на 1280×720 и 390×844. Прежний путь — в Chromium без GPU (SwiftShader): там при включённой камере
    ≈ 5–10 к/с на 1280×720 и ≈ 15–22 к/с на 390×844 (без камеры ≈ 45; цифры плавают от загрузки машины), поэтому добавлена самозащита
    (раздел «Камкордер»). На телефоне с GPU не измерялось. Если на слабых устройствах будет тяжело: перенести цветокоррекцию из CSS-фильтра в `ColorMatrixFilter` Pixi
    (фильтр сейчас считается компоновщиком на каждом кадре дрожания) и склеить виньетку и интерлейс в холст помех.
12. **Размер плашки заставки**: геометрия `title_plate.webp` неизвестна; название ложится по центру с отступами, подгонка — после
    появления файла.

## Известные проблемы

- Смоук в `@sparticuz/chromium` с флагом `--single-process` зависает на втором браузерном контексте — это особенность
  урезанного Chromium из песочницы, не игры; обычный Chromium (Playwright, системный) работает. Уберите `--single-process` из `CHROMIUM_ARGS`.
- Чанк PixiJS (≈ 560 КБ, gzip ≈ 165 КБ) грузится лениво после меню; при отказе WebGL игра работает на DOM-рендерере.
- `vite preview` (и любой SPA-фолбэк) на отсутствующий файл отвечает `index.html` с кодом 200: картинка не декодируется, аудио не
  играет — рантайм считает это «файла нет» (плейсхолдер и одно предупреждение), `__vn.assets(true)` тоже. Dev-сервер и плагин ассетов
  отвечают честным 404. Chromium при этом сообщает `net::ERR_ABORTED` по оборванным запросам аудио (смена трека, перезагрузка) —
  это не ошибка игры, смоук такие обрывы игнорирует.
