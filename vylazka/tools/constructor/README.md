# Конструктор — программа на Mac

Партнёр 18.11: «давай конструктор отдельной простой программой без этих плясок с терминалом». Конструктор — обычная
программа «Конструктор» с иконкой: своё окно, без браузера и без Терминала.

- Всё, что ставишь, двигаешь, крутишь и убираешь, **сохраняется само** — в файлы игры `src/world/partner/*.json`.
- Вкладка **«Каталог»** — поиск по смыслу по всему каталогу Sand3D, около 106 тысяч вещей, с картинками. Можно искать
  по-русски: частые слова переводятся сами («старый чемодан» уходит в каталог как «old suitcase»).
- Понравилась вещь — **«В заявку»**; заявки — во вкладке «Заявки». Основная модель доводит их до игры: проверяет
  лицензию, что нет марок, надписей и персонажей, подбирает масштаб и материалы. После этого вещь появляется на полке.
- **«Залить в игру»** — кнопка справа вверху. Она проверяет сделанное правилами игры и отправляет на GitHub.
- При каждом запуске программа сама забирает свежее с GitHub и ставит, что для этого нужно.
- Ещё она держит правила партнёра для всех проектов в общей памяти Claude Code на этом Mac (`~/.claude/CLAUDE.md`, блок между
  метками `constructor:rules`; текст — `claude_memory.md`). Остальное в этом файле она не трогает (квиз 22.11: «Через Конструктор»).

## Один раз: поставить программу

Нужны Node.js и Git, а проект должен лежать в рабочей папке `~/Desktop/Claude/Usession` (у партнёра всё это стоит с
18.11). Последний раз в Терминале:

```bash
cd ~/Desktop/Claude/Usession/vylazka && git pull && npm run constructor:app
```

Программа «Конструктор» появится в `~/Desktop/Claude`, рядом с папкой проекта, и откроется сама. Перетащи её в Dock.

В первый раз Mac может спросить, можно ли «Конструктору» открывать файлы в папке «Рабочий стол». Ответ — «Разрешить»:
проект лежит на рабочем столе.

## Каждый раз

Открыть «Конструктор» из Dock или из папки. Закрыть — как любую программу (⌘Q или красная кнопка). Всё уже сохранено.

## Как двигать вещи

- **Двигать** (G): тяни вещь по полу; стрелки — по 10 см (⇧ — 50, ⌥ — 2).
- **Выше или ниже** (партнёр 19.11: «в этом режиме нужно перемещение вещи по вертикали»): над выбранной вещью — ручка ↕ с
  высотой над полом. Тяни её вверх или вниз; шаг 5 см, с ⇧ — по сантиметру. То же — ⌥ и тянуть саму вещь (у манекена — шарик
  таза). Выше 2,6 м и выше потолка не поднимется. Вещь игры от подъёма становится передвинутой — но если она легла обратно,
  туда же, где стояла, это не правка: записи «передвинута» не будет.
- **Под потолком** (край справа): ручка опускает вещь от потолка, край остаётся — в помещении с другим потолком она висит так же
  близко к нему. Уйти из-под потолка — только другим краем.
- **Замена** остаётся заменой и от ручки: с «Висит в воздухе» висит над местом вещи игры, без отметки встаёт обратно на её место.
  Сохранённая замена видна на месте своей вещи игры, а сама вещь игры под ней спрятана.
- **Отпустил — ложится** (квиз 19.11: «Ложится на то, что под ней»): поднятая вещь ложится на то, что прямо под её серединой, —
  столешницу, полку, крышку тумбы, твою же вещь, а нет ничего — на пол; строка вверху скажет, на что. В игре так же: в другом таком же
  помещении стол стоит иначе — вещь ляжет на то, что есть там. ⌘↑ / ⌘↓ — на опору выше или ниже.
- **Висит в воздухе** — галочка справа, в разделе «Выбрано» под названием (не путать с кнопкой «Карточка»): тогда вещь остаётся там, куда её подняли, и в игре висит на той же
  высоте; ⌘↑ / ⌘↓ — на 5 см (⇧ — 25, ⌥ — 1). Настенных вещей и того, что под потолком, это не касается.
- **Крутить** (R): кольца по трём осям, ⇧ — без щелчков по 15°; Q / E — на четверть.

## Как устроено окно (по правилам Apple)

Партнёр 18.11: «Перестрой весь интерфейс конструктора следуя четким правилам Apple HIG и на нативных элементах macos».

- **Панель окна** (наверху, как у любой программы Mac):
  - показать или скрыть полку;
  - место и помещение — меню-кнопки;
  - вариант помещения — у каждого своя расстановка, в игре помещение берёт один из них по жребию;
  - «Двигать / Крутить»;
  - «Отменить», «Копия», «Удалить»;
  - сохранено ли;
  - «Залить в игру»;
  - показать или скрыть инспектор.
- **Меню** (всё по-русски, и системные пункты тоже):
  - «Файл → Залить в игру…»;
  - «Правка»: «Отменить» ⌘Z (шаг с вещами; в поле ввода — текст), «Повторить» ⇧⌘Z (только текст), «Копия вещи» ⌘D,
    «Удалить вещь» ⌘⌫;
  - «Вид»: «Полка» ⌃⌘S, «Инспектор» ⌥⌘I, «Двигать», «Крутить», «Обновить окно» ⌘R, «Открыть в браузере»;
  - «Место»: места ⌘1–⌘4, «Помещение» (подменю), «Следующий вариант» ⌘], «Предыдущий вариант» ⌘[;
  - «Справка → Клавиши конструктора» ⌘?.
- Правый щелчок не открывает меню браузера («Перезагрузить», «Назад»); в полях ввода — обычное меню текста.
- **Полка слева** — боковая панель, полупрозрачная, как в Finder: сверху сегменты «Полка / Каталог / Заявки», поиск,
  фильтр полки — всплывающее меню («Все вещи», «Мебель», «Вещи памяти»…), список вещей.
- **Справа — инспектор**: выбранная вещь, поставленное в помещении, карточка вещи, правило.
- Шрифт, кнопки, поля и поиск — системные. Светлая и тёмная тема и цвет акцента — как в настройках Mac.

## Залить в игру

Кнопка **«Залить в игру»**. Негодное (вещь врастает в стену, перекрывает проход, нет имени) не уйдёт — окно скажет, что
поправить. Ушло — напиши в чат «залил». Основная модель соберёт игру по ссылке и доведёт заявки до полки. Если твои правки
не сошлись с моими, они уйдут отдельно — окно так и скажет; тоже напиши «залил», сведу сам.

В первый раз программа попросит войти в GitHub, прямо в окне:

1. «Сделать токен» — откроется GitHub, нужная галочка там уже стоит.
2. В поле **Expiration** выбрать **No expiration** — тогда входить больше не придётся.
3. Внизу страницы — «Generate token», скопировать строку `ghp_…`.
4. Вставить в окно конструктора — «Войти и залить».

Токен хранит связка ключей Mac — только для этого проекта: другие пароли (например, сохранённый в Safari пароль от
GitHub) программа не трогает. Больше он никуда не уходит. Если GitHub его не примет, окно попросит новый.

## Если что-то не так

- Окно пишет, что не открылось, — пришли основной модели снимок этого окна.
- Меню «Вид → Открыть в браузере» — тот же конструктор в окне браузера.
- По-старому, из Терминала (в `~/Desktop/Claude/Usession/vylazka`): `npm run constructor` открывает окно браузера,
  `npm run constructor:push` заливает, `npm run constructor:push -- --check` только проверяет.

## Для основной модели

- Рабочая папка партнёра — `~/Desktop/Claude/Usession` на Mac, клон всего репозитория (ветка `claude/cool-clarke-gdi2gp`).
  Облачная сессия её не видит: свежее туда приходит при запуске программы (`git pull --ff-only`), правки партнёра — через
  «Залить в игру».
- Программа: оболочка `mac/main.swift`; её собирает на Mac `mac/install.mjs` (`npm run constructor:app`): `xcrun swiftc`,
  пакет `.app`, подпись `codesign -s -`, иконка `mac/AppIcon.icns` (рисует `mac/icon.py`). Нет компилятора Swift — запасная
  программа (`osacompile`): тот же конструктор в окне браузера (`app.mjs --browser`). Оболочка только запускает
  `app.mjs` и показывает его строки `STATUS` / `READY` / `FAIL`, всё остальное делает `app.mjs`:
  - забирает свежее (`git pull --ff-only`; переписанный npm `package-lock.json` — обратно как в репозитории);
  - ставит пакеты (`npm ci`), если поменялся `package-lock.json`;
  - поднимает сервер (`serve.mjs`, `startServer`; старый запуск на порту 5199 уходит, порт тот же — на нём черновики окна);
  - пишет журнал `work/app.log` (в репозиторий не идёт).
- Поменял `main.swift` — увеличь `SHELL_VERSION` в `mac/install.mjs`, но только когда CI покажет, что новая оболочка
  собирается и работает. CI `constructor-mac.yml` собирает её из исходников при любой версии и запускает с
  `CONSTRUCTOR_SELFTEST=1`, только когда меняются файлы программы (и страница: `main.ts`, `page.html`). После проверки `app.mjs` у партнёра пересоберёт
  программу сам при следующем запуске, и окно скажет «закрой и открой снова». Снимки окна (светлая и тёмная тема)
  печатаются base64-строками последним шагом журнала: до хранилища артефактов из песочницы не дотянуться.
- Вид программы (оболочка 2): страница узнаёт оболочку по каналу `window.webkit.messageHandlers.ctor` и ставит класс
  `html.native` (стили — в `page.html`, «по Apple HIG»).
  - Страница шлёт оболочке состояние панели окна (`nativeState`: места, помещения, вариант, инструмент, можно ли
    отменить, выбрано ли, сохранение, полка и инспектор) раз в 150 мс, если оно поменялось.
  - Оболочка шлёт странице команды `window.__ctorNative.cmd(имя, значение)`: `hello`, `world`, `room`, `pick`, `tool`,
    `undo`, `duplicate`, `delete`, `deselect`, `push`, `help`, `library`, `inspector`, `lift` (1 / −1 — выше / ниже на 5 см;
    пункта меню для неё пока нет: ⌘↑ / ⌘↓ ловит сама страница, а пункт с этими клавишами мог бы отнять их у полей ввода).
  - Рукопожатие: оболочка, поняв состояние, отвечает `hello` с номером своей версии (пока в состоянии `hello: false`). Нет
    ответа за 4 с — страница снимает `html.native` и показывает свои кнопки: оболочка у партнёра бывает старше страницы.
    Поэтому поля `nativeState` только добавлять (в `PanelState` новые — необязательные), не переименовывать и не убирать.
  - `editing` — курсор в поле ввода: «Отменить» и «Повторить» из меню идут тексту (менеджер отмены окна), «Копия» и
    «Удалить» вещи выключены. У вещей повтора нет — ⇧⌘Z странице не отменяет.
  - Полка — прозрачная, под ней `NSVisualEffectView` (материал боковой панели).
  - В браузере и на странице в Claude класса нет — там прежний вид.
- `serve.mjs` — сервер окна. Он отдаёт:
  - страницу (`page.mjs`, `local: true`);
  - записи (`GET /api/work`, `PUT`/`DELETE /api/work/<коллекция>/<ключ>`);
  - каталог через спейс Sandflow (`/api/catalog/search|facets|object|render`; картинки — в `work/.cache`, в репозиторий не
    идут);
  - `/api/hello`, `/api/push`, `/api/token`, `/api/ping`, `/api/quit`.

  Чужим нельзя: имя хоста — только `127.0.0.1`/`localhost` с нашим портом, правки — только со своей страницы (Origin),
  кнопки сервера (POST) — только с меткой `x-constructor`. В контейнере сеть к спейсу — через прокси:
  `NODE_USE_ENV_PROXY=1 NODE_EXTRA_CA_CERTS=/root/.ccr/ca-bundle.crt npm run constructor -- --no-open`.
- `push_lib.mjs` — «Залить в игру» и для кнопки, и для `push.mjs`:
  - проверка (`check.ts`: `placedProblems`, `removedProblems`, `figureProblems`, ключи);
  - коммит этих файлов; нет имени в git — имя владельца репозитория и безадресная почта GitHub;
  - `git pull --rebase`, `git push` без вопросов в терминал. Не сошлось — откат, и коммит партнёра уходит веткой
    `partner/constructor-<время>`: её сводит основная модель (`git fetch origin 'partner/*'`), у партнёра ничего не меняется.

  Вход — `saveToken`: `git credential approve` с `credential.useHttpPath` — запись только для этого репозитория, на Mac — в
  связке ключей (`osxkeychain`). Ссылка «Сделать токен» — `tokenUrl`: открытый репозиторий — `public_repo`, иначе `repo`.
- Программа следит за веткой `claude/cool-clarke-gdi2gp`. Работа в другой ветке до партнёра не дойдёт, пока её не влить
  сюда (или пока программу не переведут на новую ветку).
- Коллекции: `things`, `figures`, `removed` → `src/world/partner/*.json` (игра: `placed_data.ts`, `figures_data.ts`);
  `verdicts`, `requests` → `tools/constructor/work/*.json`. Записи — по времени сохранения, одна строка на запись.
- Страница в Claude (`build.mjs`) — та же, но пишет в свою базу; перенос оттуда — руками, в те же файлы.
- Заявки доводятся `scripts/import_sand3d.py` (строка в `SHELF`), как полка 18.11 (`docs/vylazka/assets.md`, «Sand3D»).
