# «Вылазка» — хоррор-исследование от первого лица с бодикама

Вторая игра репозитория, отдельный пакет: по сборке от новеллы (`runtime/`) не зависит.
Игрок с одним фонарём лезет на заброшенные объекты; картинка — запись с нагрудной камеры.
Фонарь иногда глохнет, и его надо трясти. Движок — three.js (WebGL2), мир собирается кодом.

**Состояние: технический срез (этап 1 из 6).** Один тестовый уровень, собранный руками: коридор,
спальный отсек за гермодверью, лестница вниз. Проверяются вид, частота кадров и управление на
реальных устройствах. Генератор уровней, рой, цели вылазки и звук — следующие этапы
(план — `docs/vylazka/design.md`, появится на этапе 2).

## Команды

```bash
cd vylazka && npm install
npm run dev                # dev-сервер, http://localhost:5175
npm run typecheck && npm test
npm run build              # dist/ + проверка архива (scripts/check_dist.mjs)
npm run build:playgama     # dist-playgama/ с Playgama Bridge SDK
npm run smoke              # смоук сборки в Chromium (программный WebGL)
npm run smoke -- --dist dist-playgama
npm run smoke:matrix       # + раскладка на 6 размерах экрана × ru/en, скриншоты в e2e/out/
node e2e/shots.mjs         # скриншоты фиксированных ракурсов в e2e/out/shots/ — смотреть картинку глазами
```

Браузер для смоука: переменная `CHROMIUM_PATH`, иначе `/opt/pw-browsers/chromium`, иначе
`npx playwright-core install chromium`.

## Управление

| | ПК | Телефон |
|---|---|---|
| Идти | WASD или стрелки | стик под левым пальцем |
| Вести луч | мышь | палец на правой половине экрана |
| Бежать | Shift | стик до упора |
| Фонарь | F | кнопка справа внизу |
| Трясти заглохший фонарь | резко водить мышью из стороны в сторону; запасной способ — стучать F | быстро тереть кнопку фонаря; тряска самим телефоном — усиление, если датчик доступен |
| Пауза | P (Esc игрой не используется) | кнопка слева вверху |

## Параметры адреса

| Параметр | Что делает |
|---|---|
| `?q=low\|med\|high` | качество (иначе: телефон — среднее, ПК — высокое; через 10 с игры понижается само, если кадров мало) |
| `?lang=ru\|en` | язык (иначе — язык площадки или браузера) |
| `?touch=1\|0` | принудительно включить или выключить тач-управление |
| `?fps=1` | счётчик кадров, размер буфера, вызовы отрисовки и треугольники под временем записи |
| `?fail=N` | первый отказ фонаря через N секунд (`0` — без принудительного отказа) |
| `?pseudo=1` | псевдолокализация: строки длиннее на 35 % |
| `?autostart=1` | без стартового экрана |

## Как устроено

```
src/
  main.ts  app.ts  game.ts     загрузка; экраны, пауза, главный цикл; симуляция и сборка кадра
  lifecycle.ts                 единая пауза: площадка, скрытая вкладка, игрок, потеря захвата мыши, контекст
  platform/                    IPlatform: web-plain (localStorage) и playgama (Bridge SDK)
  core/                        целочисленный ГСЧ, i18n, математика
  world/                       kit (сборщик геометрии), shell (клетки 3 м → стены, пол, потолок),
                               props (реквизит), colliders (коробки в хеше), materials, test_level
  render/                      renderer, shaders, matcap_atlas, grime, exposure
  player/                      controller, rig (нагрудная камера), shake, motion, input_*
  systems/flashlight.ts        заряд, отказы, оживление тряской
  ui/                          hud, overlay, touch_controls, styles.css
  debug/debug.ts               window.__vz
```

- **Один материал на весь мир.** Атлас 4×4 matcap-шаров запекается на CPU при старте
  (`render/matcap_atlas.ts`), номер материала лежит в вершине. Сцена среза — один вызов отрисовки;
  кадр целиком — четыре (тень, мир, пыль, пост).
- **Свет**: `ambient (альбедо × AO) + фонарь × matcap`. Matcap берётся по направлению на фонарь
  и входит только в слагаемое фонаря, поэтому при погасшем фонаре мир не подсвечен «от камеры».
- **Тень фонаря** — ручной depth-pass из руки. Фонарь держат у пояса (0,27 м правее и 0,42 м ниже
  камеры): тени уходят вверх по стенам и заметно смещены. На низком качестве выключена.
- **Бодикам** — один пост-проход: бочкообразная дисторсия, хроматическая аберрация, усиление
  сенсора с шумом, мягкий клиппинг, виньетка. Усиление считается аналитически по лучам фонаря
  (`render/exposure.ts`), без чтения пикселей.
- **Разрешение фиксированное**: 640×360, 960×540 или 1280×720 по качеству; canvas растягивается CSS.
- **Симуляция** — фиксированный шаг 1/60 с; поворот луча применяется сразу, без ожидания шага.
- **Контроллер** — цилиндр против осевых коробок; препятствия ниже 0,36 м перешагиваются, поэтому
  лестницы собираются из ступенек-коробок.

## Отладочный API `window.__vz`

Ставится и в боевой сборке: смоук гоняет именно её. Основное: `state()`, `freeze(on)`,
`step(n, input)`, `tick(n)` (обороты цикла с настоящим вводом), `teleport(x, y, z, yaw, pitch)`,
`fail()`, `shake(level, seconds)`, `quality(q)`, `info()`, `probe()` (яркость кадра сеткой 32×18),
`shadows(on)`, `loseContext(ms)`, `lang(code)`.

## Что переиспользовано из `runtime/`

Скопировано с адаптацией (не импортируется): платформенный слой, `check_dist.mjs`, каркас смоука,
ядро i18n, `mulberry32`, шрифт JetBrains Mono (OFL).

## Проверено и не проверено

- Проверено в Chromium на программном WebGL: логика, вёрстка на шести размерах экрана, сборка
  с настоящим Bridge SDK на его mock-платформе, потеря и восстановление графического контекста.
- **Не проверено: частота кадров на телефоне.** В тестовом окружении нет видеокарты. Это и есть
  задача технического среза — посмотреть на реальном устройстве.
- Акселерометр и захват мыши внутри iframe порталов не проверялись: в автотесте их нет.
