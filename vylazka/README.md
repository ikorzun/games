# Untitled Session — исследование от первого лица

Вторая игра репозитория (папка пакета пока прежняя — `vylazka/`), отдельный пакет: по сборке
от новеллы (`runtime/`) не зависит. Игрок с одним фонарём ходит по заброшенному убежищу, в которое
вросли домашние комнаты, и ищет вещи из воспоминаний; место время от времени рассыпается и выбрасывает
в другое. Кнопки действия нет: игрок ходит, смотрит и светит. Язык по умолчанию — английский.
Движок — three.js (WebGL2), мир собирается кодом. Замысел — `docs/vylazka/untitled_session.md`,
числа и устройство — `docs/vylazka/design.md`. Плакаты на стенах убежища — настоящие листы-картинки
(`assets/posters/`, там же README; запросы, по которым они сделаны, — `docs/vylazka/posters.md`).

**Состояние:** ядро (сессия, скачки, вещи), три карманных пространства (белое нигде, луг, кукольный
домик), особые помещения, кинескоп и рендер мира точками (как 3D-скан: под лучом фонаря мелкие мягкие
точки сходятся в поверхность, вокруг висят россыпью и разлетаются, когда луч уходит) сделаны. Звука нет: звуковой слой готов, клипов нет, набор
надо собирать заново (`audio/README.md`). Частота кадров на телефоне не измерена. Публикация на
площадке отложена до оценки владельцем.

## Команды

```bash
cd vylazka && npm install
npm run dev                # dev-сервер, http://localhost:5175
npm run typecheck && npm test
npm run build              # dist/ + проверка архива (scripts/check_dist.mjs)
npm run build:playgama     # dist-playgama/ с Playgama Bridge SDK
npm run build:single       # dist/ одной страницей (dist-single/untitled_session.html): код, шрифты и плакаты вшиты
npm run smoke              # смоук сборки в Chromium (программный WebGL)
npm run smoke -- --dist dist-playgama
npm run smoke -- --shell   # в chromium-headless-shell: тот же браузер, что на CI
npm run smoke:matrix       # + раскладка на 6 размерах экрана × ru/en, скриншоты в e2e/out/
node e2e/shots.mjs         # скриншоты ракурсов тестового коридора в e2e/out/shots/ — смотреть картинку глазами
node e2e/shots_gen.mjs     # скриншоты сгенерированного бункера: по кадру на примету и на коридор яруса
node e2e/shots_props.mjs   # скриншоты витрины реквизита: по кадру на предмет из реестра PROPS
node e2e/shots_pocket.mjs --kind meadow   # четыре вида карманного пространства (void, meadow, dollhouse); --q, --walk N
```

Браузер для смоука: переменная `CHROMIUM_PATH`, иначе `/opt/pw-browsers/chromium`, иначе
`npx playwright-core install chromium`.

Браузеров два, и перед отправкой смоук стоит прогнать в обоих. Локально по умолчанию идёт полный
Chromium — он ведёт себя как браузер игрока. CI берёт `chromium-headless-shell` (ключ `--shell`),
а у того захват мыши ненастоящий: курсор стоит в точке (0, 0), каждое движение приходит парой
«+координата, −координата», нажатие кнопки — одиночным рывком. Проверка, зелёная в одном браузере,
может упасть в другом; какой браузер гонял тест, написано в первой строке лога.

Ещё одна особенность `chromium-headless-shell`: пока мышь захвачена, сам браузер без остановки шлёт
странице синтетические «движения» — десятки тысяч событий в секунду. Лёгкая страница их разбирает,
а на полном уровне они копятся: за секунды браузер и страница набирают гигабайты памяти, кадры почти
перестают идти, длинный сценарий заканчивается падением страницы («Target crashed»). В полном Chromium
и в настоящих браузерах этого нет. Поэтому смоук захватывает мышь по-настоящему только там, где
проверяется сама мышь, и только на лёгкой странице (низкое качество): вторая страница сценария
«Игра на ПК» — тряска, пауза, потеря и возврат захвата — и первая половина «Звука». Картинку
на высоком качестве тот же сценарий проверяет на отдельной странице с заглушкой. Остальным страницам
смоук тоже подставляет заглушку захвата (`FAKE_LOCK` в `e2e/smoke.mjs`): игра считает мышь
захваченной, браузер её не трогает.

Чтение пикселей кадра (`__vz.probe()`, `__vz.probeColor()`) на программном рендере медленное: каждый
вызов ждёт, пока кадр дорисуется целиком. Поэтому частоту и порядок событий проверки считают по
состоянию игры (`__vz.state()`), а кадром подтверждают картинку — несколькими чтениями, не десятками.
Сама игра пикселей не читает.

Проверки не должны зависеть от скорости машины. Часть событий игры живёт в настоящем времени: вспышка
воспоминания горит 5,2 с, сообщения — несколько секунд, графический контекст возвращается, когда
пересоберутся шейдеры. Такое читается тем же обращением к странице, которым вызывается, или ожидается
по условию (`waitForFunction`), а не по сроку: CI уже падал на проверке, которая читала вспышку через
десяток обращений после её появления. Запас по времени проверяется прогоном на двух ядрах из четырёх:
`taskset -c 0,1 node e2e/smoke.mjs --shell --matrix --no-shots`.

И от случая проверки зависеть не должны. До заморозки (`freeze(true)`) игра успевает прожить несколько
кадров в настоящем времени, и сколько именно — зависит от машины; дальше случайные числа игры идут
уже по-другому. Поэтому то, что игра выбирает случайно (срок карманного пространства — 46–60 с),
проверка читает из состояния (`pocketInfo.stay`), а не угадывает по общему пределу.

## Управление

| | ПК | Телефон |
|---|---|---|
| Идти | WASD или стрелки | коснуться и отпустить — шаг вперёд; держать палец на месте — идти вперёд, пока держишь; в левой половине экрана повести пальцем — стик (в любую сторону) |
| Вести луч | мышь (если страница не даёт её захватить — мышь с зажатой кнопкой) | вести пальцем в правой половине экрана; если палец уже идёт удержанием, он ведёт луч, а ходьба продолжается |
| Бежать | Shift | стик до упора |
| Фонарь | F | кнопка справа внизу |
| Трясти заглохший фонарь | резко водить мышью из стороны в сторону; запасной способ — стучать F | быстро тереть кнопку фонаря; тряска самим телефоном — усиление, если датчик доступен |
| Пауза | P (Esc игрой не используется) | кнопка слева вверху |
| Звук | M или кнопка «Звук» на заставке и на паузе | кнопка «Звук» там же |

Кнопки действия нет: клавиш E, R, Tab и кнопок «взять» и «цели» больше нет. Вещь «вспоминают»,
подержав её в луче.

## Параметры адреса

| Параметр | Что делает |
|---|---|
| `?seed=N` | сид убежища (по умолчанию берётся из профиля игрока) |
| `?rank=1\|2\|3` | ранг объекта: 1 — два яруса, 2 и 3 — три (по умолчанию — по числу успешных вылазок) |
| `?level=pocket_void\|pocket_meadow\|pocket_dollhouse` | просмотр карманного пространства: белое нигде, луг, кукольный домик |
| `?level=test` | вместо генератора — коридор технического среза, собранный руками |
| `?level=show` | витрина реквизита: предметы реестра `PROPS` в ряд у стены; `&props=a,b,c` — только названные |
| `?q=low\|med\|high` | качество (иначе: телефон — среднее, ПК — высокое; через 10 с игры понижается само, если кадров мало) |
| `?lang=ru\|en` | язык (по умолчанию английский; русский включается и в настройках) |
| `?touch=1\|0` | принудительно включить или выключить тач-управление |
| `?fps=1` | счётчик кадров, размер буфера, вызовы отрисовки и треугольники под временем записи |
| `?fail=N` | первый отказ фонаря через N секунд (`0` — без принудительного отказа; по умолчанию 40, в тестовом коридоре 12) |
| `?pseudo=1` | псевдолокализация: строки длиннее на 35 % |
| `?autostart=1` | без стартового экрана |
| `?audio=папка` | взять весь набор звуков из папки рядом с игрой, а не из сборки (послушать новые клипы без пересборки) |

## Как устроено

```

  lifecycle.ts                 единая пауза: площадка, скрытая вкладка, игрок, потеря захвата мыши, контекст
  platform/                    IPlatform: web-plain (localStorage) и playgama (Bridge SDK)
  core/                        целочисленный ГСЧ, i18n, математика
  gen/                         layout (план убежища с домашними комнатами и опасности по сиду),
                               ascii (карта текстом)
  world/                       kit (сборщик геометрии), shell (клетки 3 м → стены, пол, потолок),
                               props, props_bunker, props_more (реквизит убежища и реестр PROPS),

                               thing_mesh (вещи как отдельные сетки),

                               pocket_dollhouse (кукольный домик),
                               furnish (обстановка по типам помещений), dress (следы людей и времени),
                               signs (надписи: тексты и раскладка атласа), showcase (витрина),
                               level_build (план → уровень), colliders, materials, test_level
  render/                      renderer, shaders, matcap_atlas, detail (фактуры), grime (карта
                               запустения), noise, signs_atlas, exposure
  player/                      controller, rig (нагрудная камера), shake, motion, input_*
  systems/                     flashlight (отказы, оживление тряской; заряд не садится),
                               session (воспоминания, паника, среда, обвалы),

                               jumps (когда и куда выбрасывает: скачки),
                               director (когда и чем пугать), anomalies (лестница, комната)
  swarm/                       ai (поведение роя на графе уровня), body (черви и фигура)
```

- **Один материал на весь мир.** Атлас 8×4 matcap-шаров запекается на CPU при старте
  (`render/matcap_atlas.ts`), номер материала лежит в вершине. Помещение — один чанк и один вызов
  отрисовки; длинные коридоры режутся блоками 4×4 клетки. В сгенерированном бункере кадр — 20–50
  вызовов и 60–110 тысяч треугольников вместе с проходом тени.
- **Поверхность = шар + фактура + запустение.** Фактуры — стопка из 17 тайловых слоёв
  (`render/detail.ts`), рельеф наклоняет нормаль по экранным производным. Запустение — одна карта
  (`render/grime.ts`), по которой краска облезает чешуйками, металл ржавеет, бетон сыреет. Всё
  рисуется кодом, готовых картинок в сборке нет. Подробно — раздел 6 документа с правилами.
- **Надписи** — атлас на canvas (`render/signs_atlas.ts`) по раскладке из `world/signs.ts`:
  трафареты, таблички, плакаты ГО, шкалы. Лист со знаком — обычный четырёхугольник мира с uv в атлас.
- **Окружение пространств**: у убежища и карманных пространств свой `Env` — рассеянный свет, цвет
  дали, туман, множитель света фонаря (`world/pockets.ts`). Остальное — `design.md`, разделы 6 и 7.
- **Распад и красная сетка**: вершинный шейдер рассыпает мир или вещь, отдельный проход рисует
  красный каркас; кинескоп и срывы кадра — в пост-проходе (`render/shaders.ts`).
- **Дымка в луче** — отдельный маленький проход по глубине кадра (`HAZE_FRAG`).
- **Рой** — один вызов отрисовки: шаблон червя (9 колец × 5 граней) размножен инстансами, изгиб тела
  считает вершинный шейдер; прозрачность — экранным дизерингом, без сортировки. В момент поимки рой
  смыкается в метре от камеры, а экран закрывает срыв сигнала: сотня червей на объективе стоила бы кадров.
- **Звук** — только файлы, по списку `audio/manifest.json`; синтеза в коде нет. Разовые звуки идут
  из событий шага, петли пересчитываются каждый кадр из состояния игры. Пока клипов нет, игра молчит
  и ничего не запрашивает; подробности — `audio/README.md` и раздел 13 документа с правилами.
- **Отсечение.** Чужой ярус рисуется только с лестницы и в 16 м от её площадок; дальше 30 м чанки
  не рисуются — свет фонаря туда не достаёт.
- **Генератор** считает только целочисленным ГСЧ: один сид даёт один уровень на любом устройстве.
  План и сборка уровня третьего ранга занимают десятки миллисекунд и пока идут в основном потоке.
- **Свет**: `ambient (альбедо × AO) + фонарь × matcap`. Matcap берётся по направлению на фонарь
  и входит только в слагаемое фонаря, поэтому при погасшем фонаре мир не подсвечен «от камеры».
- **Тень фонаря** — ручной depth-pass из руки. Фонарь держат у пояса (0,27 м правее и 0,42 м ниже
  камеры): тени уходят вверх по стенам и заметно смещены. На низком качестве выключена.
- **Бодикам** — один пост-проход: бочкообразная дисторсия, хроматическая аберрация, усиление
  сенсора с шумом, мягкий клиппинг, виньетка. Усиление считается аналитически по лучам фонаря
  (`render/exposure.ts`), без чтения пикселей.
- **Разрешение фиксированное**: 640×360, 960×540 или 1280×720 по качеству; canvas растягивается CSS.
- **Симуляция** — фиксированный шаг 1/60 с; поворот луча применяется сразу, без ожидания шага.
- **Контроллер** — цилиндр против осевых коробок; препятствия ниже 0,36 м перешагиваются, поэтому
  лестницы собираются из ступенек-коробок.

## Отладочный API `window.__vz`

Ставится и в боевой сборке: смоук гоняет именно её. Основное: `state()`, `freeze(on)`,
`step(n, input)`, `tick(n)` (обороты цикла с настоящим вводом), `teleport(x, y, z, yaw, pitch)`,
`fail()`, `shake(level, seconds)`, `quality(q)`, `info()` (вызовы отрисовки, треугольники, размер
буфера; про облако точек — `points`: сколько точек отдано видеокарте, `clouds`: у скольких сеток есть
облака, `cells`: сколько клеток с точками живо), `cloudUsage()` (сколько из отданных точек шейдер
показывает; считает перебором, медленно), `probe()` (яркость кадра сеткой 32×18),
`shadows(on)`, `scan(on)` (облако точек вкл/выкл), `loseContext(ms)`, `lang(code)`, `level()` (помещения и приметы), `gotoLandmark(id)`,
`gotoRoom(id)`, `hazards()`, `swarm('release'|'appear'|'sleep', hops)`, `phase(n)`, `anomalies()`, `calm(on)` (без роя и пугалок),
`audio()` (что загружено, что игра просила сыграть и что прозвучало, какие петли идут), `mute(on)`.

Добавились (интерфейс `VzDebugApi` в `src/debug/debug.ts`): `look(yaw, pitch)`, `toggleLight()`,
`start()`, `pause(on)`, `render()`, `things()` (вещи сна и их состояние), `gotoThing(id)`, `sees(id)`
(почему вещь видна или нет), `memory()` (искомое воспоминание), `reveal()` (поторопить следующее),
`gotoMemory()`, `gotoPocket('exit' | 'focus', distance?)` (в карманном пространстве встать перед красным проёмом выхода или перед макетом в домике и посмотреть на него), `jump(to, style)` (начать скачок), `gotoFx(fx)` (встать в помещение с особенностью
`strobe`, `dark`, `wire`, `thin`), `finish()` (считать всё вспомненным), `calmFlash(on)` (мягкие
вспышки), `probeColor()` (средний цвет кадра и доля красных точек), `missingKeys()`, `showcase()`,
`sheets()` (какие листы-плакаты загружены), `sheetMarks()` (где они висят), `gotoSheet(i, distance?)` (встать
перед листом), `sheetContrast(id)` (есть ли в клетке листа рисунок: у пустого листа около 10, у плаката — десятки).
В `state()` есть `dark` — `{ for, shifts }`: сколько секунд фонарь не светит и сколько вещей темнота
уже поменяла. Там же `pocketInfo` — `{ age, stay, done, fade, exit, focus, blanks }`: сколько прошло и
сколько отпущено в карманном пространстве, сделало ли оно своё дело, насколько редеет (1 → 0,2), где
выход и главный предмет (макет), какие вещи — белые болванки; вне пространства `null`. Строка-вспышка
горит несколько секунд настоящего времени: читайте её тем же `page.evaluate`, которым вызвали событие.
Убраны `goals()`, `items()`, `gotoGoal(i)`, `gotoItem(id)`, `gotoExit()`.

Скопировано с адаптацией (не импортируется): платформенный слой, `check_dist.mjs`, каркас смоука,

## Проверено и не проверено

- Проверено в Chromium на программном WebGL: логика (список проверок — вывод `npm test` и `npm run smoke`), вёрстка на шести размерах экрана, сборка
  с настоящим Bridge SDK на его mock-платформе, потеря и восстановление графического контекста.
- **Не проверено: частота кадров на телефоне**, в том числе новых эффектов (кинескоп, распад, красная
  сетка, строб). В тестовом окружении нет видеокарты; посмотреть надо на реальном устройстве.
- **Нет звука:** клипов нет, набор надо собирать заново под новый замысел.
