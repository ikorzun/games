# Эпизод 1 «Смерть за квартиры» — план точек выбора (вовлечение игрока)

Назначение: исправить главную претензию к пилоту — «просто прокликиваю диалоги». Документ задаёт правила,
технику и разбивку работы для сценаристов-черновиков (`episode-drafter`); решения в §2 приняты старшей моделью и
не обсуждаются в черновиках. Структура блоков, схема и мини-игры не меняются.

## 1. Диагноз (до правки)

| Показатель | Значение |
|---|---|
| Реплик (`say` + `narrate`) | 658 |
| Точек выбора | 10 (из них с таймером — 1, в s35) |
| Самые длинные промежутки без выбора | s22–s28 — 121 реплика; s16–s18 — 56; s38–s40 — 53; s12–s14 — 43; s42 — 43; s31–s32 — 40 |
| Первый выбор | s11, после 52 реплик пролога |

Цель: точка выбора каждые 12–20 реплик, и у каждой — **немедленная видимая реакция** (1–3 реплики, разные для
разных опций). Часть выборов оставляет след в переменных, который «стреляет» позже (отголоски).

## 2. Правила точек выбора

1. **Исход дела неизменен** (`bible.md` §6). Выборы меняют тон, доверие, какие детали игрок узнаёт, судьбы вымышленных
   персонажей и текст эпилога. Ни один новый выбор не трогает `case_strength` (баланс концовок в s48 рассчитан) и
   не создаёт новых концовок.
2. **Виды и доля** (`choice.kind`):
   - `dialogue` — основа (≈ 60 %): как Громов отвечает или спрашивает; 2–3 опции. Эффекты: `style_hard +1` или
     `style_soft +1` (или без эффекта); `trust_oper ±1` — только если Сайко в сцене и реплика касается его.
     `remember: false`.
   - `investigative` (≈ 25 %): что спросить, проверить, заметить; опции дают разные сведения; могут ставить новый
     флаг (`bool`) для отголосков. `remember: true`.
   - `moral` — не больше одной новой на часть; эффекты на `boss_favor`, `gromov_rep`, `style_*`; `remember: true`.
   - `tactical` — только блок b11 (pursuit), с таймером; исход операции не меняет (за это отвечает `hasty`).
   - `cosmetic` — не больше одной на часть; без эффектов; `remember: false`.
3. **Таймер** (`timer_ms` 8000–15000, только `dialogue`/`tactical`): 1–2 на часть, в напряжённых разговорах (допрос,
   звонок, лестница). `default_option` — «промолчать / подождать»: естественная пассивность Громова, и это не
   проигрыш, а один из характерных ответов.
4. **Реакции.** Каждая опция ставит служебную переменную: `{"var": "last_choice", "op": "set", "value": "<option_id>"}`.
   Сразу после выбора идут 1–3 реплики с `"when": "last_choice == '<option_id>'"`, затем общий текст. Реакция — не оценка
   игрока («правильно/неправильно»), а поведение персонажа: Сайко усмехается, Левина молчит, Ковригин потеет,
   Ирина Лапина отворачивается. Реакции ставить до следующего выбора (там `last_choice` перезапишется).
5. **Отголоски.** В более поздних сценах своей части — реплики с `when` на флаги и переменные ранних выборов, своих и
   из предыдущих актов: `docs_first`, `found_photo`, `galina_trust`, `witness_safe`, `buyer_detained`, `boss_pressure`,
   `wrong_suspect`, `notary_pressed`, `trust_oper`, `style_hard`, `style_soft`. Часть D обязана написать отголоски
   стиля: Сайко в s42 (`style_hard >= 3`; `style_soft >= 3`; `style_hard <= 1 && style_soft <= 1` — «ты как бумага,
   Громов») и рассказчик в s46–s47 (одна реплика на каждый из трёх случаев).
6. **Журнал решений** в эпилоге показывает все выборы с `remember: true`, поэтому `remember: true` — не больше чем у
   двух новых выборов на часть.
7. **Текст.** Манера речи каждого персонажа — по `ep01-voices.md` (раздел «Речь» в профиле). Подписи опций ≤ 60
   знаков: намерение Громова или короткая цитата, как у существующих («Давить: „вы знали“», «Показать карточки и
   молчать»). Все опции — в характере Громова: он не хамит, не шутит, не угрожает; «жёстко» для него — холодная
   формальность и давление фактами; «мягко» — участие без обещаний. «Правильных» ответов нет.
8. **Запрещено:** новые персонажи, фоны, CG, музыка, мини-игры, концовки; изменение текста существующих ключей;
   удаление реплик (переносить в сцену-продолжение можно); реальные имена; насилие действием.

## 3. Техника: выбор внутри сцены

- `choice` — всегда **последний** шаг сцены; `goto` опции — id сцены. Чтобы поставить выбор внутри `sNN`: обрезать
  `sNN` на точке вставки (последний шаг — `choice`), остаток перенести в новую сцену `sNNb` (следующая вставка —
  `sNNc` и т. д.) в том же блоке, с тем же `stage`; `music`/`ambient` в новой сцене не указывать — они продолжают играть.
- Новая сцена начинается с `show` всех персонажей, стоящих на сцене (те же `expression` и `position`), с
  `"transition": "cut"` — иначе персонажи «мигнут». Переход между сценами одного блока с одним фоном движок делает
  `cut` автоматически.
- Все опции обычно ведут в одну и ту же `sNNb`. Отдельные сцены-ветки (`sNN_<opt>` → `jump` в `sNNb`) — только если
  реакция длиннее трёх реплик.
- `block_scenes` в черновике — новый список сцен блока: все старые в прежнем порядке, новые сразу после родителя.
- Ключи: новые реплики в существующей сцене продолжают нумерацию (`ep01.s12.l019`…); в новой сцене — `ep01.s12b.l001`…;
  выбор — `ep01.<scene>.c_<name>.prompt` и `ep01.<scene>.c_<name>.<option_id>`. Все новые ключи — в `locale_ru`.
- Выражения — только из набора персонажа (`assets.sprites[].expressions` в мастере); `--check` это проверяет.
- Опция с условием (`when`) показывается неактивной (по умолчанию `hidden_when_false: false`): игрок видит, что
  упустил; подпись должна читаться и в неактивном виде.
- Переменные `style_hard`, `style_soft` (int) и `last_choice` (string) уже объявлены в мастере. Новые флаги — через
  поле `variables` черновика (`bool`, `default: false`, с `doc`), не больше четырёх на часть.

## 4. Формат черновика и проверка

Файл: `episodes/s1/_drafts/ep01_murylev/choices_<part>.json` — поля `part`, `block_scenes`, `variables` (опц.),
`scenes` (каждая изменённая сцена **целиком** и каждая новая; нетронутые сцены не включать), `locale_ru` (только
новые ключи). Проверка:

```bash
python3 tools/merge_drafts.py episodes/s1/ep01_murylev.json --check --part choices_<part>
```

Критерий «готово»: «проверка пройдена», план по количеству точек из §5 выполнен, у каждого нового выбора есть
реакции по §2.4. Черновик **не трогает** `episodes/s1/ep01_murylev.json`, `locales/*`, схему, инструменты и чужие
черновики. Слияние (`merge_drafts.py` без `--check`), правка и линтер — за старшей моделью.

## 5. Разбивка на части

Карта сцен (реплик / существующих выборов) и цели. Предложения по содержанию — ориентир; сценарист читает сцену и
ставит выбор там, где он драматургически оправдан, соблюдая шаг 12–20 реплик. Цель по числу новых реплик — чтобы
эпизод не распух: реакции короткие.

## 6. Отчёт сценариста

Таблица новых выборов (сцена, id, kind, опции, эффекты, таймер), список новых сцен и переменных, вывод `--check`,
5–10 мест для проверки старшей моделью (тон, факты, право). Старшая модель сливает части по одной, читает все новые
реплики, правит, запускает линтер и `tools/loc_sync.py skeleton`, затем коммитит.
