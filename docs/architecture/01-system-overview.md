# 01. Обзор системы

## Что мы делаем

Антология визуальных новелл по мотивам передачи «Криминальная Россия»: каждый эпизод — одно
реальное дело 90-х, рассказанное языком передачи (закадровый рассказчик, реконструкции,
«говорящие головы» следователей, архивные документы), но интерактивно: игрок ведёт
следствие, принимает решения и проходит мини-игры, встроенные в сюжетные биты.

Четыре языка: русский (источник), английский (обязательный fallback для веб-платформ),
испанский, португальский.

## Три принципа, на которых держится архитектура

1. **Сценарий — это данные, а не код.** Эпизод описывается JSON-файлом по схеме
   `schemas/episode.schema.json`: блоки → сцены → шаги. Из одного файла собирается и веб-рантайм,
   и (при необходимости) Ren'Py-скрипт. Сценаристы и переводчики не трогают код движка.
2. **Нарратив определяет форму.** Каждый эпизод относится к архетипу (серийный убийца, война
   группировок, мошенничество…). Архетип задаёт шаблон блоков, визуальный режим каждого блока,
   набор мини-игр, тип выборов и палитру. Описано в `02-narrative-blocks.md` и `03-visual-language.md`.
3. **Исторический исход неизменен, агентность — в маршруте и цене.** Игрок не может «спасти»
   реальных жертв или «отпустить» реального преступника. Он выбирает, как идёт следствие,
   что оно стоит персонажам (в т.ч. вымышленным), насколько полным будет архив дела и к какой из
   концовок (`canonical` / `variant` / `early`) он придёт. Это и этическое правило, и способ
   удержать «документальность» передачи.

## Слои

```
┌──────────────────────────────────────────────────────────────────┐
│ CONTENT  episodes/*.json  locales/<lang>/*.json  assets/<ep>/      │  ← сценаристы, художники, переводчики
├──────────────────────────────────────────────────────────────────┤
│ TOOLS    tools/validate_episode.py  tools/loc_sync.py  build/     │  ← линтер, экспорт/импорт локалей, сборка
├──────────────────────────────────────────────────────────────────┤
│ RUNTIME  ядро новеллы (интерпретатор шагов) + реестр мини-игр     │  ← один рантайм, много эпизодов
│          + пресеты presentation + система сейвов + i18n           │
├──────────────────────────────────────────────────────────────────┤
│ PLATFORM адаптеры: Playgama Bridge (web) │ Steam/itch (desktop)   │  ← язык, сейвы, реклама, lifecycle
└──────────────────────────────────────────────────────────────────┘
```

- **Content** не знает о движке. Все строки — ключи локализации. Все ассеты — ASCII-пути.
- **Tools** гарантируют целостность до сборки: схема, ссылки, достижимость сцен, ключи и
  плейсхолдеры в четырёх языках, ассеты.
- **Runtime** — интерпретатор шагов (`say`, `choice`, `minigame`, `branch`…), пресеты показа
  (`reconstruction`, `chronicle`, `talking_head`…) и реестр мини-игр по типам.
  Выбор конкретного движка — `06-engine-and-pipeline.md`.
- **Platform** — тонкие адаптеры: откуда брать язык, куда сохранять, когда показывать рекламу.
  Требования Playgama зафиксированы в `../platform/playgama-constraints.md`.

## Единицы контента

| Единица | Что это | Кто владеет |
|---|---|---|
| **Сезон** | 6–10 эпизодов, объединённых общей рамкой (напр. «Сезон 1: 1993–1996») и сквозными персонажами следственной группы | продюсер |
| **Эпизод** | одно дело, 30–60 минут игры, свой JSON, свои локали, свой пакет ассетов, 2–5 концовок | сценарист эпизода |
| **Блок** | нарративная функция внутри эпизода (cold_open, investigation, confrontation…) с фиксированным визуальным режимом | сценарист + арт-директор |
| **Сцена** | единица показа: фон + персонажи + последовательность шагов; всегда заканчивается явным переходом | сценарист |
| **Шаг** | атомарная команда: реплика, титр, показ спрайта, выбор, мини-игра, ветвление | сценарист |
| **Мини-игра** | типизированный модуль с конфигом, исходами и обязательной возможностью пропуска | геймдизайнер + программист |
| **Архив** | коллекционируемые материалы дела (документы, фото, факты) — мета-прогрессия и «документальный» слой | сценарист |
