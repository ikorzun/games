# 04. Мини-игры: каталог, правила интеграции, привязка к сюжетным битам

## 1. Правила (почему мини-игры здесь вообще есть)

Исследование (`../research/01-vn-best-practices.md`, E.5–E.6) даёт три урока:
MIIP — механики поддерживают нарратив и **не растягивают** время прохождения, заданное сценарием;
Attentat 1942 критиковали за «случайные мини-игры между интервью»; The Case of the Golden Idol
хвалят за то, что механика **повторяет мысль детектива**. Отсюда правила:

1. **Диегетичность.** Каждая мини-игра — реальное следственное действие (осмотр, сверка
   документов, картотека, допрос), а не «пазл ради пазла». Поле `beat` обязательно.
2. **Коротко.** 1–3 минуты; 4–6 мини-игр на эпизод; первая — лёгкая, последняя — «босс».
3. **Результат — улика или флаг, не game over.** `success / partial / fail` ведут в сюжет;
   провал закрывает улику, а не эпизод. Досрочная концовка возможна только по накоплению провалов.
4. **Улики переносятся.** Поздние мини-игры используют то, что игрок добыл раньше
   (в допросе доступны только найденные улики) — это главный стимул играть честно.
5. **Пропускаемость.** `skip.allowed: true` всегда; кнопка появляется после N неудач
   (`after_fails`) или сразу в режиме «только история». Пропуск считается `partial` по умолчанию.
6. **Тач и мышь.** Никаких «быстрых пальцев»: окна реакции широкие, таймеры отключаемы.
7. **Локализуемость.** Все подписи — ключи; текст не «впечатан» в картинки; словесные пазлы
   (анаграммы, кроссворды) запрещены — они не переводятся.
8. **Конфиг, а не код.** Тип реализуется один раз в рантайме; эпизод задаёт `config`
   по схеме `schemas/minigames/<type>.schema.json` (линтер проверяет).

Рекомендуемая петля эпизода (исследование, резюме п. 2): осмотр по протоколу → карта-хаб / бюджет
времени → доска улик → допрос «надавить/предъявить» → **реконструкция** → суд/эпилог → монтаж эфира.

Пять типов из эпизода-примера уже описаны схемами в `schemas/minigames/`:
`crime_scene_search`, `document_check`, `database_search`, `evidence_board`, `interrogation_press`.
Остальные схемы появляются вместе с первой реализацией типа.

### Правила реализованных типов (рантайм)

**`evidence_board`** (`runtime/src/minigames/evidence_board.ts`). Узлы — `config.nodes`: `id` или `{id, label_key, kind}`
(`kind`: person | flat | property | document; если типы заданы, люди стоят справа, остальное слева — «слева квартиры,
справа люди»). Тап по узлу, тап по второму — связь; повторный тап по нитке (или по значку ✓/✕, или соединение той же
пары ещё раз) убирает её. Каждая связь проверяется сразу: пара из `required_links` — верная, любая другая (в том числе
`decoy_links`) — ошибка; ошибки считаются по уникальным парам и не «возвращаются» при удалении нитки. Все верные связи —
`success`; ошибок стало больше `max_wrong_links` или вышло время — `partial` при `partial_threshold` (по умолчанию 1)
верных связей, иначе `fail`. Узел, не входящий ни в одну верную связь, — «пустышка»: связь с ним считается ошибкой.

**`interrogation_press`** (`runtime/src/minigames/interrogation_press.ts`). Утверждения идут по очереди; для каждого игрок
предъявляет карточку улики (верная из `contradicted_by` «ломает» утверждение, неверная — ошибка, и карточка гаснет для
этого утверждения), «надавить» (если задан `press_key`; без ошибки) или оставляет утверждение без ответа. В списке игрока
— только доступные улики (`requires` истинна в `ctx.vars()`) и приманки (улики без `requires`, они ничего не опровергают).
`evidence`: `id` или `{id, label_key, requires}`; у улики-строки условие берётся из утверждения (единственная улика в
`contradicted_by`, а если их несколько — первая из тех, у кого условия ещё нет). `suspect` — id из `cast`, его имя стоит
над репликой. Опровергнуто ≥ `full_threshold` утверждений — `success`, ≥ `partial_threshold` — `partial`, иначе `fail`;
`max_mistakes` ошибок обрывают допрос («он замолчал»).

**Общее для обеих.** Итог показывается в нижней панели, `onResult` вызывается по кнопке «Далее» (пропуск — сразу).
«Пропустить» появляется после `skip.after_fails` ошибок, в режиме «только история» — сразу; подсказка — за rewarded
(`skip.hint_rewarded_ad`); таймер — `time_limit_ms`, только при включённых таймерах. Прогресс (`serialize/restore`) пишется
после каждого хода. Непригодный `config` превращается в grey-box. Ссылки внутри `config` проверяет линтер
(`tools/validate_episode.py`, `minigame_integrity`).

### Что НЕ берём и почему (из исследования, раздел A)

- **Поиск по ключевым словам (Her Story)** — свободный ввод требует стемминга и словарей на каждый
  из четырёх языков и плох на тач. Берём клик по тегам/объектам (Immortality) и банк слов.
- **«Правда / сомнение / ложь» (L.A. Noire)** — непрозрачно и pass-fail; критика единодушна.
  Давление/стресс — только скрытый модификатор к «надавить/предъявить»; на одно противоречие —
  2–3 эквивалентные улики (`contradicted_by` принимает массив).
- **Аркадные вставки Danganronpa** (буквы, тайминг) — диссонируют с документальностью.
- **Полная аудио-прослушка (Unheard)** — умножает стоимость озвучки на четыре языка; делаем текстовые
  стенограммы с шумами и обрывами, голос — только для 1–2 ключевых реплик (ru).

### Уровни сложности дедукции (дёшево, без смены контента)

`difficulty` в `reconstruction`/`deduction_fill`: **easy** — слоты подсвечены, подтверждение каждого;
**normal** — подтверждение группами по 3 (Obra Dinn); **hard** — подтверждение только всей
реконструкции. На доске улик соединение «тап — тап», перетаскивание опционально; верно/неверно
дублируется иконкой и анимацией, не только цветом (Obra Dinn монохромна и читаема).

## 5. Общий контракт реализации

- Интерфейс `IMinigame` (см. `06-engine-and-pipeline.md` §5): `mount / pause / resume /
  serialize / restore / onResult / destroy`. Пауза обязательна (реклама, уход в фон).
- Вход: `config` (по схеме), `ctx` (переменные эпизода для `requires`, язык, настройки
  доступности: таймеры выкл., режим «только история»).
- Выход: `success | partial | fail | skipped` → `outcomes` → `goto` + `effects` + `archive_unlock`.
- Автосейв: состояние мини-игры сериализуется при паузе и при каждом «ходе» (найденная точка,
  проведённая связь), чтобы поворот экрана и interstitial не сбрасывали прогресс (требование Playgama).
- Подсказка: по кнопке после N ошибок; на веб-платформах может быть rewarded-рекламой
  (`skip.hint_rewarded_ad`), но подсказка — бонус, а не условие продолжения.
- Сложность (`difficulty`) меняет лимиты ошибок/времени, не содержание.
- Телеметрия: `minigame_start/finish/skip` с типом и результатом через `bridge.analytics`
  (чтобы видеть, где игроки застревают и пропускают).

## 6. Антипаттерны

- Мини-игра, результат которой ни на что не влияет.
- Мини-игра на реакцию без режима доступности.
- Текстовые головоломки (анаграммы, шифры на буквах) — не локализуются.
- «Game over» из мини-игры или повтор без ограничения попыток.
- Мини-игра дольше трёх минут или две подряд без сцены между ними.

## 7. Реализация в рантайме: crime_scene_search, document_check, database_search

Код: `runtime/src/minigames/<тип>.ts` и `<тип>.css`; общая оболочка (заголовок, прогресс, таймер, пропуск,
подсказка, пауза, итог, автосейв) — `mg_shell.ts` / `mg_shell.css`. Config, непригодный для механики, превращает
игру в grey-box (эпизод остаётся проходимым); линтер (`tools/validate_episode.py`) проверяет перекрёстные ссылки
внутри config и ловит такое заранее.

**Общее.**
- *Неудачи* — промахи (осмотр), ошибки (документы, картотека). `skip.after_fails` — сколько неудач нужно до появления
  «Пропустить»; в режиме «только история» кнопка есть сразу; пропуск считается по `skip.skip_counts_as`.
  Нет `partial` в `outcomes` — частичный итог идёт по `fail` (правило интерпретатора).
- Итог (успех / частично / неудача) показывается плашкой; в сюжет игра уходит по «Далее». Партия заканчивается, когда
  цель достигнута, неудач стало `max_*` или вышло время.
- Таймер — `minigames.<id>.time_limit_ms` (у осмотра ещё `config.time_limit_ms`); выключается настройками «таймеры»
  и «только история»; время вышло — итог по найденному. `difficulty` лимиты не пересчитывает: числа задаёт автор.
- Подсказка за rewarded-рекламу — при `skip.hint_rewarded_ad` и если платформа умеет; бесплатных подсказок нет,
  кроме `hint_after_misses` у осмотра. Подсказка — бонус: пройти можно и без неё.
- Автосейв после каждого хода; `serialize()` — чистый JSON, `restore()` игнорирует мусор.

**crime_scene_search.** `scene_bg` → фон из `assets.backgrounds` (нет файла — серая заглушка, зоны видны коробками
с подписями). `hotspots[].rect` — доли картинки целиком `[x, y, w, h]`; для попадания зона растягивается минимум
до 56 px и получает запас 6 px, из пересекающихся побеждает ближайший центр; `?debug=1` в адресе рисует рамки и id
зон (калибровка по утверждённой картинке). `required: true` — улика: все найдены → success, часть → partial, ничего →
fail; `required: false` подписывается, но в итог и в промахи не входит. Промах — тап мимо всех зон (двойной тап —
один промах), `max_misses`. С клавиатуры: стрелки двигают прицел (Shift — мелко), Enter / Space осматривает.
*Что нашёл — то и узнал* (2026-10-13): у зоны могут быть `archive_unlock` (материал блокнота) и `effects` (как у
outcome) — их применяет интерпретатор для каждой найденной зоны после эффектов итога (`finishMinigame(result, found)`;
список находок — из `serialize().found`). Без списка (автопилот, тесты) успех считается находкой всех обязательных
зон, частично и неудача — ничего; пропуск не даёт находок никогда («не смотрел — не видел»). Линтер проверяет, что
материал объявлен, а эффекты — на объявленных переменных нужного типа. Осмотр показывается во весь экран (`is-wide`):
картинку разглядывают.

**document_check.** Документ — лист: подложка из `assets.documents` (нет файла — бумага) и текст из локали — тот же,
что показывает шаг `document` (`text_key` шага или `archive_items[asset]`). `fields[]` — нажимаемые фрагменты;
`fields[].text_key` — строка, которая **дословно** входит в текст документа на каждом языке (иначе фрагмент
выводится отдельной строкой под текстом; линтер сверяет по ru). `discrepancies[]` — какие из `fields` настоящие
несоответствия (`hint_key` — объяснение: показывается при находке и как подсказка); остальные — ловушки, нажимаемы
первые `decoys` штук (не задано — все); ловушка = ошибка (`max_mistakes`). Успех — найдено `required`, partial —
хотя бы одно. Телефон: вкладки и свайп по листу; широкий экран: листы рядом.

**database_search.** `fields` — поля карточки по порядку (первое — заголовок строки, `date` — справа);
`values[]` — подпись поля (`label_key`) и варианты значений (`options[]`: `id` + `text_key`; `{n}` в строке — номер
квартиры; у `date` вариантов нет — даты дд.мм.гггг). Колода детерминирована (`seed`, иначе из id мини-игры) и от
языка не зависит: `target_count` карточек несут весь `pattern`; по ⌊шум / 4⌋ карточек на каждое поле паттерна
совпадают только по нему (одного фильтра мало); остальные случайны. Чипы-фильтры — у полей с 2–8 вариантами
