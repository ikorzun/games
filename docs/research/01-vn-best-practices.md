## 0. Самое важное (резюме)

1. **Порядок работ:** аутлайн → полный сценарий («script lock») → прототип на плейсхолдерах в движке → арт → звук → полировка → QA/LQA. Так советуют и MIIP (habr), и Lemmasoft/itch-сообщество: сценарий определяет список ассетов, мини-игры, сложность кода и время прохождения (а значит и цену). Озвучку и локализацию MIIP сознательно отложили на конец (se7en.ws, ч. 2).
2. **Числа для скоупа:** практический ориентир сообщества — 10 000 слов ≈ 45–60 минут игры; для 2–5 часов нужен один «путь» в 25–60 тыс. слов (при 125–300 слов/мин по разным оценкам). Короткая ВН по шкале VNDB — 2–10 ч.
3. **Ассеты для 2–5 ч:** ориентир — 12–25 фонов (с вариантами время суток), 4–8 персонажей по 6–12 эмоций (слои: тело + лица), 8–20 CG. Пример из devlog'а: фон 4–5 дней, полный набор спрайтов персонажа 3–4 дня, CG 4–5 дней работы художника → 15 фонов + 6 персонажей + 12 CG ≈ 125–160 человеко-дней арта.
4. **Цены:** ставки художников от $20–60 за бюст-спрайт у начинающих до $60–100+ за спрайт с эмоциями и $70–300 за фон у опытных фрилансеров; CG — $250–800 у студий. В рублях: «экстремальный» бюджет 700 ₽ спрайт / 1000–1200 ₽ фон / ~1200 ₽ CG (DTF, 2026) против 4500–6500 ₽ за персонажа у художников с прайсом (VK).
5. **Перевод:** вендорские ставки EN→ES-LATAM / PT-BR ≈ €0.09–0.14 за слово, EN→ES-ES — €0.10–0.14; рынок в целом $0.08–0.20; вычитка ≈ 50 % от ставки перевода; русские бюро RU→EN ≈ 3.6–4.3 ₽/слово (данные 2024). 40 тыс. слов × 3 языка у вендоров ≈ €11–17 тыс. без вычитки.
6. **Выбор вариантов языка:** PT-BR, а не PT-PT (бразильцы отвергают европейский португальский; доля PT-BR в Steam ~4.3–4.4 % против ~0.2–0.4 % у PT-PT). Испанский: Steam-доля es-ES ~4.6–4.9 %, es-419 ~0.75–0.9 %, но es-419 — «нейтральный» латиноамериканский с *tuteo*; Playgama отдаёт язык только как ISO 639-1 (`ru`, `en`) без региона → в web-версии придётся выбирать один вариант испанского/португальского по умолчанию.
7. **Движок — главная развилка.** Playgama требует интеграцию Bridge SDK (реклама, Storage вместо localStorage, `platform.language`, `game_ready`), архив ≤ 300 МБ, обязательную английскую локализацию. Официальные обёртки Bridge есть для Unity, Godot 3/4, Construct 3, GDevelop, GameMaker, Defold, Cocos Creator, Scratch и «Plain JS» (Phaser, PlayCanvas). **Для Ren'Py адаптера нет** — web-сборка Ren'Py (WASM) работает, но интеграция рекламы/хранилища потребует самодельного JS-моста.
8. **Ren'Py** остаётся лучшим «ВН-движком по умолчанию» для desktop (бесплатный, MIT + части LGPL, система `translate`, подмена картинок через `tl/<lang>/`, lint, layeredimage, мини-игры через creator-defined displayables и screens; версии 8.4 (июль 2025) и 8.5 (ноябрь 2025) активно развиваются, web-сборка поддерживается с 8.1). Но web-версия: нет многопоточности, видео только через браузер, рекомендация держать `game.zip` < 100 МБ, браузер не кэширует файлы > 50 МБ, лимит itch.io 1000 файлов.
9. **Godot 4 + Dialogic 2** — самый сбалансированный вариант «один движок на web + desktop + мини-игры + Playgama»: официальный Bridge-плагин для Godot 4, однопоточный web-экспорт по умолчанию с 4.3 (работает на iOS/macOS), CSV-локализация с ключами `#id`, но Dialogic 2 требует Godot 4.5+ и остаётся менее «ВН-зрелым», чем Ren'Py; WASM ядра ~20–27 МБ без сжатия, долгая компиляция на мобильных.
10. **Unity + Naninovel** (~$150, скидки 50 %; Unity Personal бесплатен до $200 тыс. выручки, Runtime Fee отменён) — самый «про» вариант с встроенной локализацией (папки `Resources/Naninovel/Localization/<RFC5646>`, managed text, подмена ресурсов по локали) и официальным Bridge-пакетом, но тяжелее для соло и в web.
11. **Phaser/PixiJS + Ink/Yarn** — минимальный бандл и полная свобода мини-игр, Bridge подключается напрямую, но всю ВН-обвязку (бэклог, скип, сейвы, откат, локализация) пишете сами; Ink «не спроектирован под локализацию» (нужен инструмент тегирования строк ID), Yarn Spinner имеет line ID и CSV-экспорт.
12. **Локализация — ключи vs исходный текст:** для UI и мини-игр — строковые ключи; для реплик допустим источник-как-ключ (Ren'Py), но дублирующиеся строки получают один перевод и теряют контекст. Расширение текста EN→ES ≈ +20–25 %, EN→PT ≈ +15–30 %; короткие строки UI — до +100 %. Шрифт с кириллицей + латиницей с диакритикой: Noto Sans (с сабсетом), Open Sans, PT Sans, Inter; на Playgama шрифты должны лежать внутри сборки (внешние ресурсы запрещены).
13. **Кавычки:** RU «…» (внутри „…“), EN “…” (US) / ‘…’ (UK), ES «…» → “…” → ‘…’ (рекомендация RAE), PT-BR “…” (в Португалии традиционно «…»).
14. **AI:** Steam требует отметить генеративный AI (включая текст — т.е. и AI-перевод), itch.io с ноября 2024 требует тег «AI Generated» (под-теги Graphics / Sound / Text & Dialog / Code), иначе проект не индексируется. Исследования 2024–2025: постредактирование «сырого» MT для творческих текстов переводчики считают медленнее и хуже перевода с нуля; LLM-черновик — только с человеческой редактурой и LQA носителем.
15. **Сценарий:** для документальной/true-crime истории работают «branch-and-bottleneck» с флагами, структура «рыбья кость» (линейный хребет с ответвлениями-интервью/уликами), механики Her Story (поиск по базе интервью), The Case of the Golden Idol (дедукция «заполни пропуски»), Attentat 1942 (интервью + мини-игры + «монеты» на пересмотр). Эвристика пейсинга: ~50 реплик без выбора или смены сцены — пора вставить выбор.
16. **UX/доступность:** скорость текста и мгновенный вывод, авто/скип (только прочитанное vs всё), бэклог/откат, быстрые сейвы и автосейв, масштабирование шрифта (Steam рекомендует возможность увеличить текст до ≥ 38 px при 1080p), не кодировать смысл только цветом, субтитры к SFX, отсутствие мерцания, таймеры на выборах — только отключаемые; контент-предупреждения на странице магазина и в игре.

| 8 | Полировка и QA | Lint, тест сейвов между версиями, чек-листы магазинов | Чек-листы Steam/itch/Playgama закрыты | см. F.6 |

### A.2. Почему именно так (и типичные провалы)

- **Сценарий первым**, потому что он — единственный источник оценки объёма: количество фонов/спрайтов/CG, мини-игр, время прохождения (а значит цена и ожидания игроков) выводятся из него (se7en.ws ч.2; Lemmasoft p=503489).
- **Не писать сразу в движке**: авторы на Lemmasoft/itch отмечают, что код «размывает» рукопись и проблемы текста становятся не видны (https://lemmasoft.renai.us/forums/viewtopic.php?p=399869; https://attagirlstudios.itch.io/ellswynns-saga/devlog/688234/turning-the-story-script-into-a-game).
- **Плейсхолдеры до арта**: позволяют проверить структуру, темп, точки выборов и дать художнику точное ТЗ; замена плейсхолдеров на финальный арт — штатный шаг (VN Paths; Placeholder Pals).
- **Ограничить скоуп**: 2–3 ветки для первого проекта (Lemmasoft p=503489); первая ВН «вряд ли будет лучшей» (itch.io blog 912418).
- **Специфичный для вашего случая риск — платформа.** На Playgama обязательны Bridge SDK (инициализация, Storage, реклама, `game_ready`), архив ≤ 300 МБ, английская локализация и автоопределение языка (checklist, п. 1–19). Если это выясняется после выбора движка и готового арта — переделка. Поэтому **вертикальный срез (одна глава + одна мини-игра) должен быть собран и выложен в песочницу Playgama до начала основного арта.**
- **Локализация после script lock**, иначе каждая правка умножается на 3 языка; но интернационализация (ключи строк, шрифты, запас места в UI, отсутствие текста в картинках) закладывается на этапе прототипа (см. D).
- **Сейвы**: план совместимости сейвов между версиями нужен до релиза демо, иначе апдейты ломают прогресс игроков (см. F.5).
- **MIIP-урок про команду**: даже «соло за 3–4 месяца» к 6-му месяцу превратилось в 2D-художника + 2 Spine-аниматоров + маркетинг + тестировщиков + локализаторов (habr 824424) — закладывайте бюджет и время на подрядчиков.

## C. Сравнение движков: ВН + мини-игры + 4 языка + HTML5 (Playgama) + desktop

### C.0. Жёсткие требования Playgama (из официального чек-листа и Bridge SDK)

Источник: Game checklist (https://wiki.playgama.com/playgama/mcp/game-checklist.md), Bridge SDK Setup (https://wiki.playgama.com/playgama/bridge-sdk/setup.md), Platform (https://wiki.playgama.com/playgama/bridge-sdk/api/platform.md), Storage (https://wiki.playgama.com/playgama/bridge-sdk/api/storage.md).

- **Bridge SDK обязателен**: инициализация; чтение `platform.language` (ISO 639-1: `ru`, `en` — **без региона**) и применение локализации; `platform.sendMessage('game_ready')` после загрузки; реакция на паузу и состояние звука (реклама, уход в фон); сохранения **только через `bridge.storage`** (не `localStorage`, не файлы движка), пакетно, массивом ключей; минимум один формат рекламы (interstitial обязателен), показ в естественных паузах (переходы между главами), rewarded — только opt-in.
- **Локализация**: английский обязателен как язык по умолчанию и fallback; при нескольких языках — автоматический выбор по `platform.language`; ручной переключатель должен быть понятен без знания текущего языка (иконки, названия языков на самих языках: English, Español).
- **Сборка**: архив ≤ **300 МБ**, `index.html` в корне, только латиница в именах файлов, **никаких внешних ресурсов** (шрифты, библиотеки — внутри сборки; снаружи только сам Bridge с CDN Playgama), никакой сторонней аналитики (GA4 и т.п.), никаких внешних ссылок на соцсети/сайты, без привязки к домену.
- **UI/UX**: вёрстка держится на всех размерах (portrait и landscape, если поддерживаются оба), без скроллбара страницы, у попапов есть «закрыть», мобильные тачи отзывчивы, **долгое нажатие не должно вызывать выделение текста/контекстное меню** (критично для ВН!), полноэкранный режим на мобильных, на desktop не шире 2:1, читаемые шрифты на любом экране, кнопка mute; обязательны и мобильное, и десктопное управление. Рекомендуемая матрица тестов: 360×640, 390×844 (portrait), 915×412 (landscape), 1280×720, 2560×1440.
- **Аудио**: ogg/mp3, не wav — «ограничение не 300 МБ, а время загрузки».
- **Официальные обёртки Bridge**: Plain JS (JS Core — Phaser, PlayCanvas, LayaAir и т.п.), Unity (пакет + WebGL-шаблон), Construct 3, GDevelop, Godot 3 и Godot 4 (плагин + HTML-шаблон), GameMaker, Defold, Cocos Creator, Scratch/TurboWarp. **Адаптера для Ren'Py нет.** Bridge ≥ 2.2.0 требуется для песочницы (инструкции консоли).

Следствия для ВН: (1) сейвы Ren'Py-web (IndexedDB) напрямую не подойдут — нужно либо проксировать сохранения в Bridge Storage, либо выбирать движок с готовым адаптером; (2) `platform.language` без региона → в web-версии один испанский и один португальский по умолчанию (рекомендуется PT-BR и «нейтральный» испанский, см. D.3) с ручным переключением; (3) 300 МБ — комфортно для ВН с webp/ogg, но web-ядро движка тоже считается.

### C.1. Ren'Py

- **Лицензия/цена**: бесплатно, большая часть кода под MIT, части — производные от LGPL, поэтому игры нужно распространять с соблюдением LGPL (страница лицензии, зеркало https://translations.launchpad.net/renpy-doc/trunk/+pots/license/en_GB/+translate?start=0; https://en.wikipedia.org/wiki/Ren%27Py).
- **Актуальность**: 8.4.0 «Tomorrowland» — 12 июля 2025, Python 3.12, web-дистрибутив отдельным пакетом `renpy-8.4.0-web.zip`, новая `config.web_unload_music`, отложенные `FS.syncfs` в web, настраиваемый путь к `game.zip` (https://www.renpy.org/release/8.4.0, https://www.renpy.org/doc/html/changelog.html); 8.5 — ноябрь 2025: автоматизированный фреймворк тестирования игр, Live2D в web, Unicode 17 (https://lemmasoft.renai.us/forums/viewtopic.php?p=575901); 8.5.2 — январь 2026 (https://www.ifwiki.org/Ren%27Py). PWA-режим (установка на устройство, локальный кэш) — с 8.1 (https://www.renpy.org/release/8.1.0).
- **Web/HTML5**: движок компилируется в WebAssembly, «Build Web Application» даёт `web.zip` + папку файлов, нужен веб-сервер; целевые браузеры — свежие Chrome/Edge/Firefox/Safari и их мобильные версии (https://renpy.org/doc/html/web.html). Ограничения по документации: видео только форматами браузера и только `renpy.movie_cutscene()`; аудио — либо браузерный быстрый путь, либо медленный встроенный с большим числом форматов; **нет многопоточности и предзагрузки изображений** (возможны «икания» кадра); сокеты/requests заблокированы песочницей; хостеры ограничивают размер и число файлов; **браузеры не кэшируют файлы > 50 МБ** (повторная загрузка при каждом запуске). Progressive download: в `progressive_download.txt` «+» помечает ассеты для дозагрузки, пока не докачалось — показывается пикселизированная версия картинки; отключение прогрессивной загрузки ломало игру в некоторых браузерах на Mac (https://renpy.org/doc/html/web.html, https://itch.io/t/2289319/creating-htmlweb-builds-last-tested-with-75122070801). RenPyWeb FAQ: держать `game.zip` < 100 МБ (https://renpy.beuc.net/). Практика: 70 МБ картинок → 8 МБ после webp+ogg; лимит itch.io в 1000 файлов считается по web-архиву **плюс** содержимому `game.zip` (https://arghbulous.itch.io/the-muzeum/devlog/1309260/renpy-web-build-tips-to-stay-under-the-1000-files-limit-other-optimisations, https://itch.io/t/2109287/too-many-files-publishing-renpy-vn-to-play-in-browser). Сообщество отмечает «бета-статус» web-порта: ошибки записи БД в Firefox, ложные срабатывания антивируса, обрезку экрана на Android при запуске со страницы itch.io (https://ebbasuke.itch.io/vampirehunter/devlog/404568/note-to-self-remember-this-when-making-a-web-build, https://itch.io/t/6707019/html5-game-is-cut-off-in-fullscreen-on-android-but-only-when-launched-from-the-itchio-page).
- **Мини-игры**: creator-defined displayables — наследуете класс Displayable, переопределяете `render()` (возвращает Render), `event()` (получает pygame-событие; возвращённое значение завершает интеракцию); объект должен быть pickleable (нельзя хранить Render) — «самая мощная настройка», требует Python/ООП (документация, зеркало https://translations.launchpad.net/renpy-doc/trunk/+pots/udd/en_GB/+translate?start=11). Для простых мини-игр (клик по уликам, drag-and-drop, таймеры, пазлы) достаточно screens с imagebutton/drag/timer (⚠ деталей документации screens поиском не проверял). Пикабу-обзор: «расширяем до бесконечности за счёт PyGame» — но в web pygame-уровень ограничен однопоточностью.
- **Локализация**: Launcher → «Generate Translations» создаёт `game/tl/<язык>/` с блоками `translate <lang> <id>:` для диалогов и `translate <lang> strings:` для меню/`_()`-строк; общий `common.rpy`; переводы редактируются руками или через внешние инструменты (документация, зеркало https://translations.launchpad.net/renpy-doc/trunk/+pots/translation/ja/+translate?start=36; обновлённый туториал Lemmasoft https://lemmasoft.renai.us/forums/viewtopic.php?p=466825; devlog https://mysterycorgi.itch.io/renpy-tips/devlog/74300/implementing-translations). Картинки подменяются автоматически: `game/tl/piglatin/library.png` приоритетнее `game/library.png`, включая подпапки (галерея) — имя языка строчными буквами. Шрифты и стили по языку — `translate <lang> python:` / `translate <lang> style:`; переключение `renpy.change_language()`. Известная ловушка: добавление имён персонажей/текста экранов в `strings` руками вызывало падение у пользователя (https://lemmasoft.renai.us/forums/viewtopic.php?p=573944). ⚠ Не проверено поиском, но по устройству системы: идентичные строки в `translate strings` получают один перевод на все вхождения — контекстозависимые слова («Да» / «Yes» как согласие и как ответ на вопрос о факте) нужно разводить разными исходниками.
- **Текст/шрифты**: кириллица и латиница с диакритикой — через любой TTF/OTF со нужными глифами (DejaVuSans по умолчанию содержит кириллицу — ⚠ по общим сведениям); Unicode 17 в 8.5.
- **Сейвы**: см. F.5 (ломаются при переименовании лейблов/структур).
- **Mobile**: Android/iOS поддерживаются с 6.99 (iOS требует Mac и платную учётку Apple) (https://lemmasoft.renai.us/forums/viewtopic.php?p=364282); разработчики жалуются, что Android-сборка сложнее десктопной и периодически ломается конкретными версиями (https://boundbynight.itch.io/bbn-vn/devlog/256162/continuing-efforts-for-an-android-build, https://demonicalpha.itch.io/lykaois/devlog/517161/android-version).
- **Инструменты**: lint («Check Script») — статический анализ: неопределённые изображения, незагружаемые файлы картинок/аудио, прыжки на несуществующие лейблы; не ловит динамические ссылки (https://itch.io/post/8219406, https://itch.io/post/7809384). Layeredimage — группы атрибутов (одновременно виден один атрибут группы), `always`, `default`, `auto` (https://gruntsteel.itch.io/distant-travels/devlog/452114/how-to-set-up-layeredimages-in-renpy-new-sprite-teaser).
- **Playgama**: адаптера нет. ⚠ Не проверено поиском: web-порт Ren'Py позволяет вызывать JavaScript из Python через emscripten-мост, т.е. технически можно написать собственную интеграцию Bridge (реклама, пауза аудио, прокси сейвов в Storage), но это нетривиально и без официальной поддержки; реалистичнее публиковать Ren'Py-web на itch.io/своём хостинге, а для Playgama делать игру на движке с адаптером.

### C.2. Naninovel (Unity)

- Цена ~$150–165 в Asset Store, частые скидки 50 % (https://hazedenki.net/post/from-zero-to-game-dev-part-2-choosing-a-visual-novel-engine-utage-vs-naninovel, https://itch.io/post/5517174); исходники в пакете; целевые платформы — desktop, mobile, консоли, web (WebGL-демо собрано без кастомного C#) (https://assetstore-fallback.unity.com/packages/tools/game-toolkits/naninovel-135453, https://naninovel.com/faq).
- Unity: Runtime Fee отменён; Personal бесплатен до **$200 000** выручки/финансирования в год, сплэш опционален; Pro $2 200/место/год (https://unity.com/blog/terms-update-runtime-fee-cancellation, https://unity.com/pricing-updates).
- Локализация: локаль = подпапка `Resources/Naninovel/Localization/<RFC5646>` (например `pt-BR`), утилита генерирует документы перевода; **managed text** для UI и имён персонажей; любые ресурсы (например фон с надписью) подменяются по локали; для языков нужен совместимый шрифт (раздел Fonts в гайде) (https://naninovel.com/guide/localization, https://naninovel.com/guide/managed-text, https://naninovel.com/faq).
- Мини-игры: всё, что умеет Unity; WebGL-билд тяжелее (⚠ размер не найден) и чувствителен к памяти на мобильных.
- Playgama: официальный Unity-пакет + Bridge WebGL Template (https://wiki.playgama.com/playgama/bridge-sdk/setup.md).
- Навыки: C#, Unity-пайплайн; для соло без Unity-опыта — самый высокий порог.

### C.3. Godot 4 + Dialogic 2

- Dialogic 2: официальные доки требуют **Godot 4.5+** (сторонние блоги пишут 4.3+ — доверять докам); переводы только через CSV: «Update CSV files» → «Collect translation» → файлы перевода Godot; каждому текстовому событию присваивается ключ `#id`; глоссарии имеют свои свойства перевода; поля с запятыми — в кавычках (https://docs.dialogic.pro/translation.html, https://docs.dialogic.pro/). Известные запросы: добавить в CSV колонку с именем таймлайна/говорящего (https://github.com/dialogic-godot/dialogic/issues/2712). ⚠ Статус релиза (stable/beta) поиском не уточнён.
- Godot-локализация: CSV в UTF-8 без BOM, импортированный CSV нужно вручную зарегистрировать в Project Settings → Localization; в 4.6 появились контексты перевода в CSV (https://docs.godotengine.org/en/latest/tutorials/i18n/localization_using_spreadsheets.html). Встроенная **псевдолокализация** (см. D.6).
- Web-экспорт: с 4.3 по умолчанию однопоточный экспорт, не требует COOP/COEP-заголовков и работает на macOS/iOS; многопоточный на Safari/iOS зависал; Safari имеет проблемы с WebGL 2.0 (https://docs.godotengine.org/es/4.5/tutorials/export/exporting_for_web.html, https://forum.godotengine.org/t/godot-4-3-will-finally-fix-web-builds-no-sharedarraybuffers-required/38885). Размер WASM: 27.1 МБ по умолчанию (4.1.2), 23.1 МБ после wasm-opt (https://github.com/JohannesDeml/Godot-Web-LoadingTest); ~19.5 МБ для пустой сцены (форум); в сжатом виде источники расходятся (5–9 МБ brotli/gzip против «35 МБ» в одном блоге); главная проблема — **время компиляции на мобильных**, а не скачивание (https://forum.godotengine.org/t/reduce-html5-loading-time/13709, https://ask.godotengine.org/89624/why-does-my-small-game-take-2-minutes-to-load-on-web).
- Мини-игры: нативно в Godot — максимальная гибкость, 2D-инструменты, анимации.
- Текст: динамические TTF-шрифты, кириллица/диакритика — без проблем; Playgama: официальный плагин для Godot 4 + HTML-шаблон `res://addons/playgama_bridge/template/index.html`, Bridge первым в AutoLoad (https://wiki.playgama.com/playgama/bridge-sdk/setup.md).
- Навыки: GDScript (проще C#), но ВН-функции (бэклог, скип прочитанного, откат, галерея) зависят от зрелости Dialogic и часто дописываются самостоятельно.

### C.4. Phaser / PixiJS (свой движок) + Ink / Yarn Spinner

- Лицензии: оба MIT, бесплатны для коммерции; Phaser — полный фреймворк (сцены, ввод, звук, физика), PixiJS — только рендер; Phaser 3 использует собственный рендерер, не PixiJS (https://toolradar.com/compare/pixijs-vs-phaser, https://phaser.io/trial). Phaser Editor — коммерческий ($120/год или разовая лицензия; есть ограниченный free-тир) (https://phaser.io/trial).
- Текст: кириллица — через web-шрифты (объект Text) с предзагрузкой шрифта, либо bitmap-шрифты, которые придётся перегенерировать под каждый язык и XML-карту (https://www.html5gamedevs.com/topic/28424-solved-loading-custom-fonts-and-displaying-cyrillicfrenchturkish-characters, https://phaser.discourse.group/t/bitmap-fonts-for-multi-language-game/3086).
- Ink/inkjs: «Ink не спроектирован под локализацию и привязку озвучки» — инструмент Wildwinter сканирует .ink, генерирует ID строк как теги и подгружает JSON/CSV перевода по тегу (https://wildwinter.medium.com/ink-localisation-tool-7e321f834794); inkjs обычно на мажорную версию отстаёт от основного ink (https://github.com/inkle/ink, https://deepwiki.com/y-lohse/inkjs/1-overview); демо интеграции с Phaser (https://github.com/lizgw/phaser-ink-demo); предостережение Black Market Protocol — каждая механика требовала ink-функцию + JS-мост + ручную синхронизацию состояния, в итоге логику перенесли в Phaser, оставив Ink для простых выборов (https://phaser.io/news/2025/10/from-inkjs-to-phaserjs). ⚠ Лицензия Ink (MIT) поиском не подтверждена.
- Yarn Spinner: line ID (`#line:`) на каждую реплику, «Add Line Tags to Scripts», экспорт «Strings and Metadata as CSV» (колонки id/text/file, lock для отслеживания изменений), для Godot — свой CSV, несовместимый с форматом Godot, импортировать как «Keep File» (https://docs.yarnspinner.dev/yarn-spinner-for-unity/assets-and-localization, https://docs.yarnspinner.dev/yarn-spinner-for-godot/godot-csharp/localization). ⚠ JS-рантайм Yarn и лицензия поиском не проверены.
- Articy:draft X: бесплатная версия с теми же функциями, лимит **700 объектов на проект**, коммерческое использование разрешено, экспорт есть, функции локализации (Project Languages, DeepL, экспорт/импорт, Localization View); платная ~€7.98/мес или €79.99/год (сторонний листинг) (https://www.articy.com/en/articydraft/free/, https://www.articy.com/en/out-now-articydraft-x/, https://us.fitgap.com/products/articy). Для ВН в 30–50 тыс. слов 700 объектов может не хватить (⚠ оценка).
- Playgama: JS Core подключается напрямую (`<script src="https://bridge.playgama.com/v2/stable/playgama-bridge.js">` или npm `@playgama/bridge`, плагин для Vite) (https://wiki.playgama.com/playgama/bridge-sdk/setup.md).
- Навыки: JS/TS и готовность написать всю ВН-обвязку самостоятельно.

### C.5. Monogatari, Tuesday JS, Visual Novel Maker, Twine

- **Monogatari** (web-движок в духе Ren'Py): TypeScript, браузерный бандл и ES-модуль, встроенная поддержка переводов с выбором языка в игре, сейв/загрузка, откат, автоплей, скип, лог, упаковка в Electron/мобильные (https://github.com/Monogatari/Monogatari, https://monogatari.io/, https://hyuchia.itch.io/monogatari). Риск: последний push в основной репозиторий — 2024-11-14 (снимок на март 2025), признаков активной разработки мало (https://awesome.ecosyste.ms/projects/github.com%2FMonogatari%2FMonogatari).
- **Tuesday JS**: бесплатный, Apache 2.0, редактор в браузере, сценарий в JSON, любые браузерные медиа (SVG, GIF, CSS), автономные версии для Android/desktop, таймер смены сцены, язык проекта по умолчанию и превью на выбранном языке; редактор локализован на русский и японский; репозиторий активен (push апрель 2026, 640 звёзд) (https://kirill-live.itch.io/tuesday, https://kirill-live.itch.io/tuesday-js/devlog/181289/tuesday-js-localization-preview, https://gittrend.io/repo/Kirilllive/tuesday-js). Мини-игры — только через собственный JS/HTML; Bridge подключить легко (это обычная web-страница).
- **Visual Novel Maker** (Degica): $59.99, частые скидки ~50 %; экспорт на Windows/macOS/Linux/Android/iOS/web заявлен в 2018 — свежих подтверждений статуса нет (https://gg.deals/ca/application/visual-novel-maker/, https://devforums.toucharcade.com/threads/visual-novel-maker-by-degica.322575/). Не рекомендуется из-за неясного статуса поддержки.
- **Twine**: ни один story format (Harlowe/SugarCube/Snowman) не имеет встроенной локализации истории; практика — дублировать пассажи по языкам или отдельные истории; переводчики предпочитают документы, команды строят свою систему (https://twinery.org/forum/discussion/5815/twine-2-0-localization). Для ВН со спрайтами и мини-играми не подходит, годится для быстрого прототипа ветвления.

## D. Локализация ВН: RU → EN / ES / PT

### D.1. Ключи vs исходный текст как ключ

- **Ren'Py**: реплики идентифицируются автоматически (лейбл + хэш текста — ⚠ детали по общим сведениям), строки интерфейса/меню — по исходному тексту в `translate strings`. Плюс: ничего не размечать руками. Минусы: правка исходной строки «отвязывает» перевод; одинаковые строки получают один перевод независимо от контекста (https://translations.launchpad.net/renpy-doc/trunk/+pots/translation/ja/+translate?start=36).
- **Yarn Spinner / Dialogic**: явные ID (`#line:abc123`, `#id`) — перевод переживает правки текста, CSV-экспорт удобен переводчикам; Yarn хранит `lock`-хэш, чтобы отмечать изменённые строки (https://docs.yarnspinner.dev/yarn-spinner-for-unity/assets-and-localization, https://docs.dialogic.pro/translation.html).
- **Ink**: без ID — нужен внешний инструмент, который прописывает ID как теги и подменяет текст по тегу (https://wildwinter.medium.com/ink-localisation-tool-7e321f834794).
- **Практика**: для UI, мини-игр, названий улик, подсказок — всегда ключи (`ui.menu.continue`, `mg.lockpick.hint_1`); для реплик — ID на строку; экспорт в одну таблицу (id, speaker, ru, en, es, pt-BR, context, max_len, screenshot) — такой «loc-kit» (строки + контекст + скриншоты + глоссарий + стайлгайд) ожидают переводчики (https://www.gamedeveloper.com/business/a-step-by-step-guide-to-game-localization, https://allcorrectgames.com/insights/localization-glossaries-what-they-are-and-why-they-matter).

### D.2. Расширение текста и запас места

| Пара | Расширение | Источник |
|---|---|---|
| EN → ES | +20–25 % (Eriksen) | Phrase (https://phrase.com/?p=103382) |
| EN → PT | +15–30 % | там же; Kwintessential +15/+30 % (https://www.kwintessential.co.uk/blog/translation-text-expansion-how-it-affects-design-2) |
| EN → ES/FR в играх | в среднем +20.3 %; PT-BR +13 %, PT-PT +14.3 % | исследование игровой локализации (пересказ, https://gameworldobserver.com/?p=231) |
| PT-BR vs EN | нужно на 25–30 % больше места | Localize Direct (https://localizedirect.com/posts/brazilian-portuguese-game-localization-factsheet/) |
| Короткие строки (1–4 символа) | до +100 %; > 50 символов — ~+10 % | Microsoft (https://learn.microsoft.com/zh-cn/previous-versions/visualstudio/visual-basic-6/aa716226(v=vs.60)) |
| Практика дизайна | закладывать буфер 30–40 % | Game Developer (https://gamedeveloper.com/game-platforms/localization-of-mobile-game-apps-from-english) |

⚠ Для русского исходника: русский текст в символах обычно длиннее английского, поэтому UI, свёрстанный под RU, чаще переживает EN без проблем, а ES/PT-BR оказываются сопоставимы с RU по длине — но кнопки/ярлыки всё равно проектируйте под +30–40 % и с автоподгонкой размера шрифта (по общим сведениям, поиском не проверено).

### D.3. Выбор варианта языка и размер рынка

- **PT-BR, не PT-PT**: Бразилия — один из крупнейших рынков, PT-BR — «пятый по популярности язык Steam» (вендорская оценка), английский в Бразилии знают слабо, бразильцы **отвергают европейский португальский** — «локализуйте под Бразилию или не локализуйте вовсе» (https://localizedirect.com/posts/brazilian-portuguese-game-localization-factsheet/, https://inlingogames.com/blog/localization-in-the-brazilian-market/). Доли Steam Hardware & Software Survey: PT-BR ≈ 4.26 % (дек. 2025) / 4.42 % (март 2026), PT-PT ≈ 0.2–0.4 % (https://www.quantumrun.com/consulting/steam-language-statistics/, https://store.steampowered.com/hwsurvey/Steam-Hardware-Software-Survey-Welcome-to-Steam).
- **Испанский**: Steam-доля «Spanish — Spain» ≈ 4.6–4.9 %, «Spanish — Latin America» ≈ 0.75–0.89 % (многие латиноамериканцы сидят на es-ES или английском интерфейсе). es-419 — «нейтральный латиноамериканский» (регистрация тега IANA: лексика/грамматика/орфография, приемлемые для большинства вариантов; https://ftp.iana.org/assignments/lang-tag-apps/es-419), у Google — с *tuteo* (tú, не vos) и согласованием с офисами в Мексике, Колумбии, Перу, Аргентине, Чили (https://multilingual.com/?p=123012). Для одного бюджета: заказать **нейтральный испанский** (без испанского сленга «vale/tío», без voseo) у переводчика, работающего и на ES, и на LATAM, и указать в Steam оба языка; при росте — отдельная es-ES редактура. ⚠ Сравнения затрат es-ES vs es-419 для студий поиском не найдено.
- **Русский** — третий язык Steam (≈ 9.1–9.3 %), что оправдывает качество RU-оригинала как отдельного рынка (https://www.quantumrun.com/consulting/steam-language-statistics/).
- **Playgama**: `platform.language` даёт только `es`/`pt` без региона → web-версия получает один вариант по умолчанию (PT-BR, нейтральный ES) + ручной переключатель с названиями языков на самих языках (чек-лист п. 2–3).

### D.6. Псевдолокализация и LQA

- **Псевдолокализация** (Godot встроена): удвоение гласных как имитация расширения, `expansion_ratio` (0.3 = +30 % «достаточно для большинства случаев»), акцентированные символы — выявляют непереведённые строки и отсутствующие глифы, `fake_bidi`, `override` звёздочками — находит текст вне системы локализации (https://docs.godotengine.org/en/stable/tutorials/i18n/pseudolocalization.html). В Ren'Py то же можно получить, сгенерировав «фейковый язык» скриптом поверх `tl/` (⚠ по общим сведениям); Unity Localization имеет псевдолокаль (⚠ не проверено).
- **LQA** = проверка носителями в контексте игры после перевода/редактуры: обрезания и переполнения, непереведённые строки, грамматика/терминология/тон, пол персонажей, форматы дат/валют, культурные отсылки, соответствие требованиям платформ; лучшие практики — письменное ТЗ для LQA, несколько раундов «нашли → исправили → перепроверили», разные люди на перевод и LQA, глоссарий и стайлгайд тестировщикам, тесты на реальных устройствах (https://localizedirect.com/posts/lqa-what-is-game-localization-testing, https://igda.org/news-archive/how-to-get-the-most-from-lqa-what-it-is-and-best-practices/, https://inlingogames.com/blog/what-is-localization-testing-and-why-is-it-important/, https://www.testroniclabs.com/localization-qa-2/).
- Специфика ВН: LQA должна проходить **все ветки и все концовки** на каждом языке и на каждой платформе (web portrait/landscape, desktop) — из-за ветвления цена LQA растёт быстрее, чем объём текста; русские бюро берут от 15 ₽ за строку (https://itrex.ru/services/website-i-soft/perevod-kompyuternyh-igr).

### D.8. AI-перевод с человеческой редактурой

- Исследования: постредактирование MT (MTPE) творческих игровых текстов переводчики считают **медленнее перевода с нуля** и ограничивающим творческую свободу (докторский проект MTxGames, https://koneensaatio.fi/?p=85555); эксперимент 2025 (12 фриланс-переводчиков, CTT workshop): опыт позитивный при переводе с нуля, негативный при «статичном» постредактировании сырого generic-MT, нейтрально-позитивный при «гибком» постредактировании доменно-адаптированного MT (https://aclanthology.org/2025.ctt-1.3.pdf); мультимодальность и креативность игровых текстов делают MT-подсказки контрпродуктивными (https://aclanthology.org/2024.eamt-2.24.pdf); мнение IGDA: постредактирование творческого MT занимает столько же времени и даёт хуже качество, проверяя грамматику, а не смысл/стиль (https://igda.org/news-archive/should-i-translate-my-game-using-machine-translation-or-ai/).
- Практический режим для соло: LLM — для черновиков **UI/технических строк**, для проверки терминологической консистентности и для подготовки глоссария/объяснений реалий переводчикам; реплики и наррация — переводчик-человек; LQA — носитель. Любой AI-текст в сборке (включая перевод) подпадает под обязательное раскрытие AI на Steam (раздел «AI Generated Content Disclosure» охватывает «art, sound, or text») и itch.io (тег с под-тегом Text & Dialog) — см. F.3.

### D.9. Русские реалии 90-х и сленг — как готовить переводчиков

- Исследование локализации Atomic Heart (90 терминов советских реалий): основные приёмы — калькирование, адаптация, транслитерация; требуется «баланс между аутентичностью и адаптацией для международной аудитории» (https://apni.ru/article/12178-osobennosti-peredachi-realij-i-imyon-sobstvennyh-v-lokalizacii-atomic-heart-na-anglijskom-yazyke).
- Сленг и юмор — транскреация, а не дословный перевод; сленг нельзя переводить «литературным языком»; глоссарий нужен, чтобы несколько переводчиков не расходились в терминах и именах (https://mylingvo.by/blog/lokalizaciya-igr-perevod-slenga, https://app2top.ru/columns/lokalizatsiya-igry-vzglyad-so-storony-perevodchika-82281.html).
- Основные потери — игра слов и «пасхалки»; для славянских языков помогает опора на уже сделанную локализацию на другой славянский язык (пример Kingdom Come, Ведьмак 3) (https://dtf.ru/ruvlad/1340919-long-eshe-odin-vzglyad-na-lokalizaciyu-videoigr).
- Рекомендуемый формат (синтез): **глоссарий реалий** (термин — буквальный смысл — коннотация — рекомендация: сохранить/транслитерировать/заменить аналогом — пример), **карточки персонажей для переводчиков** (возраст, регистр речи, обращение ты/вы, ругательства), **стайлгайд** (тон документалистики vs разговорная речь, обращение к игроку, формат дат/денег: рубли 90-х, «деноминация»), **комментарии к строкам** (`context`), **внутриигровой глоссарий/сноски** как самостоятельная механика документальной ВН (объяснение «ларёк», «челнок», «МММ» самим игроком через интерфейс «досье», а не сноской переводчика). Для ES/PT-BR — предупредить о различиях диалектов и попросить нейтральные варианты.

### D.10. Что ещё локализовать

- **Картинки с текстом** (вывески, документы, газеты 90-х — важны для документальности): Ren'Py подменяет файлы из `tl/<lang>/` автоматически, Naninovel — по локали, в Godot/Phaser — через словарь путей; альтернатива — рисовать текст поверх картинки движком, чтобы не множить ассеты (вывод по https://translations.launchpad.net/renpy-doc/trunk/+pots/translation/ja/+translate?start=49, https://naninovel.com/guide/localization).
- **Мини-игры**: все подсказки, названия предметов, тексты улик, кнопки — через ключи; раскладка пазлов не должна зависеть от длины слов (кроссворды/анаграммы — отдельная версия на язык).
- **Store-страницы, трейлеры, скриншоты, достижения, контент-дескрипторы** — на каждом языке (Steam показывает локализованные страницы по языку аккаунта — ⚠ по общим сведениям).
- **Числа и даты** — формат по локали (01.09.1994 / 09/01/1994 / 1 de setembro de 1994).

## E. Сценарное мастерство ВН

### E.1. Структуры ветвления (Sam Kabo Ashwell, «Standard Patterns in Choice-Based Games», 2015)

Источник: https://www.ifwiki.org/Standard_Patterns_in_Choice-Based_Games, зеркало https://gwern.net/doc/www/heterogenoustasks.wordpress.com/927e47e1d10dd1b25586b7dc48eaa3a5a4ab5cdd.html; также Emily Short «Small-Scale Structures in CYOA» (https://emshort.blog/2016/11/05/small-scale-structures-in-cyoa/).

| Паттерн | Суть | Стоимость контента | Для документальной ВН |
|---|---|---|---|
| Time cave | сильное ветвление, нет слияний, нет состояния | экспоненциальная | нет — не хватит слов и арта |
| Gauntlet | «длинная, а не широкая» линейная нить с короткими ответвлениями-смертями/возвратами | низкая | да, для «ошибочных» версий событий, быстро возвращающих к фактам |
| Branch and bottleneck | ветки расходятся и сходятся в «бутылочных горлышках», состояние (флаги) накапливается | умеренная | **основной выбор**: главы = горлышки, флаги = что игрок узнал/кому поверил |
| Quest / «fishbone» (i-docs) | линейный хребет, от которого отходят необязательные «кости» (интервью, документы) | низкая | да, для «расследования» между главами (https://directorsnotes.com/2016/08/08/interactive-documentary-guide/) |

### E.2. Значимые vs косметические выборы, флаги

- Таксономия разработчика: hard branching (не возвращается в основную линию), soft branching (возвращается), stat manipulation, world-building, «chitchat с нулевым влиянием» (https://itch.io/devlog/692035/meaningful-choices-while-reducing-branching.amp).
- Игроки видят «фальшивое» ветвление: если для продолжения нужно выбрать «правильный» вариант — выбор не значим (https://tildes.net/~games/15wq/visual_novels_and_adventure_games_with_choices_that_matter); «реальные» выборы — те, последствия которых игрок ощущает, а не просто другой абзац (https://forums.fuwanovel.moe/topic/8046-real-choices-in-a-vn/).
- Отложенные последствия через скрытые флаги/переменные отношений — сильный приём (Swan Song), а выборы, встроенные в диегетический интерфейс (телефон в Steins;Gate), ощущаются естественнее меню (https://tildes.net/~games/15wq/visual_novels_and_adventure_games_with_choices_that_matter).
- «Survive and advance»: вариант, завершающий игру, делает ставки осязаемыми (https://thenewleafjournal.com/survive-and-advance-visual-novel-choices/).
- Правило для соло: 3 типа выборов с явной пометкой в сценарии — **флаговые** (меняют состояние, окупаются позже), **ветвящие** (локальная сцена, слияние ≤ 300–500 слов), **тональные** (реплика/эмоция, 0 влияния) — и дисциплина «один hard-branch на главу максимум» (синтез Lemmasoft-совета про 2–3 ветки).

### E.3. Частота выборов, текст на экран, темп

- Эвристика: **≈ 50 реплик без выбора или смены сцены — вставьте простой выбор**; «стена текста» вызывает усталость (https://gamedesignskills.com/game-design/visual-novel/). Темп замедляют длинные куски текста между картинками и выборами, сложные предложения, паузы; ускоряют — меньше текста, частые визуальные смены и выборы; чередуйте быстрые и медленные сцены (https://neotegoelgames.wordpress.com/2021/02/15/how-to-use-choices-when-writing-visual-novels/, https://vnpaths.com/how-to-write-a-good-visual-novel-story/, https://lemmasoft.renai.us/forums/viewtopic.php?t=43292).
- **ADV vs NVL**: ADV — окно в нижней трети, 1–3 строки за клик, автор управляет темпом количеством текста на клик; NVL — текст на весь экран, ближе к странице книги; совет: ADV для диалоговых ВН, NVL для прозы, мелкий NVL-текст даёт «стены» (https://vnpaths.com/adv-vs-nvl/, https://dev.to/codefatale/adv-vs-nvl-style-in-renpy-2a8m, https://onedaytodisappear.itch.io/one-day-to-disappear/devlog/148931/adv-or-nvl-this-is-the-problem). Длина строки: исследования читаемости дают 45–75 символов, для новичков оптимум ~45 (https://en.wikipedia.org/wiki/Line_length). Практический ориентир (вывод): ADV-бокс 2–3 строки × 50–70 символов ≈ 120–200 символов на клик в RU; закладывать +30 % для ES/PT-BR или автоматический перенос на второй «клик».
- **Наррация vs диалог**: в ВН от первого лица «наррация» — это поток мыслей героя, отличие от реплики — только отсутствие имени; перемежайте длинные диалоги реакциями нарратора; не описывайте то, что уже видно на экране; избегайте длинных вступительных монологов над статичной картинкой — мысли должны раскрывать характер или «стрелять» позже (https://lemmasoft.renai.us/forums/viewtopic.php?p=23340, https://lemmasoft.renai.us/forums/viewtopic.php?p=511194, https://itch.io/t/2388254/how-do-you-write-a-visual-novel-effectively-and-in-an-engaging-way). Первое лицо даёт эмоцию, но мешает сообщать факты вне знания героя; третье — информативнее, но менее иммерсивно (https://lemmasoft.renai.us/forums/viewtopic.php?p=385966); второе лицо естественно для интерактивной прозы, не смешивайте лица (https://literarydevices.net/mastering-second-person-pov-writing-reading-tips/).
- Для документальной подачи это аргумент за **двухголосую структуру**: «документальный нарратор» (третье лицо, факты, даты — локализуется как нон-фикшн) + «свидетель» (первое лицо, сленг, эмоция — транскреация).

### E.4. Концовки

- Типовой паттерн: «истинная» концовка открывается после «хорошей»; преждевременная попытка даёт обычную/плохую концовку; истинная содержит полные раскрытия и эпилог (https://www.tvtropes.org/pmwiki/pmwiki.php/Main/BadEnd, https://forums.fuwanovel.moe/blogs/entry/3847-the-true-ending-%E2%80%93-an-anatomy-of-visual-novels).
- Плохие концовки — короткие необязательные ответвления; их легко сделать несправедливо-наказывающими; но они могут быть легитимными «что если» и ранними намёками (https://forums.fuwanovel.moe/blogs/entry/3711-the-bad-ending-%E2%80%93-an-anatomy-of-visual-novels, https://www.digitallydownloaded.net/2023/05/on-the-value-of-bad-endings-in-visual-novels.html).
- Советы: одна истинная концовка — нормальная практика, если плохие не ощущаются пустыми; **предупредите рано, что выборы влияют на исход**; дайте скип прочитанного текста для повторных прохождений (https://writing.codidact.com/q/25971). Единого правила порядка открытия нет (игроки делятся на «сначала плохие» и «сначала хорошие») (https://community.wanikani.com/t/visual-novel-book-club/57316?page=16).
- Для true-crime: концовки лучше строить не как «победа/поражение», а как **разные интерпретации дела** с итоговым «что известно на самом деле» (документальный эпилог) — чтобы ветвление не искажало факты (вывод автора на основе i-docs-принципов ниже).

### E.5. Как сделать документальную/true-crime наррацию интерактивной

- Принципы i-docs: «Story first, technology second» (Vassiliki Khonsari, 1979 Revolution); «интерактивность ради интерактивности скучна» — спрашивайте, что пользователь должен *делать*, чтобы почувствовать себя частью истории (Sandra Gaudenzi); ветвление быстро усложняется — структура «рыбья кость» (линейный хребет, из которого можно выходить и возвращаться) (https://directorsnotes.com/2016/08/08/interactive-documentary-guide/); исследовательские рамки — четыре режима интерактивности Gaudenzi, «12 тактик» нарративной когерентности i-docs (https://openrepository.aut.ac.nz/items/9a11170b-cf50-452c-9222-86353805e956, https://dei.fe.up.pt/phd-defense-in-digital-media-narrative-in-interactive-documentary-a-categorisation-framework/).
- **Attentat 1942** (Чехия): вымышленные персонажи, построенные на артефактах, свидетельствах, фото и кинохронике; «кинематографические» интервью, написанные историками, 8 выживших; мини-игры как передышки (расшифровать дневник, проложить маршрут побега, карты); за них дают «монеты», которыми оплачивается **повторный просмотр интервью** за пропущенной информацией; критика — «минимальная интерактивность, случайные мини-игры между Q&A» и ощущение «интерактивного документального фильма» (https://www.pcgamer.com/uk/attentat-1942-is-a-historically-accurate-game-about-the-nazi-occupation-of-czechoslovakia, https://gamecritics.com/andrazevedopedro/attentat-1942-second-opinion/, https://www.mobygames.com/game/98087). Урок: мини-игры должны быть **диегетичными** (связаны с действиями расследования), а не «паузами».
- **Her Story**: база из 7 полицейских интервью 1994 года, поиск по словам в видеоклипах, нелинейное восстановление дела (https://en.wikipedia.org/wiki/Her_Story_(video_game)). Для ВН: «архив» улик/расшифровок с поиском по ключевым словам — дешёвая в арте механика (текст + несколько портретов).
- **The Case of the Golden Idol**: улики собираются кликами по объектам/людям/документам; решение — **заполнение пропусков** в утверждении (убийца, жертва, орудие); игра почти не подсказывает; «свитки» подозреваемых и мотивов — памятка; дизайнеры стремились дать ощущение детектива через геймплей, а не «нарративную декорацию» (https://www.gamedeveloper.com/design/case-of-the-golden-idol, https://theescapeeffect.com/blog/the-case-of-the-golden-idol-review-a-brilliant-web-of-deduction). Для ВН: «дедукционная доска» как мини-игра между главами, проверяющая, понял ли игрок факты.
- **Этика true crime**: у реальных дел есть живые жертвы и семьи; игра о нераскрытом деле (Zodiac) критиковалась за «повышение знаменитости убийцы»; защитники указывают, что проблема — в гламуризации, а не в медиуме (https://ethics.org.au/where-are-the-victims-the-ethics-of-true-crime/, https://www.nme.com/gaming-features/video-games-about-real-world-crimes-are-a-step-too-far-2795845). Практики (синтез): опора на открытые источники с указанием их в игре («досье источников»), фикционализация/анонимизация частных лиц, фокус на жертвах и контексте эпохи, а не на «игре за убийцу», отдельное предупреждение о реальных событиях, отсутствие «очков» за насилие.
- Дешёвые для соло интерактивные формы документалистики: «досье» с открываемыми документами; выбор, **кому из свидетелей поверить** (флаги доверия → разные интерпретации); таймлайн, который игрок собирает; «монеты внимания» как в Attentat 1942; задания «найди несостыковку» между показаниями.

### E.6. Мини-игры в ВН — правила интеграции

- MIIP ч.3: механики должны развлекать, поддерживать повествование/атмосферу и разнообразить продвижение, **не растягивая время прохождения**, заданное сценарием (https://habr.com/ru/companies/miip/articles/840926/).
- Из критики Attentat 1942: «случайные» мини-игры воспринимаются как помеха; из Golden Idol: механика, повторяющая мысль детектива, — как суть.
- Рекомендации (синтез, ⚠ прямых источников про «skip mini-game» в выдаче не было): 3–6 типов мини-игр, каждая ≤ 2–3 минут, с ясной связью с сюжетом; возможность **пропустить или упростить** мини-игру (доступность и локализационный риск словесных пазлов); результат мини-игры — флаг/улика, а не «game over»; для web — управление и мышью, и тачем (требование Playgama п. 25, 31).

## F. Продакшн-пайплайн

### F.1. Именование ассетов и слои спрайтов

- Ren'Py выводит имена изображений из файлов и разбирает их как «тег + атрибуты» (`show eileen happy`), layeredimage собирает спрайт из групп (`always` — база, `group face` — эмоции, `group outfit`) с одним активным атрибутом на группу и `default`-значениями (https://gruntsteel.itch.io/distant-travels/devlog/452114/how-to-set-up-layeredimages-in-renpy-new-sprite-teaser, https://raspberrysoft.itch.io/indecent-wife-hana/devlog/353375/sprite-construction-in-renpy). Dialogic и Naninovel используют аналогичные «портреты/позы».
- Готовьте референс-лист персонажа (фронтальная фигура в полный рост, базовая одежда) и рисуйте все эмоции от него; экспорт — PNG с прозрачностью (https://vnpaths.com/how-to-create-visual-novel-sprites/, https://crystalgameworks.com/setting-up-visual-novel-sprites/); референс-разрешение фиксируется до начала арта (https://naninovel.com/guide/backgrounds).
- Схема имён (рекомендация автора отчёта; ⚠ общепринятого стандарта в выдаче не найдено): `bg_<локация>_<время>_<вариант>.webp` (`bg_kiosk_night_rain`), `ch_<имя>_<поза>_<слой>_<значение>.png` (`ch_lena_a_face_sad`), `cg_<глава>_<номер>_<вариант>.webp`, `ui_<экран>_<элемент>_<состояние>_<lang>.png`, `bgm_<настроение>_loop.ogg`, `sfx_<источник>_<действие>.ogg`, `vo_<lang>_<line_id>.ogg`; только латиница и подчёркивания (требование Playgama п. 18, лимит 240 символов пути на itch.io), версии не в имени файла, а в git/таблице.
- Список фонов/спрайтов/CG — одна таблица с колонками: id, глава/сцена, приоритет (P0 — без него нет прохождения, P1 — качество, P2 — nice-to-have), статус (placeholder/sketch/final), художник, дата, лицензия/источник (для архивных фото).

### F.3. AI-контент: правила платформ и качество

- **Steam**: обязательный ответ «да/нет» об использовании генеративного AI в игре, на странице и в маркетинге; раздел «AI Generated Content Disclosure» на странице магазина; две категории — заранее сгенерированный контент (арт, звук, **текст**) и генерируемый во время игры; инструменты-помощники (код-ассистенты) раскрывать не нужно; правила «существенно переписаны» в январе 2026; в H1 2025 ~8 000 релизов задекларировали AI против ~1 000 за весь 2024 (https://www.videogameschronicle.com/news/valve-has-significantly-rewritten-steams-rules-for-how-developers-much-disclose-ai-use, https://gamedeveloper.com/business/valve-tweaks-and-clarifies-ai-disclosure-rules-for-steam, https://tbreak.com/steam-ai-disclosure-policy-update-developers/). Точные формулировки — в Steamworks.
- **itch.io** (с ноября 2024): вопрос о генеративном AI на странице редактирования проекта; тег «AI Generated» / «No AI», под-теги Graphics, Sound, Text & Dialog, Code; не помеченные AI-проекты **не индексируются** на страницах браузинга; традиционный «игровой AI» и процедурная генерация исключены (https://mobilemarketingmagazine.com/itch-io-mandates-genai-disclosure-for-creators/, https://80.lv/articles/asset-creators-on-itch-io-now-have-to-disclose-the-use-of-generative-ai/, https://www.pcgamesinsider.biz/news/74828/devs-need-to-disclose-if-game-uses-genai-on-itchio/).
- **Playgama**: в чек-листе требований к AI-дисклеймеру нет; советует брать ассеты из CC0-библиотек (https://wiki.playgama.com/playgama/mcp/game-checklist.md).
- **Качество/консистентность**: ⚠ поиском не подтверждено (лимит), по общим сведениям — главная проблема AI-арта в ВН не «разрешено ли», а стилистическая и анатомическая консистентность персонажа в 6–12 эмоциях и нескольких позах; разумная практика — AI только для фонов-референсов/черновиков и для документальных текстур (бумага, фото-эффекты), финальные персонажи — у художника, и честный дисклеймер на обеих площадках. Для документального проекта дополнительно: не выдавать сгенерированные «архивные фото» за подлинные.

### F.4. Аудио

- Лицензии: CC0 — без атрибуции и для коммерции; CC-BY — с указанием автора (ведите файл credits с источником и лицензией каждого ассета); CC-BY-NC — нельзя в платной игре; CC-BY-SA/GPL — спорно для проприетарной игры; на Freesound лицензия задаётся **на каждый звук**, фильтруйте по CC0; OpenGameArt — проверяйте условия CC-BY; DRM/условия платформ могут конфликтовать с CC-BY (https://app.cinevva.com/guides/game-asset-licenses, https://community.gamedev.tv/t/solved-asking-about-copy-right/35543, https://opengameart.org/node/85600).
- Композитор «в целом не нужен» для бюджетной ВН — стоковая музыка дешевле/бесплатна (постмортем $38k, https://gamedevreport.beehiiv.com/p/how-to-spend-38k-on-a-visual-novel-and-ludum-dare-dying-in-2028); серия AI: The Somnium Files экономила, ставя историю и озвучку выше графики (https://automaton-media.com/en/news/amidst-rising-development-costs-the-ai-the-somnium-files-series-has-persevered-by-prioritizing-story-and-voice-acting-over-graphics-and-environments-producer-says/).
- Нарратор: ставки см. B.6; 4 языка озвучки ×4 стоимость — реалистично озвучивать только RU (и, возможно, EN), остальным давать субтитры; в Steam указывать «полная озвучка» только для языков, где она есть.
- Web: ogg/mp3, лупы с точными точками зацикливания; на Playgama — mute-кнопка, пауза звука при рекламе/уходе в фон, проверка `platform.isAudioEnabled` при старте (https://wiki.playgama.com/playgama/bridge-sdk/api/platform.md).

### F.5. Линтинг, QA и совместимость сейвов

- Ren'Py lint: статическая проверка неопределённых изображений, незагружаемых файлов, несуществующих лейблов, аудио (https://itch.io/post/8219406); Ren'Py 8.5 — фреймворк автотестов игр (https://lemmasoft.renai.us/forums/viewtopic.php?p=575901). Для Godot/JS — свои скрипты: обход всех веток скрипта, проверка, что каждый `id` есть во всех языках, что все ссылки на ассеты существуют, что нет «мёртвых» лейблов.
- Сейвы: типичный сбой Ren'Py после апдейта — «Couldn't find a place to stop rolling back. Perhaps the script changed in an incompatible way?»; сейвы, сделанные сразу после лейбла, частично работают (грузятся с начала лейбла), сделанные позже внутри сцены — падают; увеличение лимитов rollback в `options.rpy` убирает краш, но не откат к началу сцены; Python-словари в старых сейвах **не обновляются** автоматически — часть правок «тихо» не применяется, часть ломает загрузку (https://itch.io/post/8735386, https://itch.io/post/6743843, https://lemmasoft.renai.us/forums/viewtopic.php?p=504252). Практики (из форумных ответов + общие): не переименовывать/не удалять лейблы — только добавлять; новые переменные — через `default`; `renpy.retain_after_load()` для значений, переживающих загрузку; тест загрузки сейвов предыдущей версии перед каждым релизом; changelog с пометкой «ломает сейвы»; старую сборку оставлять доступной.
- Web/Playgama: сохранения только через `bridge.storage` (облако, где доступно), ключи пакетом, загрузка перед геймплеем, значения по умолчанию при `null`, сохранение при значимых событиях, а не каждый кадр; поворот экрана и реклама не должны сбрасывать прогресс (https://wiki.playgama.com/playgama/bridge-sdk/api/storage.md, checklist п. 4–7). Для ВН: сериализуйте не «позицию в скрипте» (ломается при правках), а `chapter + scene_id + line_index + флаги` с миграцией версий.
- QA-матрица: Playgama — 360×640, 390×844 portrait, 915×412 landscape, 1280×720, 2560×1440; тесты поворота, ресайза, долгих нажатий, жестов, ухода/возврата в браузер, открытия/закрытия рекламы; проверка опубликованной ссылки headless-браузером (checklist п. 33, 36).

**Steam** (из найденного + ⚠ общие сведения о процессе — проверять в Steamworks):

- ⚠ Общие сведения: сбор $100 за приложение, отдельные ревью страницы магазина и билда, страница «Coming Soon» заранее (вишлисты), таблица поддерживаемых языков (интерфейс / субтитры / озвучка) по каждому языку, проверка Steam Deck (управление геймпадом/тачпадом, читаемый шрифт на 7"), достижения, Steam Cloud для сейвов.

**itch.io**: лимиты HTML5 (F.2), AI-тег (F.3), отдельные билды Win/macOS/Linux + web, страница с указанием языков; «Too many files» — типичная ошибка Ren'Py-web при сборке не той кнопкой (https://itch.io/t/2109287/too-many-files-publishing-renpy-vn-to-play-in-browser).

**Playgama**: 36 пунктов чек-листа (https://wiki.playgama.com/playgama/mcp/game-checklist.md) — Bridge ≥ 2.2.0, `game_ready`, Storage, реклама в естественных паузах (между главами, перед мини-игрой — но никогда «под пальцем»), rewarded только как бонус (например, подсказка в дедукционной мини-игре), без внешних ссылок/аналитики/регистрации, 300 МБ, портрет/ландшафт, mute, прохождение до конца, тест опубликованной ссылки.

### F.7. Мобильный/тач UX для ВН

- Цели касания: Apple ≥ 44×44 pt, Material ≥ 48×48 dp, ≥ 8 dp между элементами; главное действие (следующая реплика) — крупнее минимума (https://blog.openreplay.com/improving-tap-targets-mobile-ux/, https://uxarmy.com/blog/mobile-ux-best-practices/).
- Tap-to-advance — базовая механика; свайпы (по текстбоксу — лог, длинный свайп — скрыть текст) — предложения сообщества, не стандарт (https://vnpaths.com/how-to-play-visual-novels/, https://lemmasoft.renai.us/forums/viewtopic.php?p=324317).
- Тестируйте «неожиданное» поведение: скрытый UI, быстрый меню поверх катсцен, пропуск до конца озвучки (https://arimiadev.com/i-played-over-100-visual-novels-in-one-month-and-heres-my-advice-to-devs/).
- Playgama: долгое нажатие не должно выделять текст/вызывать контекстное меню (CSS `user-select: none`, `touch-callout: none` — ⚠ техника по общим сведениям), полноэкранный режим, клавиатура при тапе в поле ввода, элементы не деформируются при смене ориентации (checklist п. 25–26). ⚠ Safe area (вырезы, индикатор «домой») — поиском не покрыто; по общим сведениям — CSS `env(safe-area-inset-*)` и отступы быстрого меню от краёв.
- Портрет для ВН на телефоне: текстбокс внизу под большим пальцем, спрайты по центру, быстрый меню — в нижнем углу; ландшафт — классическая раскладка. Playgama требует проверить обе ориентации, если обе заявлены.

## H. Сводный план для вашего проекта (соло, RU-источник, 4 языка, Playgama + Steam/itch)

1. **Неделя 0–2**: концепт, 4 документа MIIP, схема «branch-and-bottleneck» с главами-горлышками, список мини-игр (3–6, диегетичных, ≤ 3 мин, пропускаемых), этическое ТЗ для true crime (источники, анонимизация).
2. **Выбор движка до сценария в движке**: Godot 4 + Dialogic 2 (или Unity + Naninovel) при приоритете Playgama; Ren'Py — при приоритете Steam/itch. Собрать и выложить в песочницу Playgama «вертикальный срез» (1 глава + 1 мини-игра + Bridge Storage/реклама/`platform.language`) **до** заказа арта.
3. **Сценарий**: цель 30–50 тыс. слов на одно прохождение (3–5 ч), ветвление ≤ ×1.5, выбор не реже чем раз в ~50 реплик, два голоса (документальный нарратор + свидетель), ID на каждую строку, UI — ключи.
4. **Арт**: 12–25 фонов (+ варианты), 4–8 персонажей × 6–12 эмоций послойно, 8–20 CG; бюджет по ставкам B.4; время ≈ 120–160 человеко-дней художника; документальные материалы — с лицензией.
5. **Локализация после script lock**: RU→EN (сильный переводчик + глоссарий реалий), затем EN→ES (нейтральный) и EN→PT-BR носителями с доступом к RU-консультации; псевдолокализация и буфер +30–40 % в UI; LQA по всем веткам на web (portrait/landscape) и desktop; AI — только черновики UI и как QA, с дисклеймером.
6. **Релиз**: чек-листы F.6; сейвы с версионированием; AI-дисклеймеры; контент-предупреждения; языки в Steam — интерфейс+субтитры для 4 языков, озвучка только там, где есть.
