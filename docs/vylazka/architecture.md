# Архитектура «Untitled Session»: что есть и куда расти

Владелец сказал: «проект будет большим». В пакете `vylazka/` около 24 тысяч строк, три мира из восьми,
и всё это выросло за два дня быстрых итераций. Этот документ — разбор нынешнего устройства (сделан
отдельным агентом-архитектором 15.11.2026 по коду, проверен основной моделью) и путь к структуре,
которая выдержит восемь вылазок, коллаж кусков пространства и параллельную работу многих агентов.

Выбор стека — отдельно, `stack.md`. Замысел — `untitled_session.md`, числа — `design.md`.

## 1. Как устроено сейчас

```
core (rng, i18n, save) ← gen (layout) ← world (kit, shell, props*, furnish*, level_build, pockets, flat, points)
                                         ↑                    ↑
                    systems (session, things, jumps, echo, cell_lights, director, anomalies) + swarm
                                         ↑
           game.ts (оркестратор)  →  render/renderer.ts (three.js)  ←  app.ts → debug/debug.ts
```

- `gen`, `world` и `systems` обходятся без three.js; three.js есть только в `render/` (два файла).
- **От сида до кадра.** `generateLayout(seed, rank, world)` → `buildLevel()` → `BuiltLevel` (куски
  геометрии, преграды, места для вещей, граф ходьбы) → `game.loadLevel()` → `renderer.setWorld()`.
  Каждый кадр `game.draw()` собирает `FrameView` (около 45 полей) → `renderer.render()` (около десяти
  проходов подряд).
- **Состояние** почти всё лежит в `Game` (около 70 полей); отдельно — `Session`, `Things`, рендер и `App`.

## 2. Что мешает расти

1. **Мир размазан по коду.** Различия трёх миров разбросаны примерно по десяти файлам: соль сида и
   квоты (`gen/layout.ts`), стиль стен (`level_build.ts`), обстановка (`furnish*.ts`), окружение
   (`pockets.ts`), воспоминания (`session.ts`), вещи и доля особых комнат (`game.ts`), разбор адреса
   (`app.ts`), сейв. Четвёртый мир — правки в десяти файлах, включая два самых горячих: параллельные
   агенты будут сталкиваться.
2. **У мебели не было своей идентичности.** Предмет писал себя прямо в общую сетку помещения и сам
   ставил преграды; после сборки его как объекта не существовало. «Вещь меняется» было сделано тремя
   несвязанными способами: вещи сна, варианты комнат, перестановка в темноте. (Первый шаг к единой
   вещи сделан — см. §5, шаг 8.)
3. **Данные и код перемешаны в реквизите.** Запись предмета хранит и габариты, и код сборки; реестр
   работает как библиотека помощников; в `props_more.ts` 1935 строк, около сорока строк на предмет.
4. **`Game` — объект, который знает всё** (1572 строки): расстановка вещей, особые комнаты, логика
   каждого карманного пространства, рой, эхо, призрак, строб, сборка кадра. `loadLevel` вручную
   обнуляет около тридцати полей: забытая строка — утечка состояния между сессиями.
5. **Рендер — монолит.** Порядок проходов зашит в один метод, материалы создаются в конструкторе,
   шейдер мира — около 390 строк с веткой `#ifdef`. Новый способ изображения (скан, проволока, фото)
   — правка двух файлов по полторы тысячи строк.
6. **Скрытые связи**: обстановка и симуляция света должны совпасть по хешу; рендер тянет константы
   из систем; звук импортирует типы из `game.ts`; размер текстуры света молча равен размеру сетки
   уровня.
7. **Облако точек — не сплаты.** Точки сеются по треугольникам и берут цвет поверхности под собой;
   для скана-сплата источника нет.
8. **Тесты и параллельная работа.** Смоук — один файл на две тысячи строк; главный тест сессии —
   1300 строк на весь `Game`; отладочный интерфейс читает внутренности `Game` напрямую.

## 3. Что не трогать

- Целочисленный ГСЧ и своя соль сида у каждой подсистемы: один сид — один мир.
- `gen`, `world`, `systems` без three.js: тесты идут в node, переезд в Worker почти бесплатный.
- Фиксированный шаг 1/60 и пошаговая отладка (`__vz.freeze/step`).
- Один материал, атлас matcap, номер материала в вершине; помещение — один вызов отрисовки.
- `Env` и `PocketSpace` — готовые прообразы «окружения» и «куска пространства».
- `Things` как чистая логика; подставной рендер в тестах — готовый порт рендера.

## 4. Целевая структура

```
content/   данные: sorties/<id>.ts, recipes/<род>/*.ts, виды, окружения, сюжет        (без логики)
gen/       план по сиду (граф помещений и кусков)                                     (чистый TS)
assemble/  план + рецепты → куски, объекты, граф ходьбы                               (чистый TS, Worker)
sim/       ядро игры + features/* (рой, эхо, карманы, свет мира…)                     (чистый TS)
contracts/ порт рендера, события, кадр по секциям
present/   three.js: рендереры видов, проходы списком
app/       экраны, ввод, площадка; отладка — через contracts
```

Граница «данные / код»: **данные** — мир, квоты, стили, окружение, задания и их порядок, пулы вещей,
рецепты простых вещей, список ассетов; **код** — интерпретаторы рецептов, генераторы и поведения по
имени, рендереры видов, системы.

**Вылазка как данные.** Одна запись заменяет все `if (world === …)`:

```ts
export interface SortieDef {
  id: SortieId;                         // ключ реестра, а не перечисление в layout.ts
  plan: { generator: string; quotas: Quota[]; edge: EdgeKind; loops: number };
  rooms: Record<string, RoomRecipe>;    // стиль стен + правила обстановки
  env: Env;
  light: { behavior: string; params?: object };   // 'flashlight' | 'sensor' | 'streetlamps' | …
  objects: { pools: Record<string, ObjectPick[]>; flatShare: number };
  story: StoryStep[];                   // пять заданий по порядку: вещь + ключ строки
  pockets: PocketKind[];
  assets?: string[];                    // пакеты моделей, сканов, картинок — грузятся по вылазке
}
```

**Кусок пространства и его вид** — то, что владелец назвал коллажем: уровень склеен из кусков, у
каждого свой способ изображения и свои швы с соседями.

```ts
export type Look =
  | { kind: 'kit'; mesh: MeshData }                        // болванки из кода (нынешний путь)
  | { kind: 'model'; asset: string }                       // готовая модель или скан-сетка
  | { kind: 'splat'; asset: string; density?: number }     // точки с собственным цветом
  | { kind: 'image'; cell: number; w: number; h: number; washable: boolean }   // экран, проекция
  | { kind: 'wire'; mesh: MeshData }
  | { kind: 'photo'; mesh: MeshData; texture: string };
export interface Piece {
  id: string; bounds: Aabb; tier: number;
  looks: Look[]; env?: Partial<Env>;                       // свой свет и туман внутри куска
  colliders: Aabb[]; seams: Seam[];
}
export interface Seam { a: string; b: string; at: Vec3; n: Vec3; w: number; h: number; style: 'frame' | 'fog' | 'redline' | 'cut' }
```

**Единая вещь** — всё, что можно растворить и вернуть: и мебель, и вещи сна.

```ts
export interface WorldObject {
  id: number; recipe: string; seed: number;
  pos: Vec3; yaw: number; mount: Mount;
  state: 'present' | 'dissolving' | 'absent' | 'returning';
  baked?: boolean;                      // лежит в общей сетке помещения, гасится по номеру объекта
  behavior?: string;                    // 'memory' | 'dream' | 'static'
}
```

**Рецепты в духе .kkrieger** (`_research/kkrieger.md`): простая вещь — список операций, сложная — имя
генератора.

```ts
export interface Recipe {
  w: number; d: number; h: number; mount: Mount; tags: string[];
  solid?: [Vec3, Vec3][];               // преграды — данные, а не побочный эффект сборки
  ops?: Op[];                           // box / cyl / sheet / lathe / sweep / repeat / mirror
  build?: string;                       // имя генератора в коде
}
```

**Проходы рендера списком** и **возможности игры как модули** (`Feature`: рой, эхо, карманы, свет
мира — каждая создаёт своё состояние заново при загрузке уровня, без ручных обнулений).

## 5. Путь

| # | Шаг | Как проверить | Объём | Параллельно |
|---|---|---|---|---|
| 1 | **Страховочная сеть**: «золотые» хеши плана, сеток, преград и расстановки вещей — 3 мира × 3 сида | хеши стабильны на нынешнем коде | S | нет: основа для остального |
| 2 | **`contracts/`**: порт рендера из подставного рендера тестов, события, общие константы | типы, тесты | S | да |
| 3 | **Разрезать смоук** на `e2e/scenarios/*.mjs`; тест сессии — по темам | тот же зелёный набор | M | да |
| 4 | **`SortieDef`**: все различия миров — в `content/sorties/*.ts` | золотые хеши совпадают побайтно | M | нет; дальше каждый мир — свой файл |
| 5 | **Разгрузить `Game`**: расстановка вещей и особые комнаты — чистые функции; карманы, рой, эхо, призрак — модули | золотые тесты, смоук | M–L | да, по модулю на агента |
| 6 | **Проходы списком**, материалы — внутри своих проходов | кадры с фиксированных точек с допуском | M | да |
| 7 | **Реквизит по полкам**: помощники отдельно, предметы — по 150–300 строк на файл, преграды — данными | золотые хеши, кадры витрины | M | да, по роду на агента |
| 8 | **Единая вещь**: номер объекта в вершине + текстура состояний; вещи сна и мебель — один тип | вызовов отрисовки столько же; «коснулся → растворилось → свет погас и зажёгся → вернулось» | L | нет (ядро) |
| 9 | **Куски и виды**: помещения и карманы — `Piece`, у каждого вида свой рендерер | золотые тесты, смоук | M | после 8 |
| 10 | **Новые виды**: модель/скан, точки с цветом, проволока; ассеты грузятся по вылазке | размер сборки, кадр на слабом качестве | M каждый | да |
| 11 | **Рецепты-операции**: интерпретатор, пилот на десяти простых предметах | хеши сеток, кадры витрины | M | да |
| 12 | **Генерация в Worker; порядок заданий из `SortieDef.story`** | смоук | M | да |

Шаги 1–3 дешёвые и снимают риск со всего остального; 4 открывает работу над мирами по отдельным
файлам; 5–7 убирают главные узлы столкновений; 8–9 — суть требований «всё иллюзорно» и «коллаж».

**Что уже сделано из шага 8** (15.11.2026, по прямому указанию владельца — правило «коснулся —
растворилось»): у вершины есть номер объекта, у рендера — текстура состояний, мебель растворяется и
возвращается без отдельных сеток (`design.md`, §6, «Иллюзорные вещи»). Вещи сна и мебель пока два
разных типа под общим правилом — слить их в один предстоит.

## 6. Решения по развилкам

| Развилка | Решение | Почему |
|---|---|---|
| Как растворять запечённую мебель | номер объекта в вершине + текстура состояний | отдельная сетка на каждый предмет умножила бы вызовы отрисовки на телефоне |
| Формат данных мира | TypeScript-константы с проверкой типов; бинарные файлы — только для ассетов из скриптов | типы, проверка при сборке, не нужен загрузчик |
| Сканы-сплаты | свои точки с собственным цветом, а не настоящие гауссовы сплаты | вид игры уже такой; посильно WebGL2 на слабом телефоне |
| Швы коллажа | стык по проёму клетки (ребро сетки 3 м) с набором стилей шва | генератор, преграды и ходьба остаются простыми |
| Размер | бюджет килобайт на вылазку, ассеты грузятся по вылазке; сборка одним файлом остаётся «кодовой» | порталы считают размер и время загрузки |
| Где живут поведения света и пространств | в данных — имя и параметры, код — в реестре модулей | новый мир — файл данных и, если надо, один модуль |

Открыто для владельца: порядок — сначала навести порядок (шаги 1–4, около двух пачек без новых
картинок) или продолжать добавлять видимое и платить за это позже. Рекомендация основной модели:
шаги 1 и 4 сделать до четвёртого мира, остальное — между пачками с видимым результатом.
