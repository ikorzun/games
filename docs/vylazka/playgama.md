# Untitled Session на Playgama

Сборка для Playgama: Bridge SDK, разметка аналитики, крючок рекламы (выключен), проверенный архив.
Требования прочитаны 17.11.2026 с живой вики через коннектор Playgama: чеклист (Game Requirements),
обязательные шаги Bridge SDK (API → Required steps), руководство по телеметрии, гайды. В кабинете Playgama
ничего не создано и не загружено: это решение партнёра («Только собрать»).

## Как собрать

```bash
cd vylazka
npm install                    # @playgama/bridge 2.4.3 — последняя версия на 17.11.2026
npm run typecheck && npm test
npm run build:playgama         # dist-playgama/ и проверка архива (scripts/check_dist.mjs)
node e2e/smoke.mjs --dist dist-playgama --only bridge --no-shots   # Bridge: язык, game_ready, пауза, аналитика
cd dist-playgama && zip -q -r -X ../untitled_session_playgama.zip .   # index.html — в корне архива
```

В архиве: `index.html`, `playgama-bridge.js` (SDK, первый скрипт в `<head>`), `playgama-bridge-config.json`,
`assets/`, `audio/`. Сборка 17.11: 124 файла, 9,9 МБ (в zip 8,4 МБ), самый большой файл — код игры, 1,65 МБ.

Как игра говорит с площадкой:

- **Порядок загрузки.** Сначала SDK и `bridge.initialize()`, потом код игры: `index.html` подключает его только
  после инициализации (`vite.config.ts`, `bridgeFirstPlugin`). Вне Playgama сборка прежняя.
- **Конфиг.** `vylazka/playgama-bridge-config.json` кладётся рядом с `index.html`. Сейчас это `{}`: обязательных полей
  нет. Файл из редактора конфига Playgama можно положить на его место; сборка падает, если это не JSON-объект.
- **Язык.** На Playgama — `bridge.platform.language`: русский, если площадка говорит `ru`, испанский — если `es` (любой вариант:
  es-419, es-MX), иначе английский.
  Вне Playgama — английский. Язык, выбранный игроком в настройках, хранится в профиле и важнее обоих.
- **Сохранения.** Один ключ `profile` в `bridge.storage`: одно чтение на старте, запись по событиям. Строка
  проверки `#diag` на Playgama между запусками не помнится: мимо Bridge игра ничего не пишет.
- **Пауза и звук.** Начальные `isPaused` и `isAudioEnabled` применяются сразу, дальше — события `PAUSE_STATE_CHANGED`
  и `AUDIO_STATE_CHANGED` (Bridge складывает в них скрытую вкладку, рекламу и паузу площадки). Открытая
  реклама — отдельная причина паузы `ad`, в том числе если она открылась ещё до старта игры.
- **game_ready** — один раз, когда показана заставка и её можно нажать.
- **Версия сборки** `0.1.0+ГГГГММДД.ччмм` уходит в Bridge (`bridge.gameVersion`): площадка пишет её в каждое
  событие, и сводки можно сравнивать от сборки к сборке.

## События

Bridge сам пишет в аналитику инициализацию, `game_ready` со временем загрузки (`time_s`), начало и конец
визита, рекламу с местом показа (`advertisement_interstitial_*`) и lifecycle-сообщения. Игра этого не
дублирует. План событий — `src/analytics/events.ts`, проверки — `tests/analytics.test.ts`.

Lifecycle-сообщения площадки (`platform.sendMessage`; у них только `world` и `level`):

| Сообщение | Когда | Данные |
|---|---|---|
| `game_ready` | заставка показана, её можно нажать | — |
| `level_started` | началась сессия | `world` — место, `level` — номер сессии (до 99) |
| `level_completed` | сессия кончилась, игрок в лимбо | `world`, `level` |
| `level_paused` / `level_resumed` | пауза во время сессии (P, мышь отпущена, вкладка скрыта, реклама) и возврат | `world`, `level` |

События игры (`bridge.analytics.send`):

| Событие | Когда | Данные |
|---|---|---|
| `first_input` | первое нажатие после `game_ready` | `ms` (с шагом 100 мс), `input`: mouse, touch, pen, key |
| `progression_started` | началась сессия | `step_id` — место, `step_index` — номер сессии, `stage` 0–4, `lap`, `mode`: loop или scenes |
| `progression_completed` | лимбо | то же и `duration_s` (без пауз), `memories`, `caught`, `jumps`, `pockets` |
| `memory_recalled` | вспомнено воспоминание | `memory_id`, `tier`, `k` (какое по счёту в сессии), `world`, `lap`, `stage`, `t_s` |
| `caught` | Осыпь поймала | `world`, `lap`, `stage`, `k` (сколько уже вспомнено), `t_s` |
| `jump` | скачок, кроме смены сессий и поимки | `cause`, `to` (карман или `elsewhere`), `world` |
| `pocket_used` | дело в кармане | `kind`: void, meadow, dollhouse; `what`: map, next, remind, replay |
| `place_erased` | место стёрто до конца — миг | `world`, `laps`, `n` |
| `hint_shown` | подсказка обучения (`dark` — 45 с без вещи в луче, игрок застрял) | `id`, `world`, `t_s` |
| `settings_changed` | игрок сменил настройку; качество — и само, когда кадров мало | `setting`: sound, lang, sens, bright, flash, place, quality; `value`; `auto` |
| `webgl_status` | WebGL2 нет на старте, контекст потерян, восстановлен | `status`: unavailable, lost, restored |
| `performance_sample` | раз в ~30 с игры; остаток не короче 10 с — в конце сессии | поля контракта Playgama, счётчики ошибок за окно, `build_version`, `quality` |

`performance_sample` считает кадры только в игре: заставка, лимбо, пауза и скрытая вкладка в окно не входят.

Чего в событиях нет: личных данных, сида, текста, адресов, сообщений ошибок и стеков. Значения — числа, флаги
и слова из конечных списков; покадровых событий нет. Отдельного события лимбо нет: это тот же миг, что
`progression_completed`.

## Реклама

**Рекламы нет по решению партнёра** (квиз 17.11: «Пока без рекламы»). `showInterstitial` не вызывается нигде,
наградной рекламы нет.

Крючок оставлен выключенным: `src/platform/ads.ts`, `ADS.interstitial = false`. Если его включат:

- реклама просится только в лимбо между сессиями, через 1,5 с после его начала; если место стёрто — после мига;
- место показа — `limbo`; под этим id Bridge пишет свою аналитику рекламы;
- следующая сессия ждёт ответа на просьбу о рекламе: долго грузившаяся реклама не откроется посреди игры;
- пока реклама открыта, игра стоит и молчит: причина паузы `ad` и события Bridge;
- реклама не загрузилась — игра идёт дальше.

В брифе было ещё «не после первой сессии» и «не чаще раза в 3 минуты». Своих таймеров и счётчиков в игре нет:
Bridge запрещает их (обязательный шаг 7, гайд Monetization → Best practices). Задержку перед первой рекламой и
промежуток между ними (обычно 120–240 с) задаёт площадка. Сессия длится не меньше 5 минут, так что лимбо и так
приходит не чаще раза в 5 минут. В конфиге есть `minimumDelayBetweenInterstitial` и `initialInterstitialDelay`,
но вики просит оставлять значения площадки.

Без межстраничной рекламы игра не выполняет пункт 2.1.2 и шаг 7: модерация, скорее всего, её вернёт.
Включить рекламу — одна строка (`ADS.interstitial = true`), но решает партнёр.

## Риски

1. **Язык площадки.** Раньше игра на Playgama всегда начинала на английском (решение партнёра), теперь — на
   языке площадки, если знает его. Этого требуют шаг 3 и пункт 3.4.2. Вернуть прежнее — одна строка в
   `app.ts` (`init`), но тогда пункт 3.4.2 не выполнен.
2. **Реклама выключена** — пункт 2.1.2.
3. **Надписи на стенах убежища русские.** Модерация может счесть их непереведённым текстом (3.4.3).
4. **Плакаты гражданской обороны** (ядерный удар, дозиметрия, убежище), карта страны, которой больше нет,
   облигации и нотгельд 1917–1929 годов могут счесть отсылкой к войне или политике (4.1.2).
5. **Загрузка стала последовательной:** код игры (0,5 МБ в gzip) качается после инициализации Bridge. На
   медленной сети первый кадр придёт позже.
6. **Два стика на телефоне** против «одной рукой» (1.6.6) — уточнять у модерации.
7. **Bridge 2.4.3 вышел 17.11.** После слияния нужен `npm install`: в основном checkout стоит 2.4.2.

## Что может только партнёр (в кабинете Playgama)

1. Создать игру в кабинете: название **Untitled Session**, категория, языки — **en и ru** (es — когда носитель вычитает перевод: квиз 21.11), устройства и ориентация.
2. Загрузить архив `untitled_session_playgama.zip`. После загрузки можно прогнать архив инструментом проверки Playgama.
3. Обложка, иконка, скриншоты, описание на английском и русском.
4. Решить про рекламу (пункт 2.1.2).
5. Отправить игру на модерацию и решить про публикацию.
