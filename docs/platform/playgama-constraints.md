# Ограничения платформы Playgama (веб-дистрибуция)

Источник: официальный чеклист Playgama и документация Bridge SDK, прочитанные через
консоль разработчика 2026-10-10 (`wiki.playgama.com/playgama/mcp/game-checklist`,
`wiki.playgama.com/playgama/bridge-sdk/api/platform`, `.../api/storage`).

Эти требования зафиксированы как **жёсткие ограничения архитектуры**, потому что
у студии уже есть три HTML5-игры на Playgama и веб — основной канал дистрибуции.
Steam/itch/мобильные сборки — вторичные цели и не должны ломать веб-сборку.

## Что это значит для новеллы

| Требование платформы | Следствие для архитектуры |
|---|---|
| Архив ≤ 300 МБ, `index.html` в корне, только латиница в именах файлов | Бюджет ассетов на эпизод; имена файлов и ключей — ASCII (`ep01_murylev`, не «Мурылёв»). Эпизоды грузятся по требованию (chapter-based loading), а не одним пакетом. |
| Английский обязателен как язык по умолчанию и fallback | Пайплайн локализации: `en` — обязательный полный перевод до релиза любого эпизода; `ru` — язык-источник сценария; `es`, `pt` — полные переводы. При отсутствии строки — fallback на `en`, затем на `ru`. |
| Автовыбор языка по `bridge.platform.language` (ISO 639-1: `ru`, `en`, …) | Поддерживаемые коды: `ru`, `en`, `es`, `pt`. Любой другой → `en`. Ручной выбор языка — иконкой, названия языков на самих языках (Русский / English / Español / Português). |
| Сохранения только через `bridge.storage` (не `localStorage`), одним вызовом с массивом ключей | Своя система сейвов поверх абстракции `SaveProvider`: ключи `profile`, `progress`, `settings`, `archive` сохраняются пакетно. Сейв — чистый JSON (позиция в графе сцен + переменные), без ссылок на объекты движка. |
| Прогресс должен восстанавливаться после перезагрузки, поворота экрана, рекламы | Автосейв на границах блоков и после каждого выбора; мини-игра сохраняет своё состояние при паузе. |
| Пауза и звук: подписка на `PAUSE_STATE_CHANGED`, `AUDIO_STATE_CHANGED`; проверка `isAudioEnabled` на старте | Единый `Lifecycle`-модуль: пауза таймеров мини-игр, авто-режима текста, музыки. |
| `platform.sendMessage('game_ready')` только после первого играбельного кадра | Загрузчик: шрифты + UI + первый блок эпизода, затем `game_ready`. |
| Минимум один формат рекламы (interstitial и/или rewarded), только через Bridge | Interstitial — только на границах блоков (`title_card`, конец акта, конец эпизода). Rewarded — опционально: «подсказка в мини-игре», «открыть материал архива». Никогда не в середине диалога. |
| Нет внешних ресурсов, нет внешней аналитики, нет внешних ссылок, нет логина | Все шрифты/аудио внутри сборки. Аналитика только `bridge.analytics.send` (Bridge ≥ 2.3.0). Титры без ссылок на соцсети. |
| Вёрстка держится при любых размерах, портрет и ландшафт, desktop ≤ 2:1 | UI новеллы — safe-area layout: текстовое окно и выборы адаптивны; спрайты кадрируются по высоте. Матрица проверки: 360×640, 390×844, 915×412, 1280×720, 2560×1440. |
| Тач: без выделения текста и контекстного меню при long-press; оба типа управления | `user-select: none` на игровом поле; клик/тап/пробел/Enter — продвижение текста; мини-игры с touch-паритетом. |
| Кнопка mute обязательна при наличии звука | В быстром меню новеллы: Mute, Auto, Skip, Log, Save, Settings. |
| Шрифты читаемы на всех размерах | Минимальный кегль основного текста ≥ 16 CSS px на мобильном; проверка кириллицы и диакритики es/pt. |
| Проверка опубликованной ссылки в Playwright | В CI: smoke-тест сборки headless-браузером (загрузка, `game_ready`, первый выбор, сейв/лоад, смена языка). |

## Что это значит для «Вылазки»

Вторая игра (`vylazka/`) подчиняется тем же правилам. Как они выполнены — и что осталось непроверенным:

| Требование платформы | Как выполнено |
|---|---|
| Архив ≤ 300 МБ, `index.html` в корне, латиница в именах | `vylazka/scripts/check_dist.mjs` на каждой сборке. Ядро — около 1 МБ; уровни процедурные, графика рисуется кодом, тяжёлым будет только звук (около 2,5 МБ). |
| Английский обязателен | Локали `ru` (источник) и `en`; `es` и `pt` — после заморозки текста. Надписи на стенах убежища остаются русскими: это часть сеттинга. |
| Язык по `bridge.platform.language` | `ru` и `en`; всё остальное → `en`. |
| Сохранения только через `bridge.storage`, одним вызовом | Ключи `profile` и `run` пишутся пакетно и только по событиям: находка, цель, смена яруса, обвал, пауза, конец вылазки. Уровень не хранится — восстанавливается по сиду и версии генератора. |
| Прогресс переживает перезагрузку и рекламу | Прерванная вылазка продолжается с карточки задания: то же убежище, собранное и снятое на месте, заряд и время те же. |
| Пауза и звук: `PAUSE_STATE_CHANGED`, `AUDIO_STATE_CHANGED`, `isAudioEnabled` | Единый `Lifecycle`: пауза площадки, реклама и скрытая вкладка останавливают симуляцию и звук целиком; запрет звука площадкой глушит микшер. |
| `game_ready` после первого играбельного кадра | После прогрева шейдеров и первого кадра убежища; смоук проверяет, что сообщение ровно одно. |
| Минимум один формат рекламы, только через Bridge | Interstitial между вылазками, после отчёта. Rewarded пока не используется (в бэклоге — «продолжить после поимки»). |
| Нет внешних ресурсов | Шрифт и звук внутри сборки; смоук проверяет, что внешних запросов нет. |
| Вёрстка при любых размерах, портрет и ландшафт | Матрица 360×640, 390×844, 915×412, 1280×720, 2560×1440 и квадрат × ru/en в CI. В портрете игра играбельна и советует повернуть телефон. |
| Тач и клавиатура с мышью | Обе схемы; вся игра проходится жестами. Тряска телефоном — только усиление: в iframe порталов акселерометр часто запрещён, основной жест — тереть кнопку фонаря. |
| `Esc` игрой не используется | Пауза — `P`, кнопка на таче и потеря захвата мыши. |
| Кнопка mute | Кнопка «Звук» на карточке задания, на паузе и в отчёте; клавиша `M`. Выбор запоминается в профиле. |
| Звук — только файлами | Синтеза в коде нет вовсе: каждый звук — файл из `vylazka/audio/manifest.json`. Сборка с неполным набором файлов не проходит проверку. |

**Не проверено.**

- Правило о звуке (синтезированный в коде звук не принимается) известно со слов рецензента,
  читавшего живую вики. Перечитать самому не вышло: коннектор Playgama не отвечал, а хост
  `wiki.playgama.com` закрыт сетевой политикой сессии. Решение «только файлы» безопасно при любой
  формулировке правила.
- Два стика на телефоне против рекомендации «главные действия одной рукой» — возможно, придётся
  уточнять у модерации или добавлять упрощённую схему.
- Захват мыши внутри iframe: худший случай (песочница без `allow-pointer-lock` и без хранилища)
  покрыт автотестом — игра идёт, луч ведётся мышью с зажатой кнопкой. Как именно встраивает игру
  портал и работает ли там акселерометр, проверяется только на площадке.
- Частота кадров на телефонах не измерена: в CI программный рендер.

Lifecycle-сообщения «Вылазки»: `game_ready`; `level_started` / `level_completed` / `level_failed`
с `{world: "bunker", level: "seed_<N>"}`; аналитика `goal_done` `{type, tier}`.

## Монетизация с учётом покрытия Bridge (по документации SDK)

Bridge покрывает 25 платформ: rewarded-реклама доступна на 23 из 25 (нет на discord, reddit),
**платежи — только на 10 из 25** (crazy_games, discord, facebook, huawei, microsoft_store, msn,
playgama, portal, reddit, yandex; **нет на poki, vk, ok, telegram, tiktok**). Следствия:

- Разблокировка эпизодов покупкой возможна не везде → ветка-fallback «открыть главу за просмотр
  рекламы» там, где `payments.isSupported` ложно.
- Проверять `getPurchases()` при каждом запуске (restore «remove ads» и купленных сезонов).
- Серверная верификация покупок доступна только на playgama/msn/microsoft_store.
- Внешние HTTP-вызовы заблокированы на facebook, game_distribution, gamesnacks, poki, reddit,
  youtube → никакой логики, зависящей от своего бэкенда.

## Рекомендуемые (не обязательные) практики из чеклиста, которые мы принимаем

- Аудио только в сжатом виде (ogg/mp3), лимит 300 МБ — не главный враг, враг — время загрузки.
- «Мир как данные»: сценарий, сцены и мини-игры описываются данными (см. `schemas/episode.schema.json`), а не кодом.
- Дебаг-хуки на глобальном объекте (`window.__vn`): перейти к сцене, установить переменную, прогнать эпизод автоматически — чтобы headless-браузер мог «пройти» эпизод в CI.
- Снимки UI по фиксированной матрице разрешений перед каждым релизом.

## Lifecycle-сообщения, которые отправляем

| Момент | Сообщение |
|---|---|
| первый играбельный кадр | `game_ready` (обязательно) |
| старт эпизода | `level_started` `{world: "s1", level: "ep01"}` |
| финал эпизода | `level_completed` |
| открытие паузы/настроек | `level_paused` / `level_resumed` |
| вход в мини-игру / выход | `in_game_loading_started/stopped` при подгрузке ассетов |
| открытие архива, финал ветки | `sendCustomMessage('archive_opened')`, `sendCustomMessage('ending_reached')` — для аналитики |
