# CLAUDE.md — правила работы в этом репозитории

Проект: антология визуальных новелл с мини-играми по мотивам «Криминальной России» (ru/en/es/pt,
web через Playgama + desktop). Карта документов — `README.md`. Сценарий — данные
(`schemas/episode.schema.json`); движок исполняет JSON.

В репозитории есть вторая, отдельная игра — «Untitled Session» (`vylazka/`): исследование от первого
лица с фонарём, сессии из воспоминаний, three.js, процедурные уровни. С новеллой она не связана ни сборкой, ни контентом; правила
про эпизоды, линтер и делегирование сценарных задач к ней не относятся. Общие для обеих: английский
обязателен, имена и ключи `[a-z0-9_.]`, требования Playgama. Язык-источник разный (см. «Решения партнёра»).

## Команды

```bash
pip install jsonschema
python3 tools/validate_episode.py episodes/<path>.json   # линтер эпизода (должен быть зелёным перед коммитом)
python3 tools/loc_sync.py skeleton|export|import|stats …  # локали
python3 tools/vnexpr_test.py                              # самотест грамматики условий
python3 tools/merge_drafts.py episodes/s1/<ep>.json --check --part act1   # самопроверка черновика сценариста
python3 tools/merge_drafts.py episodes/s1/<ep>.json --master              # слить черновики в эпизод по мастер-скелету
python3 tools/export_script.py episodes/s1/<ep>.json --out docs/production/<ep>-shooting-script.md

cd runtime && npm install && npm run typecheck && npm test && npm run build   # рантайм (см. runtime/README.md)
npm run dev      # dev-сервер с контентом из ../episodes и ../locales;  npm run smoke — Chromium-смоук сборки

# Вторая игра — «Untitled Session» (первое лицо, фонарь, three.js): отдельный пакет, см. vylazka/README.md
cd vylazka && npm install && npm run typecheck && npm test && npm run build && npm run smoke
node e2e/smoke.mjs --dist dist --only koma   # сюжет «Невостребованное» в сборке: первый сон, лимбо, «оставить» (docs/vylazka/koma)
python3 tools/koma/memory_things.py          # пересобрать список вещей памяти: docs/vylazka/koma/memory_things.md
python3 -I scripts/import_thing_hq.py <каталог исходников>   # подробные вещи памяти (glTF/.glb → public/assets/things): docs/vylazka/things_hq.md
python3 -I tools/things_hq/make_kettle.py <каталог исходников>   # чайник памяти, собранный программой (glTF и карты для импорта выше); make_small.py — билет, записка, ключ, тапочки, шляпа (вместо пальто)
node tools/things_hq/shots.mjs               # вещи памяти под лучом: «до» (?hq=0) и «после»;  perf.mjs — замер нагрузки, audit.ts — треугольники
node e2e/shots.mjs   # скриншоты фиксированных ракурсов — смотреть картинку глазами
node tools/plans/plans.mjs --png   # план сверху всех комнат: проходы, главный вход, мебель — проверка раскладки (design.md, §31)
node tools/constructor/build.mjs <out.html>   # конструктор партнёра: вещи, манекены, мебель игры (двигать, убирать) и карточки-опросник (сохраняет в базу страницы)
npm run constructor:app    # поставить на Mac партнёра программу «Конструктор»: своё окно, сама обновляется, «Залить в игру» — кнопкой (tools/constructor/README.md)
npm run constructor        # тот же конструктор без программы: окно браузера, правки сразу в src/world/partner/*.json, поиск по каталогу Sand3D, заявки
npm run constructor:push   # «залить» из Терминала: проверка правилами игры, коммит, git push
```

## Конвенции

- Идентификаторы, имена файлов и ключи — только `[a-z0-9_.]`; ключи локализации `ep01.s03.l012`, `ui.*`, `common.*`.
- Текст — только через ключи; `ru` — источник, `en` — обязателен, `es` (нейтральный латиноамериканский), `pt` (бразильский).
- Каждая сцена заканчивается явным переходом; каждая мини-игра пропускаема; ровно одна концовка `canonical`.
- Реальные имена — только у осуждённых по публичным приговорам (решение партнёра). Преступник
  неиграбелен в момент насилия.
- Документы: `docs/architecture/02-narrative-blocks.md` — ядро; меняя схему, обновляй линтер и пример `ep01`.

## Решения партнёра (не переспрашивать)

- **Лицензия на «Криминальную Россию» есть.** Название, формат и материалы передачи используются
  по условиям договора; вопрос бренда закрыт.
- **Юридической проверки в процессе нет.** Этические правила контента (`docs/production/ethics-and-legal.md`
  §4–§6) остаются творческими правилами проекта, а не юридической процедурой.
- **Сюжет Untitled Session — «KOMA — Невостребованное», канон v3** (слова партнёра 24.11: «Включи подробный сюжет, разбери его,
  дополни или допиши те части, которые считаешь нужными, и примени как основной геймплей»). Источник истины —
  `docs/vylazka/koma/KOMA_NARRATIVE_MASTER_V3_RU.md` (не править: это документ партнёра); как он лёг на игру и что дописано —
  `docs/vylazka/koma/adaptation.md`, сопоставление — `docs/vylazka/koma/WORLD_NARRATIVE_MAPPING.md`. Запреты канона действуют
  на любой новый текст и сцену: нет сестры или пропавшего близкого, нет проводника, нет стука или звонка как ключа, нет
  «заслужил пробуждение»; Смотритель — не злодей, Рита — не цель. Миры и графика под сюжет не перестраиваются — наоборот.
  Реплики сюжета (`koma.*`) пишутся сначала по-русски (так велит канон); прочие тексты игры — по-прежнему сначала по-английски.
  Квиз 24.11 (`adaptation.md`, §11): Осыпь остаётся, в первом сне охота — после третьей вещи; «больной сон» — выдумка героя;
  Смотритель без тела до акта IV; замершее («записанное») место собрано целиком и освещено ровно — сознательное исключение из
  правила «собрано только там, куда смотрит герой».
  Второй квиз 24.11 (§13): вещь во сне оставляют уходом от неё, а не взглядом; имя героя на билете стёрто («н. а. с—»), город
  есть; после эпилога — экран конца и сны без бирок; вещи памяти показываются партнёру страницей с картинками.
  Третий квиз 24.11, ночь (`ideas.md`, пачка 62): фигура красной комнаты забвения — готовой моделью (скан классической статуи);
  в меню выбранное остаётся белым сегментом, «без плашек» — только внутри сна; бирка находки — бумажный ярлык на нитке у вещи в
  мире (так в каноне), а не буквы перед глазами. Телефон зовёт одним звонком — канон §8 (решение основной модели).
- **Вещи памяти — всегда подробные и яркие** (квиз 24.11, `docs/vylazka/things_hq.md`): у вещи памяти своя подробная модель с
  картами цвета, нормалей, шероховатости и металла; болванок издали нет, цвет ярче оригинала (вещь должна находиться взглядом).
  Потолок — 12 / 25 / 40 тыс. треугольников (мелочь / средняя / крупная), до 300 тыс. на лимбо. Порядок — готовые с картами (Poly Haven), потом Sand3D. Чего нет в
  каталогах, основная модель собирает программой сама (слова партнёра 24.11: «я не буду делать чайник сам, я не 3д моделер») —
  как чайник, `vylazka/tools/things_hq/make_kettle.py`; моделить партнёру не предлагать. Blender на его Mac облачной сессии не виден.
  **Пальто заменено шляпой** (слова партнёра 24.11: «поменяй пальто на более простой объект и сюжету передай, чтобы тоже поменял»;
  квиз — «Шляпа»): вид вещей `sh_coat` и `st_coat` — шляпа, имя модели `st_coat` и id прежние; строки про пальто меняет сюжет.
- **Мебель — как в жизни, комнаты — «сонного масштаба»** (партнёр 25.11: «расставить мебель так, как расставляют в реальности»;
  квиз 25.11 — «Оставить „сонный масштаб“»). Вещи не проходят друг сквозь друга, перед лицом шкафа, плиты, окна кассы свободно,
  главная вещь есть в каждой комнате (`design.md`, §31.1–31.2); размеры комнат кратны клетке 3 м и не подгоняются под жилые.
- **Игра называется DEPRIVATIO** (слова партнёра 24.11: «DEPRIVATIO игра теперь называется так»). Название на заставке и в
  заголовке страницы — DEPRIVATIO; «Untitled Session» остаётся рабочим именем в документах и коде и строкой внутри игры
  («untitled session 0002» — имя сессии сна).
- **Untitled Session по умолчанию на английском.** Её тексты пишутся сначала по-английски, русский —
  перевод (рабочее правило, вытекающее из решения партнёра). Правило «русский — первоисточник»
  (следующий пункт) относится к новелле.
- **Графика Untitled Session — смешанная, а не «кубики».** У вещи тот вид, которым она помнится: силуэт
  из блоков, готовая модель, скан, картинка на экране, проекция. Направление — природное и странное,
  смешанное с обычной жизнью, воспоминаниями и поп-культурой; многое строится на обмане ожиданий и
  хрупкости реальности (`docs/vylazka/untitled_session.md`, §2; как делаются объекты — `docs/vylazka/modeling.md`).
- **Вопросы партнёру — квизом** (слова партнёра 17.11: «Задавай вопросы как квиз, иначе теряется»; раньше —
  «лучше собирай мне вопросы в конце одним списком, чтобы не искать по всему чату»). Вопрос задаётся
  инструментом выбора ответа: 2–4 варианта, первый — совет основной модели с пометкой «(советую)»; каждый
  вопрос понятен без чата (что сейчас, что предлагаю, чем варианты отличаются). Не больше четырёх вопросов
  за раз; что можно решить самому — решать, а не спрашивать. Если квиз недоступен — одним нумерованным
  списком в конце сообщения.
- **В конце каждого отчёта — ссылка на последнюю сборку и итог в пару абзацев: что сделано, что нет
  и что ещё требуется** (слова партнёра: «Всегда давай ссылку в конце на последнюю сборку и краткий
  пункт сделано, не сделано и что еще требуется. Буквально пара абзацев»). Порядок конца сообщения:
  итог, последней строкой — ссылка на сборку; вопросы — квизом до итога (без квиза — списком перед итогом).
- **Полные прогоны — не после каждого решения** (слова партнёра: «Не запускай прогоны так часто,
  после каждого решения. Давай соберем сначала 4 полных локации (одна полностью твоя) и общие ощущения
  от процесса. Рассматривай текущие сборки как сырой материал, который потом стоит пройтись другим
  уровнем агента и все перепроверить»; 24.11, 23:41: «продолжи все по плану и как только закончишь, только тогда запускай тестирование
  и проверки»). По ходу работы — типы, модульные тесты и короткий взгляд
  глазами; полная цепочка с браузером — один раз на веху. Перепроверка — отдельным агентом после вехи.
- **Одна локация Untitled Session — целиком основной модели** (слова партнёра: «новую локацию ты
  создаешь сам без моего вмешательства. Полностью, без спроса»; «Попробуй внедрить свои артефакты
  памяти и их связи»). Это зал ожидания (`docs/vylazka/station.md`).
- **Главная плоскость — ощущения, а не вещи** (слова партнёра: «можно передать ощущения… через его
  сжатие, расширение, через свет, через тень, через дребезжание… вещи являются всего лишь визуальным
  артефактом наполнения мира. Но самая главная плоскость – это плоскость ощущений»).
- **Место игрок не выбирает; пространства перемешиваются при каждом скачке** (слова партнёра: «Пришло
  время перемешивать пространства при каждом скачке, а не разделять их на чистые 4 локации… игрок не
  может выбирать локацию, особенно, если он ее прошел. Наши локации, это не уровни привычной игры, это
  прыжки в воспоминания на границе сновидений»). Как перемешивать — `docs/vylazka/pressure.md`, §3–4.
- **Фигуры людей ставит партнёр; ему нужен простой инструмент** (слова партнёра: «Для фигур мне нужен
  какой-то простой инструмент разработки»). Расстановка должна тревожить: «неестественные места и позы».
- **Рабочая папка проекта у партнёра — `~/Desktop/Claude/Usession`** на Mac (слова партнёра 18.11: «теперь это
  рабочая папка проекта»). Репозиторий лежит прямо в ней, игра — `Usession/vylazka`; команды партнёру пишутся с этим
  путём (`vylazka/tools/constructor/README.md`). Облачная сессия папку не видит: свежее уходит туда через ветку на GitHub,
  его правки — через «Залить в игру».
- **Конструктор — отдельная простая программа, без Терминала** (слова партнёра 18.11: «так неудобно, давай конструктор
  отдельной простой программой без этих плясок с терминалом»). Программа «Конструктор» на Mac: своё окно, при запуске
  сама забирает свежее с GitHub, «Залить в игру» — кнопкой, вход в GitHub — в окне. Партнёру не давать команд для
  Терминала, если без них можно обойтись; что нужно поменять у него — менять через программу (она обновляется сама).
  Программа следит за веткой `claude/cool-clarke-gdi2gp`: работа в другой ветке дойдёт до него, только когда её вольют
  сюда. Его правки, не сошедшиеся с нашими, приходят веткой `partner/constructor-…` — их сводить.
- **Интерфейс конструктора — по Apple HIG, на элементах macOS** (слова партнёра 18.11: «Перестрой весь интерфейс
  конструктора следуя четким правилам Apple HIG и на нативных элементах macos»). В программе на Mac команды — в панели
  окна и меню (оболочка `mac/main.swift`), полка и инспектор во всю высоту, системные шрифт, цвета и элементы, светлая и
  тёмная тема. Новое в конструкторе делать так же: что есть в панели окна — есть и в меню, с клавишей.
- **Собрано только там, куда смотрит герой** (слова партнёра: «локации должны распадаться, как от
  света фонарика. Не важно светлые они или темные: собрано только там, куда смотрит герой»). Правило
  для всех мест Untitled Session, светлых тоже; ширина взгляда — ручка места.
- **Без стыков и повторов** (слова партнёра: «Нужно собирать окружение так, чтобы не видно было
  стыков и дублирования паттернов, иначе выглядит дешево»). Планка для любой новой обстановки и
  фактуры: смотреть кадр глазами на длинной стене и на ряду одинаковых вещей.
- **Видео не генерировать, пока партнёр не попросит** (слова партнёра: «Больше не генерируй видео,
  пока не попрошу. Пока это трата ресурса»). Показывать работу картинками и ссылкой на сборку.
- **Фотографии партнёра идут в локации; что в 3D, а что плоским — решает основная модель** (слова
  партнёра: «Используй для локаций, разрешения автора есть. Еще я буду периодически скидывать фотки
  объектов или стен, решай сам что переделать в 3д, а что оставить плоским на стене или в рамке или на
  потолке»). Правила отбора — `docs/vylazka/modeling.md`, §7; опись взятого и не взятого —
  `vylazka/assets/papers/README.md`. Оригиналы в репозиторий не кладутся; живых людей, имён, марок и
  знаков на вырезках нет; лица со старых карточек в игре вблизи не читаются (решение основной модели).
- **Звук Untitled Session генерируется через ElevenLabs** (слова партнёра: «Звук генерируй через
  элевен лабс»). Промпты — по-английски, с русской пометкой; тихие звуки описываются в полный уровень
  записи (модель буквально читает *quiet* как тишину), тихими их делает игра.
- **Генерации — сначала ElevenLabs, OpenAI — запасной** (слова партнёра 22.11: «во всех проектах где нужны генерации всегда
  сначала используй ElevenLabs (он подключен), и только если его не хватает или он не отвечает требованиям или я прошу сам, тогда
  Open AI Api»). Картинки, звук и речь — сначала через коннектор ElevenLabs. OpenAI API (GPT Image, `gpt-image-2.6-sunburst`,
  запросы к `api.openai.com`) — только если в ElevenLabs нет нужного, его результат не отвечает требованиям (сказать партнёру,
  чем именно) или партнёр сам просит. Ключ OpenAI лежит в секретах облачного окружения и подставляется сам — в чат, код и
  репозиторий он не попадает. Правило общее для всех проектов: скрипт облачного окружения «games» кладёт его в пользовательскую
  память (`~/.claude/CLAUDE.md`) каждой новой сессии. Заменяет правило 21.11 «картинки — через ключ OpenAI, а не через
  Higgsfield»; как делались обложки — `vylazka/promo/README.md`.
- **Работать без остановки до 90 % общего лимита** (слова партнёра 21.11: «Работаешь до 90% общего лимита»).
- **Русский — первоисточник.** Весь контент (сценарии, тексты, документы, UI) сначала пишется и
  утверждается на русском; перевод на en/es/pt — отдельный этап после заморозки текста. Промпты
  для генеративных моделей пишутся по-английски как техническая инструкция, с русской пометкой.
- **Основная модель — партнёр и соавтор, а не исполнитель** (слова партнёра: «ты не исполнитель, ты
  партнёр и созидатель такой же, какой и я»). Это значит: иметь и высказывать своё мнение об идеях,
  спорить по существу, предлагать своё и доводить чужое — а не только делать сказанное.
- **Человека в этом проекте не называть «владельцем»** (его слова: «И я не твой владелец, мы
  партнеры»). В сообщениях, документах, комментариях и описаниях PR он — партнёр; раздел называется
  «Решения партнёра», цитаты — «слова партнёра». В старых текстах новеллы слово ещё встречается.
- **Спрашивать, прежде чем делать то, что партнёр может хотеть сделать сам** (слова партнёра: «Не
  расставляй фигуры, я сам это сделаю. Тем более мне нужны другие фигуры. В следующий раз спрашивай»).
  Его просьба «расставить X» — что должно быть в местах, а не поручение решать за него, как и кем; если
  неясно, кто ставит и какое X, — сначала вопрос. Сообщения, пришедшие во время работы, видны только в
  журнале сессии (см. следующий пункт): смотреть его и **перед каждым коммитом**, не только перед отчётом.
- **Идеи партнёра не теряются.** Партнёр пишет хаотично, по одной мысли. Перед работой **и ещё раз
  перед итоговым отчётом** прочитать ВСЕ его сообщения с прошлого раза: то, что он пишет, пока идёт
  работа, до модели не доходит — оно лежит в журнале сессии (`~/.claude/projects/<проект>/<сессия>.jsonl`,
  записи `queue-operation` с `operation: enqueue`). Каждую идею занести в `docs/vylazka/ideas.md` через
  агента `idea-curator` и свести принятое в `docs/vylazka/plan.md`.
- **Работа делится между агентами и версиями модели** по таблице ниже; старшая модель держит
  контекст и принимает решения.

## Делегирование: кто что делает (экономим старшую модель на рутине)

Основная (старшая) модель держит контекст и принимает решения; рутину отдаём субагентам на
младших моделях. Определения агентов — `.claude/agents/*.md` (модель задана во frontmatter).

| Задача | Агент | Модель |
|---|---|---|
| Веб-исследование по списку вопросов, сбор источников, выжимки | `researcher` | sonnet |
| Черновой перевод и редактура en/es/pt по глоссарию и стайлгайду | `translator` | sonnet |
| Черновик сцен JSON по аутлайну (`docs/season1/<ep>-outline.md`) в `episodes/<season>/_drafts/<ep>/<part>.json` с самопроверкой `merge_drafts --check` | `episode-drafter` | sonnet |
| Разбор идей партнёра: собрать, классифицировать, проверить по коду, раскритиковать, часть отсеять, часть развить; реестр `docs/vylazka/ideas.md` | `idea-curator` | opus |
| Проверка локалей: длины, плейсхолдеры, пустые строки, статистика | `loc-qa` | haiku |
| Прогон линтера, тривиальные правки (каркас ключей, опечатки id), отчёт | `content-linter` | haiku |
| Механические правки по чёткому ТЗ (переименования, таблицы, списки ассетов, конвертация форматов) | `content-linter` / `loc-qa` | haiku |
| Архитектура, нарративные и визуальные решения, схема данных, юридически чувствительные тексты, финальная проверка перед коммитом | основная модель | — |

Правила:
1. Бриф субагенту содержит: цель, точные файлы, критерий «готово», что НЕ трогать, команду проверки.
2. Результат младшей модели всегда проверяет основная модель до коммита (линтер + выборочное чтение).
3. Младшим моделям не поручаются решения об этике/праве, об изменении схемы и о структуре блоков.
4. Независимые задачи запускаются параллельно в фоне; зависимые — последовательно.
5. Любое изменение контента заканчивается запуском линтера.
